**v1.3 修订（2026-11-07）**：本地 ComfyUI 配音由 **CustomVoice** 切换为 **VoiceClone（参考音频克隆）**，**不改数据 schema=2、不改文本/接缝契约、不新增 provider**。

1. **动因（实测）**：CustomVoice（`FB_Qwen3TTSCustomVoice`，1.7B）只锁“音色身份”，韵律由目标文本驱动；同一讲 6 页实测中位 F0 极差约 3.7 个半音（第 5 页 +1.1 st、第 6 页 +2.2 st），人工可辨“换人格”。加 instruct、调 temperature/top_p 后差距减轻但不消失；`language=Chinese` 只消除第 6 页中英混排导致的“尖”，不解决第 5 页的高音区抬升。
2. **选型**：改用 `FB_Qwen3TTSVoiceClone`（Base 1.7B，ICL 模式，`x_vector_only=false`），以**参考音频的语音码 + 参考文本**作为韵律锚点；同一讲 6 页实测“十分平稳”，与 v1.2 相比用户可感知差异仅为“更稳”，不是功能变化。
3. **概念边界**：本版契约以**节点**为准——`FB_Qwen3TTSVoiceClone`（具体能力，吃 `ref_audio` + `ref_text`）；“VoiceDesign” 指 Qwen3-TTS 1.7B 模型家族的音色设计/生成能力（更宽泛），**不作为本版接口契约**。若未来接入 `FB_Qwen3TTSVoiceDesign`（只吃 `instruct` 文字描述、无参考音频），另行定义，不改变 `(参考音频, 参考文本)` 契约。
4. **UI**：v1.2 的“音色表（9 个 speaker）”由 **参考 voice 库**取代；**内置 2 个参考**（Vivian 默认、Uncle_fu），可导入更多；其余（地址、导入工作流、连接测试、试听、逐页落盘、五态/四态、失败可见、串行队列）不变。
5. **内部**：默认工作流 `workflows/qwen3-tts-通过克隆配音/`（API 格式：`LoadAudio → VoiceClone → SaveAudio`）；新增参考库文件 `comfy-tts-refvoices.json` 与 `voices/`；删除 `comfyVoice`，新增 `comfyRefVoice`；缓存键改为含 `refAudioSha256`/`refTextSha256`。
6. §9：新增 `E_TTS_VOICE_REF`；`E_TTS_VOICE_TABLE` 标记为 v1.2 遗留（v1.3 起不再产生）。
7. §2.5/§10/附录 A/D：AC-148 ~ AC-152 保留并改口径，AC-153 ~ AC-155 重写，新增 AC-156；发布门覆盖到 AC-156。

## 0 一页速览

**一句话**：用户勾选一组章构成一个 **Part**，系统按容量把它规划为 **N 讲**，先用一次调用产出 **讲纲**（主线 / 讲次 / 接缝句 / 术语），再逐讲生成，并在讲与讲之间做**可验证的缝合**，最后以**系列**形态连播、连练、连导出。

**关键变化**

| 维度 | 1.x（v1.6） | 2.0 |
|---|---|---|
| 单元 | 勾选即一个模块，1–5 章 | Part（不限章数）→ N 讲，讲 ≤6 万字 |
| 容量 | 超 5 章 / 6 万字直接拒绝 | 超容量自动拆讲；单章超长章内拆“上/下” |
| 接缝 | 无（各模块互不知道） | 讲纲统一主线与术语；接缝句一次生成、两处复用；后验机检 |
| 兼容 | 1.x 数据与模块可读 | **数据/契约不兼容**：同根新 schema；升级时自动备份旧根，之后重新导入；无独立单讲 |
| 功能 | 1.x 可见能力 | **全部保留**；P0/P1 与验收见 §2.5、§2.6 |
| 语音 | Qwen3-TTS 云端 / 浏览器 / 关闭 | 三者保留；**新增本地 ComfyUI（`comfyui-tts`）**，v1.3 起为 **VoiceClone 参考音频克隆 + 可导入参考 voice 库**（取代 v1.2 CustomVoice 音色表），见 FR-23.1 |
| 发布 | 独立包，可与其它版本并存 | **同包名覆盖安装**，不与 1.x 并存 |

**演示路径（8 步）**：导入 PDF → **生成章节目录** → 勾选“函数”7 章 → **确认此部分（Part）** → 预览“2 讲 / 42 页 / 约 42 分钟” → 开始生成 → 连播（第 1 讲末页承接进第 2 讲封面）→ 导出整套或按讲导出。

```
导入 PDF ──▶ 分章构建 ──▶ 确认 Part ──▶ 预览讲纲 ──▶ 开始生成 ──▶ 后验缝 ──▶ 系列可播
             chapters.json   parts.json      plan（只读/可存） series.json   stitch 报告
```

**功能边界**：本规范面向 2.0 产品。1.x 的用户可见能力全部保留（§2.6）；不兼容只指存储 schema、目录布局与内部模型。任何能力缺失都按缺陷处理。

**里程碑**：里程碑、验收门与功能对等实施顺序见 §12；P0 先完成，P1 随后，二者均在 2.0 发布前关闭。

## 1 版本定位（不兼容重写）

### 1.1 为什么需要 2.0

1.x（v1.6）的三个约束互相纠缠，导致两类“功能缺失”：

1. **5 章 / 6 万字是硬拒绝**（[generate.js:49-50](dsh-book-slides/generate.js#L49-L50)、[generate.js:105](dsh-book-slides/generate.js#L105)）：超限只能手动拆成多次生成，得到互不相关的模块，知识讲解的连贯性丢失。
2. **单章超 6 万字无法精讲**：选择阶段即被拒，用户看到的是“功能不可用”，而非“拆成两讲”。
3. **缺失“模块之上”的容器**：既不能表达“这 7 章属于同一个部分”，也不能表达“这 3 讲属于同一个系列”。

三者的共同根因是：**约束对象错了**。单次调用上下文早已由分块解决（单批 ≤1.2 万字，章内 ≤8 千，[slides.js:23-24](dsh-book-slides/slides.js#L23-L24)）；6 万字实为 **30 页 × 每页对应原文 2000 字** 的交付带宽（§3.3）。2.0 不改带宽，改的是“超过带宽时怎么办”。

### 1.2 条款关系

> 2.0 不承担 1.x 的**数据与契约**兼容义务；功能能力仍须保留。1.x 条目分两类：数据/接口条款按本表处置；**功能条款以 §2.6“1.x 能力保留总表”为准**，未列入总表、也未在 2.0 实现的 1.x 功能，按缺陷处理。

| 1.x（v1.6）条款 | 2.0 处置 | 说明 |
|---|---|---|
| FR-4 章节多选与模块（5 章 / 6 万字上限） | **废弃** | 由 Part（FR-12）与讲次规划（FR-13）取代；不再有 5 章 / 6 万字硬拒绝 |
| D11 分块生成（12000 / 8000 / 300） | **沿用常数** | 批参数保留，但不承诺与 1.x 行为一致 |
| FR-5 生成流水线（四阶段） | **重写** | 系列编排 + 单讲流水线（FR-14–FR-17）；阶段名仅作参考 |
| D13 模块缓存键 = 章集合 | **废弃** | 新两级键（§6.9），与旧键不互通 |
| FR-6 播放器 | **重写** | 播放器以系列为单位（FR-18）；不存在“游离单讲”入口 |
| FR-8 AI 语音（Qwen3-TTS） | **适配保留 + 扩展** | 云端/浏览器/关闭保留；新增 `comfyui-tts`（FR-23.1）与参考 voice 库（v1.3 取代音色表）；`voice_status` 五态不变，`audio_provider` 仅扩展枚举 |
| FR-10 导出 PPT | **重定义** | 按讲 / 整套两种（FR-19）；OOXML 实现可复用，数据契约不同 |
| FR-11 练习与复习 | **重定义** | 按系列组卷（FR-19）；题库结构可借鉴，不迁移 |
| §5.1 磁盘布局 | **废弃** | 同根新布局与 `schema=2`（§6.1） |
| 旧模块（1.x v1.6） | **不兼容** | 不读取、不迁移；2.0 只认 `schema=2` 的数据根（FR-20） |

“重写/重定义”只表示数据契约与对象变化，**不表示子能力可以减少**；子能力以 §2.6 保留总表为准。

### 1.3 不兼容声明

放弃兼容的理由：单讲模块、旧缓存键、旧书档会把“系列”做成两条路径——每条都要测、都要修，历史包袱最终会拖垮接缝机制。代价是一次重导，换单一数据模型与单一代码路径。

六条边界：

1. **同根不兼容**：2.0 使用 `~/.dsh/book-slides/`，以 `meta.json.schema=2` 标识；检测到旧 schema 时，先自动备份整个旧根，再初始化同路径的 2.0 数据；旧文件不被解析。
2. **不迁移、不导入**：不提供 1.x 模块/书档转换；升级方式 = 自动备份 → 初始化 2.0 → 重新导入 PDF。
3. **无独立单讲**：所有讲都属于某个系列（N=1 亦然），不存在游离模块。
4. **同根切换用备份**：1.x 与 2.0 共用同一目录，但互不识别对方的 schema；回滚 1.x 时把自动备份恢复回同根。
5. **不并存**：沿用同一包名 `dsh-book-slides` 与同一插件 id，2.0 覆盖安装 1.x；插件列表始终只有一个「精讲」入口。
6. **功能对等**：不兼容仅覆盖存储 schema 与内部模型；1.x 的用户可见能力（原文分屏、导入、分章、书架卡面、书籍管理、设置、作业、语音、练习、配图、导出）必须保留。删除能力不属于“不兼容”的合理代价。语音同时保留云端 Qwen3-TTS / 浏览器 / 关闭，并新增本地 ComfyUI（FR-23.1）；ComfyUI 不可用不影响前三者。

## 2 范围

### 2.1 目标

1. 一次覆盖一个 Part（规划上限 48 章 / 8 讲），无需手动拆分。
2. 讲与讲之间具备**可机检**的衔接：接缝句一致、页码与章序一致、术语一致、重复率受控。
3. 单章超长时自动章内拆分，切点落在节边界，而非任意段落。
4. 系列可连播、可部分可用（某讲失败不阻塞其余讲）。

### 2.2 非目标

- 不做整本书一次性生成（Part 之外不设全局主线）。
- 不做“部分语义”推断：插件不判断用户为何把这些章归为一组（D62）。
- 不做跨 Part 的连续播放或跨书系列。
- 不做有声书级的无缝合成（讲间保留可感知的过渡，但不做音频拼接）。
- **不兼容 1.x**：同根但只认 `schema=2`；旧 schema 不解析、不迁移，升级时仅整体备份（§1.3）。版式与字段上限可沿用实现，但不构成兼容承诺。
- **不与 1.x 并存**：不发布第二包名、不检测/引导双装；2.0 就是唯一在装的「精讲」。
- **不删功能**：不兼容不等于功能缩水。1.x 的可见能力要么在 2.0 保留，要么在 §2.5 逐项登记为“显式降级”并给出恢复版本；未登记的缺失按缺陷处理。
- **不托管 ComfyUI**：不安装/启动 ComfyUI、不下载模型或自定义节点、不做云端 ComfyUI/鉴权/HTTPS/多实例；插件只调用户显式配置的 HTTP 地址（配音与配图同一约束，见 FR-23.1、FR-24）。

### 2.3 用户场景

| 场景 | 输入 | 期望 |
|---|---|---|
| S1 一个知识块一次听完 | “函数”7 章，8.4 万字（示例） | 自动 2 讲（讲数/页数由 FR-13 规则派生，不是判据）；连播不断线；听完知道下一讲接什么 |
| S2 单章超长 | 单章 9 万字 | 拆成“上/下”两讲，不报错；切点在节边界 |
| S3 新装 2.0 | 本机已有 1.x 数据（同根） | 自动备份旧根到 `book-slides.backup-<时间>/`，2.0 初始化空书架；重新导入 PDF |
| S4 本地 GPU 配音 | 已有系列；本机 ComfyUI + `Qwen3-TTS` VoiceClone 工作流 + 默认参考 | 选 `comfyui-tts`，默认克隆工作流/默认参考开箱可用；试听通过；换参考只注入 `(参考音频, 参考文本)`、不改工作流；逐页音频落盘，0 云端费用 |

### 2.4 成功判据

| 层 | 断言 | 依赖落盘 | 不成立的表现 |
|---|---|---|---|
| L1 能覆盖 | 10 章 / 12 万字的 Part 一次规划完成，章无遗漏无重复 | `series.json` | 仍需手拼多个模块 |
| L2 能续听 | 系列内从第 1 讲第 1 页连播到最后一页，无需人工点下一讲 | 播放器系列态 | 播完即停、回列表手动找 |
| L3 能验证 | 接缝断言 100% 通过；重复率 ≤0.5；术语禁用词 0 | stitch 报告 | “接缝好不好”只能靠听感 |
| L4 单一路径 | N=1 与 N>1 走同一数据模型（Part + 系列）；不存在“游离单讲”分支 | `series.json` | 出现两套代码路径，兼容分支重新长出来 |

## 3 术语与概念

### 3.1 层级

```
部分 Part  →  讲 Lecture  →  批 Batch  →  页 Slide
（用户勾选）    （交付单元）     （调用单元）   （阅读单元）
```

### 3.2 名词表

| 术语 | 定义 | 2.0 中的位置 |
|---|---|---|
| 部分 Part | 用户人工勾选的一组原章节；插件不解释其语义；同一本书内 Part 两两无交集 | 根实体（`parts.json`） |
| 讲 Lecture | 一次独立交付的精讲，6–30 页，≤6 万字（工程上限 8 万） | 交付单元，必属系列；不再有独立模块 |
| 系列 Series | 一个 Part 的 N 讲及其讲纲、接缝、进度 | 唯一的播放/练习/导出容器 |
| 批 Batch | 一次模型调用覆盖的原文块（≤1.2 万字，章内 ≤8 千） | 生成内部单元，常数沿用 |
| 页 Slide | 一页讲义（cover / content_text / quote） | 阅读单元 |
| 讲纲 Syllabus | 系列单一事实源：主线、讲次、接缝句、术语、切点建议 | 新增 |
| 章介绍 Brief | 每章 60–100 字的定位说明 + 节标题 + 转折标记 | 新增 |
| 接缝句 Seam sentence | 相邻讲之间的一句过渡话，≤60 字，两处逐字复用 | 新增 |
| 预缝 Pre-stitch | 生成时即按接缝契约书写（不做事后补写） | 新增 |
| 后验缝 Post-stitch | 生成后的机检与定点修复 | 新增 |
| 压缩率 ρ | 本页对应原文净字数 ÷ 本页讲义字数 | 显式指标（§3.3） |
| 参考 voice | ComfyUI 克隆用的“参考音频 + 参考文本”条目；参考音频决定音色与韵律基线，`ref_text` 是它的逐字转写（与目标文本无关）；换参考不改工作流 | `comfy-tts-refvoices.json` + `voices/`（§FR-23.1） |

### 3.3 压缩率 ρ 与讲容量

```
ρ（本页）= 本页对应原文净字数 ÷ 本页讲义字数
```

- **分子**：该页 `source_pages`（及 `source_anchor`）覆盖、并被本页实际讲解的原文段落净字数；去掉页眉页码与空白后计数，**不等于物理 PDF 页的整页字数**。一页讲义可对应半页、一页或多页原文；无锚点时按 `source_pages` 区间估算。
- **分母**：标题 + 要点 + 引文 + 朗读稿（不含 `image_prompt`、`source_quote`）。按字段上限计算约 **624，按 600 计**（title 24 + 要点 5×40 + 引文 120+60 + 朗读 220）。

三档容量：

```
讲容量（设计值）   = 30 页 × 每页对应原文 2000 字 = 60000 字   （ρ = 3.3）
讲容量（工程上限） = 30 页 × 每页对应原文 2667 字 = 80000 字   （ρ = 4.4）
理论警戒          = 30 页 × 每页对应原文 3600 字 = 108000 字  （ρ = 6，不建议逼近）
```

ρ 分级：`<2.5` 偏松；`2.5–4.5` 健康；`4.5–8` 警戒（记 `density_warn`）；`>8` 拒收（必须再拆或转“速览模式”并明示）。

> ρ 只约束比例，不约束绝对信息量；后者由字段下限（`audio_script` 40–220 字、要点 1–5 条）与页数预算共同保证。

### 3.4 接缝五处与三态

| 接缝 | 位置 | 缝合者 |
|---|---|---|
| 播放缝 | 讲 N 播完 → 讲 N+1 第 1 页 | 播放器（FR-18） |
| 内容缝 | 讲 N 落点 → 讲 N+1 起点 | 讲纲接缝句（FR-15/16） |
| 切点缝 | 章与章、章内部切分处 | 讲次规划（FR-13） |
| 批缝 | 讲内批与批之间 | 生成注入（FR-16） |
| 术语缝 | 同一概念的不同叫法 | 术语表机检（FR-17） |

系列级缝合状态：

| 状态 | 含义 | 用户可见 |
|---|---|---|
| `unstitched` | 有讲但无接缝句（讲纲失败降级） | 连播可用，列表标注“本系列未做衔接” |
| `stitched` | 接缝句已注入并通过机检 | 正常 |
| `verified` | 机检与抽听均通过 | 正常，可导出 |

### 3.5 Part 的唯一定义

Part 是用户人工确认的一组原章节：`{id, title, chapters[], source}`。章节取自 `chapters.json` 的内容章（`front` 除外），顺序无关，按章号升序使用。Part 只是生成的基础对象：确认 Part 独立于预览/生成，预览与生成不得创建或修改 Part。

插件**不解释语义**：不判断“为什么在一起”，不从书的“第 X 部分”自动切分，不因标题相似建议合并/拆分。书的 part 条目仅可作为“一键选中”的便利与标题默认值。

**唯一硬约束**：同一本书内，任意两个 Part 的章集合两两不相交（`∀i≠j: parts[i].chapters ∩ parts[j].chapters = ∅`）。

## 4 决策（D62–D79）

| 编号 | 问题 | 决策 | 理由 |
|---|---|---|---|
| **D62** | Part 由谁定义？ | **用户勾选即定义**；插件不解释语义，不做自动归并 | 语义推断错误会经讲纲放大到整个系列；用户意图是唯一可靠来源 |
| **D63** | 两个 Part 能否共享章？ | **不能**；章归属唯一；N=1 的单讲同样登记为 Part | 同章落入两个系列会让练习、进度、导出出现归属歧义 |
| **D64** | 一讲多大？ | **30 页 × ρ3.3 = 6 万字**为设计值；**8 万字**为工程上限；超出即拆讲 | 由 ρ 与页数上限推导，而非拍脑袋；8 万留出锚点与朗读覆盖余量 |
| **D65** | 谁保证 N 讲像一门课？ | **讲纲**为单一事实源（主线/讲次/接缝句/术语/切点），每讲注入其切片 | 两次独立生成必然漂移；单一事实源是唯一可靠来源 |
| **D66** | 回顾/预告怎么写？ | **接缝句一次生成、两处逐字复用**：讲 i 末页结尾 + 讲 i+1 cover 开头 | 两讲各自写必然两种口径；逐字复用可机检 |
| **D67** | 缝合在生成前还是生成后？ | **预缝**（生成时注入契约）+ **后验缝**（生成后机检与定点修复） | 先机检、后调模型，成本最低且确定性最好 |
| **D68** | 切点怎么选？ | 优先**弧边界**（不拆同主题相邻章、只在章末切）；章内切分优先**节标题**，其次页边界，最后段落累计 | 切在语义停顿处，缝的需求最小；切在段落中间，缝也救不回 |
| **D69** | 讲纲失败怎么办？ | 退回**规则切分**（贪心装满容量、不拆主题弧），系列 `unstitched`，仍可连播 | 缝是最软的一层，不能因讲纲失败让整个系列不可用 |
| **D70** | 后验缝要不要调模型？ | 默认**只机检**（5 项指标）；仅当修复需要改写时才调模型，且优先只修衔接页 | 能用字符串/集合判断的，不调用模型 |
| **D71** | 修复粒度？ | 页 → 讲 → 相邻两讲 → 整系列，按问题类型取最小单元（§FR-17） | 修轻无效，修重昂贵；粒度必须与问题匹配 |
| **D72** | 改一个切点要重跑多少？ | **`replanFrom(k)`**：保留 1..k−1，只重算 k..N 的装章、页预算与接缝 | 级联成本不可接受；做不到局部化，手动切点等于不可用 |
| **D73** | 缓存与 Part 编辑 | 两级键（seriesKey / lectureKey）；系列保存**章快照**；Part 变更只标记“基于旧快照”，不静默改动已生成内容 | 增量与一致性同时成立；用户不会因改个名字就丢内容 |
| **D74** | 系列怎么播？ | **连播**：讲末页播完 5 秒过渡卡进下一讲；系列进度“已听 24/42 页”；系列目录可跳讲 | 播放缝是感知最强的接缝，修复成本最低 |
| **D75** | 练习与导出按什么单位？ | 练习**按系列组卷**（题仍按章）；导出**默认按讲**，可选合并为整套 | 练习要覆盖整个 Part；导出要兼顾“一次讲完”与“整套交付” |
| **D76** | 是否兼容 1.x？ | **不兼容**：同根新 schema、不迁移、无独立单讲；N=1 也走系列 | 双模型/双路径的成本高于一次重导；2.0 的数据与接口按系列重新设计 |
| **D77** | 1.x 与 2.0 能否并存？ | **不能**：同包名 `dsh-book-slides`、同插件 id，2.0 覆盖安装；不发布第二包名 | 并存会带来两套路由、两块面板与两套 schema 的长期维护成本 |

## 5 功能需求

### FR-12 Part 定义与管理

- **描述**：Part 是生成的基础对象，但确认 Part 与开始生成是**两个独立动作**：用户可先确认 Part、稍后预览/生成，也可由 AI 建议草稿后人工确认；生成过程不得创建、修改或删除 Part。
- **规则**
  - **草稿**：勾选章节只形成临时草稿，不写 `parts.json`。
  - **确认 Part**：用户点「确认此部分」调用 `POST /part {bookId, chapters[], title?, partId?, source?}`；成功后 Part 落盘，与是否预览/生成无关。
  - **来源扩展**：`source ∈ manual | book_toc | ai_suggest`，只记录来源，不影响生成。AI 辅助只产生草稿/建议，必须经用户「确认此部分」才落盘；生成只依赖 `partId`，不关心来源。
  - **计划预览（不落盘）**：`POST /plan/preview {bookId, chapters[], partId?}` 对草稿或已确认 Part 生成 plan，不写 Part/series；可取消，取消不影响任何产物。
  - **系列容器**：`POST /series {bookId, partId, title?, plan?}` 只创建 `draft` 系列（不带作业）；带 `plan` 时直接进入 `planned`。
  - **系列讲纲**：`POST /series/plan {seriesId, plan?, force?}` 写入/重算系列 plan；成功后状态 `planned`；不启动生成。
  - **文本生成**：`POST /series/start {seriesId, lectures?}` 只对 `planned` 系列启动文本作业；不做配音；不创建/修改 Part。
  - **单讲生成**：`POST /series/lecture/generate {seriesId, n}` 只生成指定讲；`/series/retry` 等价于重跑失败讲。
  - **配音**：由独立 `POST /revoice` 触发（FR-23），不属于文本作业。
  - **组合流程不合并接口**：UI 可顺序调用 `/series` → `/series/plan` → `/series/start`，但三者是独立动作/状态；任一步失败不自动跨步，也不创建/修改 Part。
  - **校验**：`chapters` 非空、无重复、均为内容章（`front` 除外）、章数 ≤48（8 讲 × 每讲 6 章）。
  - **不相交**：与本书已有 Part 求交集；非空即 `E_PART_CONFLICT`。UI 采用**预防式禁选**：已确认 Part 的章默认且始终不可勾选/反选，正常操作不会产生冲突；API 直调仍校验，冲突不落盘，UI 只提示先在该 Part「编辑」中移出。
  - **编辑**：在组头「编辑」中可改名、增删章；增删重新执行不相交校验；已被其它 Part 占用的章需先在原 Part 移出，再加入本 Part；成功后 `part_version+1`，其系列标记“基于旧快照”。
  - **删除**：只删分组，不删系列与模块；系列保留章快照与 `part_id` 历史值。
  - **单讲即 Part**：N=1 同样登记，`stitch` 直接为 `verified`（无需接缝）。
  - **确认反馈**：`POST /part` 成功后，详情页必须重新拉取 `GET /parts` 并渲染：Part 以组头出现（标题、章数、字数、系列数、「已确认」徽标），组内章标“属于《…》”且默认不可直接取消勾选；临时勾选清空并滚动到该组。
  - **冲突兜底**：UI 不提供重选已属 Part 章的路径；API/并发冲突只提示先移出，不自动并入/移出，取消不改任何 Part、不调模型。
  - **失败不落幽灵组**：确认/编辑失败都不新增或改写 Part；保留当前草稿以便重试。

### FR-13 讲次规划

- **描述**：把草稿章集合（预览）或 Part 的章集合按容量与弧边界切成 N 讲，给出每讲的章、页预算与切点建议。
- **规则**
  - **判据与示例**：本节规则是**判据**（对任意章集合成立）；“7 章 8.4 万字 → 5+2 讲 / 30+12 页”只是**示例**，用于说明算法，不是独立承诺。AC-96 ~ AC-98 只断言规则与不变量，不断言某组输入的具体讲数/页数；可复现输入见 **FR-13.1**。
  - **讲数**：`N_est = max(1, ceil(totalChars / 60000))` 只是容量下限估计；实际讲数由装章决定（每讲 ≤6 章且刚好装满），超过 8 讲报 `E_SERIES_TOO_MANY`，不静默截断（48 章 ×1.2 万 = 10 讲，同样报错——48 章是上限，不保证装得进 8 讲）。
  - **装章**：贪心，按章号升序；**换讲条件**（任一成立）：① 本讲已有 6 章；② 再加本章会超过硬上限 8 万（I4）；③ 再加本章会超过目标 6 万且本讲已 ≥4.2 万（避免为凑满 6 万而留下过小的讲）；④ 装完本章后本讲已达 6 万（装满）。每讲 1–6 章（I3）、≤8 万字（I4）。**不拆同主题相邻章**（由 brief 的 `role`/`turning` 判断，标记 `cut_warn` 但不阻断）——此条为规范意图，**当前未实现**（见附录 B 注）。
  - **页预算**：`pages_i = clamp(round(chars_i / 2000), 6, 30)`；按字数比例而非平均；系列总页数可超过 30（上限为每讲）。`estMinutes = totalPages`（页 × 60 秒，含停顿与翻页），由页数派生，不由模型给。
  - **切点**：只在章末移动；章内切分优先级 `节标题（第X节 / X.Y / 一、 / 【…】）→ 页边界 → 段落累计`；**单章 >6 万字**就在章内拆（6 万字 ≈ 30 页上限，再长会被 `clamp(…,30)` 压掉内容），每段 ≤6 万；拆 2 段记“上/下”，>2 段记“1/N”。多章装讲时 6–8 万仍可出现（I4 的容差是“讲”的容差，不是“章”的）。切点落在页内时，相邻两讲共享该页（至多重一页），`source_pages` 允许重叠。
  - **章不连续**：允许（Part 由用户勾选）；页面跨度（首章首页…末章末页）只用于预览展示，页预算按章逐章求和，包络空隙不计入。
  - **预览**：生成前返回讲次、每讲章与页数、预计时长，供用户确认或改切点。
- **AC-96**（容量装章，任意输入）对任意章集合：讲数 ∈ [1,8]、讲次连续；`∪lectures[].chapters` = Part 章集合且无重复（I1）；每讲 1–6 章（I3）、≤8 万字（I4）；按章号升序、相邻讲共享页 ≤1（I2）；`pages_i = clamp(round(chars_i/2000), 6, 30)`、`totalPages = Σpages_i`、`estMinutes = totalPages`；每次换讲都能对上四条换讲条件之一（章内拆产生的分段不计，见 AC-97；不是“按弧”或模型判断）。**示例**：7 章各 1.2 万字（F1）→ 5+2 讲、30+12 页、42 分钟；这些数字是公式的派生值，Q14 改参数后随之改变。
- **AC-97**（超长单章）单章 >6 万字 → 章内拆成“上/下”（>2 段为“1/N”），每段 ≤6 万字；各讲 `chapters` 均含该章号，`slice.from/to` 首尾相接且覆盖全章；切点优先落在节标题行（`第X节` / `X.Y` / `一、` / `【…】`），无节标题时退到行/字切并标 `cut_line`。边界：6.0 万字整不拆（1 讲 30 页）；6.0 万+1 字拆 2 讲。**示例**：单章 9 万字 → 上/下 2 讲（4.5 万 + 4.5 万）。2.0 无 1.x 的 `E_SELECTION_TOO_LARGE` 拒绝路径（该码在 2.0 不产生，见 §9）。
- **AC-98**（章不连续）章 1、3、5 构成 Part：讲数按 3 章字数走装章规则（3×1.2 万 = 3.6 万 → **1 讲 18 页**，不是 2 讲）；页面跨度看似 1–5（首章首页…末章末页），但页预算只按 3 章字数求和，中间第 2、4 章的页不计入；生成后每页 `source_pages` 只落在第 1/3/5 章各自的页范围内，不覆盖第 2、4 章；页区间允许空档。

### FR-14 章介绍（briefs）

- **描述**：为讲纲提供结构信息；每章一条 brief，含定位、节标题、转折标记。
- **规则**
  - 字段：`{n, gist(≤100 字), sections[], role, turning}`；`gist` 说明“本章讲什么”，`role` 说明与前后章关系。
  - `sections` **必须逐字取自该章原文中的行**（机检：能在该章文本中检索到）；不满足则丢弃该条，退回“标题 + 首尾段”。该校验对**模型回复与落盘 `briefs.json` 都生效**，缓存命中不豁免。
  - 一次调用覆盖 ≤10 章；超过分两批；失败不阻断，回退原文首尾段（D69 的同一原则）。
  - 落盘 `briefs.json`，可复用、可人工改；读取时重跑上面的校验，改坏的条目按章回退并留 warning，**不静默覆盖人工修改**；只有 `force` 重建或章纲变化（hash 不符）才用模型输出重写文件。
- **AC-99（`sections` 逐字原文，可机检）**
  - **构造**：取任一 Part 的 briefs（模型生成或落盘文件），逐条拿 `sections[i]` 与该章正文（`chapters.json.from..to` 页文本按 `\n` 拼接）比对；再手工把一条改成原文没有的字符串（保持合法 JSON、不改 `hash`），模拟篡改。
  - **断言**：① 每条 section 都能检索到；② 篡改后**只回退该章**，其余章保留模型内容；回退值全部由原文导出（`sections` 取原文标题行、`gist` 取正文开头，`role=''`、`turning=false`），不含被改坏的内容；③ 回退可见：`/plan/preview` 的 `briefsSource='mixed'`，`warnings` 含该章号；④ 人工修改不被静默重写。
  - **判定**：section 检索不到却未被回退、回退无 warning/`mixed`、或人工修改被覆盖 → 不通过。
  - **机检入口**：`node scripts/verify-briefs.mjs --book <bookId>`（逐条打印章号/字符偏移/`PASS|FAIL`，退出码 0/1）；回归 `test/v2-briefs.test.mjs`。
  - **人工边界**：`gist` / `role` 的语义质量（是否说清本章、与前后章关系）由人工抽检；**不要求人工在原文里逐条核对 `sections`**。
- **AC-100（坏 JSON 降级，故障注入）**
  - **构造**：脚本化假模型在第 1、2 次调用返回不可解析 JSON（散文 / 截断），后续讲纲调用同样返回坏 JSON。
  - **断言**：① 解析/校验失败只重试 1 次（briefs 共 2 次调用，讲纲共 2 次）；② 仍失败则整份 briefs 回退（`fallback=true`），warning 含“解析失败”；③ 讲纲降级为规则 planning（`source='rule'`、`stitched=false`），仍覆盖 Part 全部章；④ 反向用例：第一次坏、第二次合法 → 2 次调用即恢复，不降级。
  - **判定**：调用次数、`fallback`、章覆盖任一不符 → 不通过。
  - **机检入口**：`node test/v2-briefs.test.mjs`。
  - **为什么不靠真模型**：偶发的是“触发”而非“行为”；坏 JSON 后的降级是确定性的，用故障注入固定；真模型坏 JSON 发生率属运行时观测，不作验收判据。

### FR-15 讲纲

- **描述**：一次调用把 Part 规划为 N 讲，产出主线、每讲目标与落点、接缝句、术语表、切点建议。
- **规则**
  - **输入**：书名、Part 标题、briefs、预算参数（页数上限 30、目标 ρ=3.3、章数区间 [2,6]）、用户偏好（期望讲数、指定切点）。
  - **输出 schema**：`{throughline, lectures[{n, chapters[], title, goal, in, out}], seams[{from, to, concept, sentence}], terms[{name, forbid[]}], cut_notes}`。
  - **校验**：讲次连续；章覆盖 = Part 章集合且无重叠；每讲 1–6 章且字数 ≤8 万（I4）；`seams` 数 = N−1；`sentence` ≤60 字；`terms[].name` 至少出现在原文或 briefs 中。
  - **重试**：解析或校验失败回灌一次；两次失败按 D69 降级。
  - **注入**：每讲生成时只取用其切片（本讲 goal/in/out、相邻讲标题、已覆盖概念、术语表）。
- **AC-101（讲纲校验与重试，故障注入）**
  - **构造**：脚本化假模型第 1 次返回结构合格但 `seams` 数 ≠ N−1 的讲纲（2 讲给 0 或 2 条），第 2 次返回合法讲纲；另跑一组“两次都不合格”。
  - **断言**：① 不合格只重试 1 次（讲纲调用 2 次，加 briefs 共 3 次）；② 第二次合格则采用（`source='model'`、`seams.length=N−1`、`stitched=true`）；③ 两次不合格 → 规则 plan（`source='rule'`、`stitched=false`、`seams=[]`），覆盖 Part 全部章，且可进入生成（`plan_version≥1`、`lectures` 非空，过 `E_SERIES_UNPLANNED` 门）；④ 降级 warning 能定位到校验项。
  - **判定**：未重试、重试后仍采用坏讲纲、降级 plan 未覆盖全部章或进不了生成门 → 不通过。
  - **机检入口**：`node test/v2-plan-ac.test.mjs`。
  - **人工边界**：主线与每讲 `goal`/`in`/`out` 是否切题由人工抽检。
- **AC-102（术语凭空发明，故障注入）**
  - **构造**：把讲纲 `terms[].name` 换成原文与 briefs 都不存在的词；第一次坏、第二次好；再跑“两次都坏”。
  - **断言**：① 坏词判不合格并重试 1 次；② 第二次合格则采用（`source='model'`），且**出现在 briefs 里的词必须放行**（如 `brief.gist` 中的词）；③ 两次坏 → 规则 plan，warning 含“术语”；④ 不能把合法术语误杀。
  - **判定**：坏词被采用、合法词被拒、或未降级 → 不通过。
  - **机检入口**：`node test/v2-plan-ac.test.mjs`。
  - **人工边界**：术语表该不该收、`forbid` 是否合理由人工抽检。

### FR-16 文本生成与预缝

- **描述**：逐讲生成文本讲义（structuring → validate → anchor），在提示词与校验中加入接缝契约；**不包含 TTS**，配音由 FR-23 的独立作业完成。
- **规则**
  - **文本三阶段**：文本生成、结构校验、锚点回填；不调 TTS、不写音频。
  - **音频字段**：初始 `audio_file=null`、`audio_provider="none"`；播放器回退浏览器朗读或提示“未配音”。
  - **契约切片**：本讲 `goal/in/out`、主线、相邻讲标题、已覆盖概念清单（“以下概念已讲过，一句话唤起即可”）。
  - **批缝**：第 2 批起，开头强制一句承接（上一批末段要点回写）；原文 carry 由 300 字升级为“300 字原文 + 上一批标题与要点”。
  - **预缝注入**：讲 i+1 的 cover `audio_script` 以 `seam[i].sentence` **逐字开头**；讲 i 末页 `audio_script` 以它**逐字结尾**；总长仍 ≤220 字。
  - **断言**：`cover.audio_script.trim().startsWith(seam.sentence)` 与 `last.audio_script.trim().endsWith(seam.sentence)`；不通过只重试该页，不重跑整讲。
  - **可观察**：每次预缝页级修复的计数写入 `lecture.json.seam_repairs`；验收用它判定“只修该页”，不靠日志猜。
  - **不设视觉回顾页**：用 cover 的 220 字承载承接与导览；若产品要求视觉回顾页，须从 30 页预算内扣除。
  - **反模式**：不得把上一讲全文注入提示词；不得让两讲各自生成回顾/预告；不得在章内移动切点（仅章末/节边界）。
- **AC-103（预缝注入与页级修复，构造坏内容）**
  - **构造**：假模型生成 2 讲时，两侧边界页的 `audio_script` 都不带接缝句（cover 不以它开头、last 不以它结尾），迫使预缝修复介入；修复回复给出合格脚本。
  - **断言**：① 第 2 讲 cover 的前缀与第 1 讲末页的后缀**逐字相同**，且都等于 `seam.sentence`（字符级比较，不是“包含”）；② 两份 `audio_script` 总长 ≤220 字；③ 每个边界页恰好 1 次页级修复（`lecture.json.seam_repairs=1`），生成调用数 = 讲数（不重跑整讲）；④ `audio_file=null`、`audio_provider='none'`（文本阶段不产音频）；⑤ 缝合报告 `seam=100%`，系列 `stitched`。
  - **判定**：逐字不一致、超过 220 字、出现整讲重生成、或产了音频 → 不通过。
  - **机检入口**：`node test/v2-m3.test.mjs`（AC-103 用例）。
  - **人工边界**：朗读稿是否自然、信息是否讲清；本 AC 只管接缝与音频字段。
- **AC-104（篡改后修复只动 1 页）**
  - **构造**：生成完成后，把第 2 讲 cover 的 `audio_script` 换成不以接缝句开头的一段；重跑缝合报告，再执行修复。
  - **断言**：① 报告 `unstitched`，失败项定位到第 2 讲第 1 页（seam）；② 修复项恰好 1 条（第 2 讲第 1 页），修复后 cover 以接缝句开头；③ 第 2 讲其余页逐字不变；④ 第 1 讲 `lecture.json` 与 `slides.json` 的 mtime 不变；⑤ 修复后重跑报告 `stitched`、`seam=100%`；⑥ 生成调用 0（不重生成整讲）。
  - **判定**：修了别页/别讲、第 1 讲被重写、或修复后仍不通过 → 不通过。
  - **机检入口**：`node test/v2-m3.test.mjs`（AC-104 用例）。
  - **人工边界**：修复后的朗读稿读起来是否通顺。

### FR-17 后验缝与修复

- **描述**：生成后先机检，按最小粒度修复；产出可查看的 stitch 报告。
- **规则**
  - **指标**：接缝一致（100%）、页序与章序（100%）、重复率（≤0.5）、术语禁用词（0）、密度 ρ（2.5–8）、覆盖（100%）。
  - **密度 ρ 是告警项**：ρ 越界只写 `warnings`，不进入 `failures`、不改变 `state`；验收看 `metrics.density.warn`。
  - **报告**：`GET /series/stitch` 返回每项指标、失败页/讲、建议修复动作。
  - **修复矩阵**：接缝不一致 → 1 页；重复/术语漂移 → 1 页或 1 讲；切点错误 → 相邻 2 讲（`replanFrom(k)`）；讲纲整体错误 → 整系列（需用户确认）。
  - **幂等（可机检）**：同一报告重复执行修复不产生新调用——修复后报告已无该失败项，第二次 `repaired=[]`、模型调用 0。
  - **状态**：机检全过 → `stitched`；人工抽听通过 → `verified`；未过且不修 → 保持 `unstitched`，不影响播放。
- **AC-105（术语漂移定位与定点修复）**
  - **构造**：生成 2 讲后，把第 2 讲某页标题改成禁用写法（“定义域”→“定义区间”）；重跑报告，再用 `targets:['term']` 修复。
  - **断言**：① 报告 `terms` 指标 fail，失败项定位到第 2 讲该页且带 `forbid='定义区间'`；② 修复后该页含“定义域”、不含“定义区间”，`terms` 归零；③ 第 1 讲 `slides.json` 的 mtime 不变（其余讲不被重写）；④ 修复为确定性替换（`ctx=null` 也能修），不调模型。
  - **判定**：定位不到页、禁用词残留、波及其它讲 → 不通过。
  - **机检入口**：`node test/v2-m3.test.mjs`（AC-105 用例）。
  - **人工边界**：替换后语句是否通顺。
- **AC-106（重复率超限的页级修复）**
  - **构造**：把第 2 讲一页换成与第 1 讲同页几乎相同的内容，使相邻讲重复率 >0.5。
  - **断言**：① 报告 `duplicate` 指标 fail，失败项建议“重生成衔接页”；② 修复只重写该页（模型调用 ≥1），重复率 ≤0.5、指标 ok；③ 第 1 讲 `slides.json` 的 mtime 不变。
  - **判定**：未定位、整讲重写、第 1 讲被改写、或重复率仍 >0.5 → 不通过。
  - **机检入口**：`node test/v2-m3.test.mjs`（AC-106 用例）；`npm run verify:stitch -- --series <seriesId>` 可直接看六指标表。
  - **人工边界**：重写后的衔接页是否自然。

  - **逐页缩略图**：底部缩略图条按 `layout` 渲染 16:9 迷你版式（`cover`/`content_text`/`quote`，与舞台同色系），不是“序号 + 标题”的纯文字页码条；当前页高亮，标题 1–2 行截断不溢出；点击/Enter 跳页并**先停当前音频**（不留上一页声音），原文窗格同步到该页 `source_pages`；页多时横向滚动，不换行挤压舞台；N=1 同样显示。

### FR-19 系列练习与导出

- **描述**：练习按系列组卷，覆盖 1.x 的题库、组卷、判题、讲解、补题、复习与场次；导出默认按讲，可选整套合并，保留 1.x 的音频/配图/备注能力。

#### FR-19.1 练习与复习（P1）

- **范围**：系列全部章，或系列内某一讲的章；新题要求该章至少有一个 `ready`/`ready_degraded` 讲覆盖；已有题的章可直接复习。场次 5–20 题。
- **题库**：每章 4–6 题，单书上限 300；题型单选 60% / 多选 20% / 判断 20%；难度易 30% / 中 50% / 难 20%。
- **字段**：题干 ≤120 字；单选 4 项、判断 2 项、多选 2–4 个正确项；选项 ≤60 字；`point` ≤16 字；`source_quote` 10–200 字且为本章原文连续子串；`explanation` 初始为 `null`。
- **题库准备**：`POST /practice/bank {seriesId, chapters?, topup?}` 独立异步作业，状态同生成；按章缓存，键 = `sha256(bookId|章号|章标题|章字数|promptVersion|blueprintVersion)`；单章失败不影响其它章；整章失败可重试；作业可取消。
- **补题**：`topup=true` 时按模式补题；`new` 补到 `count`；`mixed` 补到 `count` 且旧题不足用新题；每轮每章 +5，最多 6 轮且单次新增 ≤30 题；补题前二次确认（轮数、预计新增、耗时、上限），取消不调模型。
- **开场与题库解耦**：`POST /practice/session` 只从已有题库组卷，不触发生成/补题；题库不足返回 `E_BANK_INSUFFICIENT`，UI 需先调用 `/practice/bank` 或显式补题。
- **去重**：题库层三重去重（题干精确、Jaccard ≥0.80、同考点 ≤2），作用域同书同章/同书；组卷层不去重。
- **组卷**：`new` 只取未答；`mixed` 到期 ≤40%、新题 >50%、其余旧题按未掌握→已掌握补；`review` 只取到期/错题；同考点 ≤2；章数 ≤题数时每章 ≥1；开场冻结 `plan`。
- **作答**：逐题提交、提交即定、不可改选/回退；可「不会，看答案」（`picked: []`）；可中途结束，正确率分母 = 已答数；同 qid 重复提交幂等。
- **判题**：宿主本地判定（单选/判断比 key，多选比集合且全对），不调模型；只返回 `{correct, answer, source_quote, source_anchor, explanation?}`，`explanation` 仅当已缓存时返回，判题不触发生成。
- **讲解（独立动作）**：`POST /practice/explain` 只在用户点「查看讲解」时调用（≤8s，150–300 字，覆盖正确项、错误项、原文依据）；成功写回题库，失败置 `failed`；同题再错复用；离线时给正确答案与原文，不阻断下一题。答错不自动生成讲解。
- **记录与复习**：每答一题 append 到 `sessions/<sessionId>.json`（含 `series_id`）并更新 `mastery.json`；断点续练从第一道未答题继续；结束写 `summary`；错题本 = `last=wrong` 或 `box=0`；Leitner 5 盒 1/3/7/21/60 天，答错回盒 0；入口显示“待复习 N”。
- **标记**：可标「这题有问题」→ `flagged`，不再组卷但保留历史。
- **书档**：`practice/` 有则随包走（题库 MUST、掌握度/场次 SHOULD），按 `qid`/`session_id` 并集；讲解缓存不入包。
- **隔离**：不写 `slides.json`/`series.json`，不改讲状态机；题库作业与生成作业互不阻塞。

  - **断言**：① **解耦**：题库为空时 `POST /practice/session` 返回 `E_BANK_INSUFFICIENT`，题库模型调用 0 次；先 `POST /practice/bank` 再 session 才成功。② **判题不讲解**：答错未生成讲解的题，响应只有 `{correct:false, answer, source_quote, source_anchor}`、**无 `explanation` 字段**，模型调用 0 次，`summary.counts.wrong` +1。③ **讲解独立**：`POST /practice/explain {qid}` 才调模型（+1 次）并写回题库；同题再调返回 `cached=true`、调用 0 次；此后判题响应才可能带回 `explanation`（仅已缓存时回填）。④ **到期优先**：注入 a（章 1/2/3 各 1 题到期）后，`mode:'review'` 的 plan 只含 `due/weak` 且这 3 道到期题**全部出现**；`mode:'mixed', count:10` 的 `source='due'` 条数在 1–4 之间（`≤ floor(10×0.4)=4`，配额上限生效，且不被新题挤到 0）。⑤ **盒子升级**：注入 b 后答对，`mastery.items[qid]` 由 `box=0` 变 `box=1`、`due_at` = 答题时刻 + 1 天；`box=2` 答对变 `box=3`、`due_at` = +7 天；答错则 `box=0`、`last='wrong'`；同 qid 重复提交幂等，不重复升级。⑥ **中途结束**：答 3 题（2 对 1 错）后 `POST /practice/finish`，`summary.answered=3`、`correct=2`、`accuracy=2/3`（分母 = 已答数，不是计划数）。⑦ **续练**：结束前重开 `POST /practice/session` 复用同一 `sessionId`（`reused=true`），`next.qid` = 第一道未答题；结束后 `GET /practice/session` 返回 `E_NO_SESSION`。⑧ **标记**：`POST /practice/flag {qid}` 后结束并开新场，该 qid 在所有 mode 的 `plan[]` 中都不再出现，`summary.counts.flagged` +1，历史答案仍保留。⑨ **补题前置信息**：题库不足以开 `count` 题时，`GET /practice/summary` 的 `topup` 给出 `rounds≥1`、`need`、`perRound`、`feasibleN`；确认后 `POST /practice/bank {topup:true, rounds}` 的新增 = `rounds×perRound` 且 ≤30 题；取消不发任何补题请求（属 UI 行为，见人工边界）。
  - **判定**：讲解被塞进判题、due 超过 40%、盒子/到期不更新、结束以计划数为分母、flagged 题仍被组卷、幂等提交重复升级、或未确认就补题 → 不通过。
  - **机检入口**：`node test/v2-practice.test.mjs`（AC-119 用例，含 Leitner 注入）；构造 a/b 也可按上面字段手工改 `mastery.json`（备份 `mastery.json.bak`）。
  - **人工边界**：讲解文字是否讲清正确项/错误项/原文依据（只判可读性；字数、超时、调用次数已由接口断言）；补题确认弹窗是否讲清代价（轮数/题量/耗时）且取消真的不出题。

#### FR-19.2 导出 PPT（P1）

- **范围**：按讲导出，或整套合并；只导出 `ready`/`ready_degraded`；生成中 `E_PPT_BUSY`，其它未就绪 `E_PPT_NOT_READY`，空 `E_PPT_EMPTY`。
- **页数**：与 `slides.length` 严格一致（6–30/讲），不增页、不合并；第 1 页必须是 `cover`。
- **版式**：`cover`/`content_text`/`quote` 三种；复用舞台视觉（米色底、宋体标题、要点、引文、页码），原生文本框/形状，不整页转图。

- **音频**：仅 `audio_file` 真实存在时嵌入；`.wav` 优先、兼容 `.mp3`；其它格式（flac/ogg）不嵌入并在计划接口 warning“X 页音频为 flac，未嵌入”；缺失页跳过并在计划接口报“X/Y 页含音频”；嵌入文件本体，进入该页自动播放，点喇叭可重播。

- **命名**：`<书名>-精讲-<讲标题去掉“第 N 讲 · ”>.pptx`；非法字符替换；`content-disposition` 同时给 ASCII fallback 与 `filename*=UTF-8''`。

### FR-21 书架、导入、分章与设置（P0）

- **描述**：保留 1.x 的输入与书籍体验：书架卡面、导入校验、目录/机械分章、章校准、设置与作业 UI；数据写入同根下的 2.0 数据。

#### FR-21.1 书架（P0）

- 卡片流展示封面、书名、作者（有则显示）、章数、页数、系列数、最近系列与「继续听」。
- 排序：最近打开优先；无系列的书排在后面；书架 >200 本时 200 条上限 + 提示，不做分页。
- 卡片右上「⋯」：重命名、删除（软删除到 `trash/<bookId>/`，7 天内可从设置页恢复；不自动清理）。
- 菜单关闭：再点「⋯」、点菜单外任意区域、按 `Esc` 都能关；关菜单不吞这次点击（点卡片本体收起并打开书，点别的卡片/按钮照常响应）；菜单开着挂全局监听、关掉即摘。
- 空态：一句引导 + 「导入 PDF」按钮 + 支持拖拽整块区域。

#### FR-21.2 导入与封面（P0）

- **只入库**：只接受 `.pdf`，单文件 ≤200MB（超出不上传）；校验顺序：可打开 → 未加密 → 至少 1 页可提取 ≥50 字符；错误码 `E_PDF_CORRUPT`/`E_PDF_ENCRYPTED`/`E_PDF_NO_TEXT`。
- **不自动分章**：`POST /import` 只写 `source.pdf`、`pages.json`、`book.json`（`title`/`author`/`sha256`/`pages`/`lastOpenedAt`），不写 `chapters.json`、不生成封面；分章由 FR-21.3 的独立动作完成。
- **封面独立**：`POST /cover {bookId}` 生成/重生成书封（书名 + 作者 + 章数 + 稳定渐变），失败退回首章标题占位；`GET /cover` 只读取。
- **去重与进度**：按 `sha256` 判重；已在书架则提示并跳转；上传显示字节进度，提取显示“正在读取第 N/M 页”。
- **成功反馈**：进入详情页并提示“生成章节目录”；无章节时 Part 选择区为空。

#### FR-21.3 分章构建（P0）

- **独立动作**：`POST /chapters/build {bookId, mode=auto|toc|mech, force?}`；可在导入后任意时刻执行/重跑，不依赖 Part、不启动生成。
- **主路径 `toc`**：用户指定目录页码范围 → 模型读成“标题 + 印刷页码” → 校准成物理页 → 校验后落盘；校验失败回退机械切章。
- **校准**：印刷页 → 物理页用目录样本拟合偏移；校准后逐章校验起止递增、不重叠、覆盖全文；失败给出具体章号。
- **回退 `mech`**：按固定页数/字数机械切分（附录 A 规则），结果不含“目录”章；无章节标题的散文集得到 1 章“全文”。
- **启发式 `auto`**：书签 → 标题 → 机械。
- 实际模式与来源写入 `book.json.chapter_source`；手工改过的章带 `manual: true`，重解析不覆盖。

### FR-22 书档导入/导出（P1）

- **描述**：把一本书的全部可再生状态导出为自包含 ZIP「书档」；在任意 2.0 数据目录导入后，书、章、系列、讲与音频保持可用，不需要重新生成。支持多本批量。
- **目标判据**：导入后同时满足「书在」（书架/章/原文可渲染）、「讲在」（系列/讲可播放）、「点开还能听」（有音频的页出声且是原音频，无音频页明确提示）。
- **容器**：`manifest.json` + `books/<bookId>/…`；单本 N=1，批量同一包内 N 项；不嵌套 ZIP。
- **内容**：只允许 MUST/SHOULD 白名单；`voice.json`（含 Key）、`audio-cache/`、`trash/`、`batches/`、`preference.json`、`progress.json`、`*.tmp` 不得入包；音频默认包含（含 ComfyUI 产出的 wav/flac/mp3；播放不需要 Key/网络）；`practice/` 有则随包走（题库 MUST、掌握度/场次 SHOULD）。
- **身份**：书用 `book.json.sha256`；系列/讲用 `contentKey = sha256(讲纲 + slides 去标识字段)`；`bookId`/`seriesId` 只是本地别名；去重/合并/幂等用稳定身份。
- **落位与冲突**：目标 `bookId` 空闲则沿用；被不同 `sha256` 占用则整本拒绝（`E_PKG_ID_CONFLICT`）；`policy ∈ merge（默认）/skip/copy`；`merge` 只补系列/讲，不改目标书/章/原文；按 `contentKey` 去重；章对不上的讲标 `orphan` 不导入；不提供覆盖式导入。
- **零生成**：导入全程不调 LLM/TTS、不重新解析 PDF；缺失项按状态归一，补齐由用户显式触发（重试/仅补配音/重新解析）。
- **原子性**：解压到 `.import/<id>/`，全部校验通过后整目录 rename 进 `books/`；失败清理；启动时清理 >24h 残留。
- **批量**：逐本判定，一本失败不影响同包其它本/其它包；响应 `{ok, items[], summary}`，HTTP 200。
- **状态归一**：非终态讲 → `interrupted`；`slides.json` 在但音频缺失 → `ready_degraded`，该页 `audio_file=null`、`audio_provider="none"`（不得清空字段导致回退浏览器朗读）；`audio_provider` 原值保留（含 `comfyui-tts`），音频扩展名允许 wav/flac/mp3/ogg；缺 `source.pdf` 整本拒绝。
- **排序/只读/上限**：导入书 `lastOpenedAt=导入时间`；导出不改 `books/`、不落临时 ZIP；单批 ≤10 本、单包 ≤4GiB，超限传输前拦截。
- **接口**：`GET /export`、`GET /export/size`、`POST /import/package`、`POST /revoice`。
- **AC-125（书档往返与冲突）**
  - **构造**：造 2 讲系列（含音频与练习）导出书档；删除书后导入同一包；二次导入；另造同 `bookId` 不同 `sha256` 的目标；批量包混入 1 本坏包。
  - **断言**：① 导入后书/章/原文/系列/讲齐全，`/audio?...&i=2` 可播且字节以 `RIFF` 开头，`practice/` 随包恢复；② 二次导入 `action='merge'`、`series.skipped=1`、`added=0`，系列数不增；③ 同 `bookId` 不同 sha256 → 整本拒绝 `E_PKG_ID_CONFLICT`；④ 批量中坏包只该本失败，`summary` 如实计数；包内白名单无 `voice.json`/`audio-cache`/`trash`/`*.tmp`。
  - **判定**：缺书/缺讲、重复建系列、冲突被覆盖、坏包拖垮整批、包内出现禁用项 → 不通过。
  - **机检入口**：`node test/v2-package.test.mjs`（AC-125 四个用例）。
  - **人工边界**：导入后在播放器点开听一页，确认是原声。

### FR-23 语音（P0；FR-23.1 本地 ComfyUI 为 P1 新增）

- **供应商**：`qwen3-tts`（千问云端）/ `comfyui-tts`（本地 ComfyUI，P1，见 FR-23.1）/ `browser` / `off`，默认 `browser`（不静默产生云端或本机 GPU 费用）；Qwen 云端模型白名单 `qwen3-tts-flash`，ComfyUI 的模型由工作流决定；云端音色只列 48 个非实时系统音色，传值必须与列表一致；ComfyUI 的音色与韵律由 FR-23.1 的**参考 voice 库**决定（默认 2 个内置参考：Vivian / Uncle_fu；选中项的 `(参考音频, 参考文本)` 在请求时注入 VoiceClone 工作流，不写 `speaker`）。
- **Key**：存 `voice.json.apiKey`（0600）；`GET /voice` 只回 `apiKeyMask`（如 `••••a1b2`）；输入框 password，空输入不覆盖旧 Key；日志/错误/URL 不含 Key。
- **试听**：`POST /voice/probe` 用当前 provider；Qwen 成功返回 `audio/wav`；ComfyUI 真跑一次当前工作流并返回音频字节（格式随工作流，响应头带 `x-tts-ms`）；两者都不落盘/不缓存，失败返回 JSON 错误码；浏览器模式返回朗读参数。ComfyUI 的试听不写 `audio/`、不进 `audio-cache/`、不改 `slides.json`。
- **独立触发**：配音不随文本生成自动执行；必须由用户显式调用 `POST /revoice`。文本 `ready` 不依赖 `voice_status`。
- **配音作业**：每页一次请求，文本为 `audio_script`（40–220 字）；`qwen3-tts` 并发 2、单页超时 60s；`comfyui-tts` 并发 1、单页超时 180s（首次含模型加载，与配图共用串行队列，见 FR-23.1）；失败重试 1 次；写 `audio/NNN.<ext>`（云端固定 `.wav`，ComfyUI 随返回格式）并回填 `audio_file`/`audio_provider`；`audio_ms` 优先 WAV 头，否则按字数估。
- **状态**：`voice_status ∈ none|voicing|ready|partial|failed`（与 §6.8 一致）；**三级都要落盘**：系列级 `series.json.voice_status`（汇总）、讲级 `lecture.json.voice_status`、页级 `audio_provider`（`qwen3-tts|comfyui-tts|browser|none`）。`failed` 与 `none` 必须分开：`none` = 从未配音/未配置，`failed` = 配过但失败（含额度耗尽、鉴权失败、超时、ComfyUI 连不上）。`voicing` 只在作业运行中有意义，落盘可省略。
- **失败与降级**：未配置 Key → `voice_status=none` + `E_TTS_UNCONFIGURED`；部分页失败 → 成功页保留，失败页 `audio_provider:"none"`，该讲 `voice_status=partial` + 具体错误码（如 `E_TTS_QUOTA`），系列汇总为 `partial`；整讲/整系列全部失败 → `voice_status=failed` + 具体错误码；**不自动回退浏览器**；播放器按 `audio_file` 播，缺文件时按 FR-18 的 provider 规则处理（browser 可用则朗读，否则提示未配音）。ComfyUI 的 `E_TTS_CONNECT` / `E_TTS_WORKFLOW` / `E_TTS_WORKFLOW_NODE` / `E_TTS_MODEL_MISSING` / `E_TTS_VOICE_REF` 按同一规则落盘与展示（v1.3 起本地配音不再产生 `E_TTS_VOICE_TABLE`/`E_TTS_SPEAKER`）。
- **失败可见（必须）**：失败不得只靠播放器里一句“有 N 讲存在未配音页”。系列卡必须显示配音徽标（未配音/配音中/已配音/部分/失败）+ 失败讲数 + **具体错误码** + 「补配音」/「重试」入口；播放器顶部显示可关闭的失败提示（错误码 + 一句话原因）；`voice_error` 落盘到系列与讲，保留错误码与失败页数，不得只写一句汇总。
- **按钮状态机（必须）**：无任何音频 →「生成配音」；有缺失页/讲（`partial`/`failed`）→「补配音」；全部就绪 →「重新配音」（二次确认：将重跑页数、命中缓存不产生费用）；**长按 3s** →「强制重新配音」（二次确认，忽略缓存），按住期间按钮显示进度条与剩余秒数（3→2→1），松开即取消。文案随状态变化，禁止任何状态都用同一个「生成语音」。
- **缓存**：云键 = `sha256(provider|model|voice|format|sample_rate|text)`；ComfyUI 键 = `sha256('comfyui-tts-clone'|workflowHash|textNode|refVoiceId|refAudioSha256|refTextSha256|model|text)`，`workflowHash=sha256(工作流原文)`、`model` 取工作流 `model_choice`，**改工作流/模型/参考音频/参考文本即失效**；目录 `audio-cache/`，缓存文件按 `<key>.<ext>` 保存（扩展名随首次产出，按 key 前缀查找），命中直接复制；401/403/429 与工作流错误不写缓存。
- **重新配音**：`POST /revoice {seriesId, lecture?, force?}` 对指定讲/系列重跑配音，默认复用缓存；`force=true` 忽略音频缓存、全部重跑（长按 3s 入口）；只改音频字段，不改文字与 `slides.json` 的其他内容。
- **安全**：Key 只发 `maas.qianwenaiapi.com`；`comfyui-tts` 只把 `audio_script` 与**当前参考音频/参考文本**发往用户显式配置的 ComfyUI 地址（非 `127.0.0.1` 时设置页明示会离开本机）；两者都不写入 `slides.json`/`series.json`/日志；卸载不删 `voice.json` 与参考库。

#### FR-23.1 本地 ComfyUI Qwen3-TTS 配音（P1，2.0 新增；v1.3 改为参考音频克隆）

- **描述**：在千问云端 Qwen3-TTS 之外，允许把逐页 `audio_script`（工作流字段 `target_text`）送进**用户自己的 ComfyUI** 上的 **Qwen3-TTS VoiceClone（Base 1.7B）** 工作流合成音频；链路与云端配音一致（显式 `/revoice`、逐页、缓存、五态、四态按钮、失败可见），但**不产生云端费用**，也不使用 Qwen Key。
- **v1.3 选型与命名澄清（必须）**
  - 合成方式由 v1.2 的 `FB_Qwen3TTSCustomVoice`（预置 `speaker` + `instruct`）改为 `FB_Qwen3TTSVoiceClone`（`ref_audio` + `ref_text`，ICL 模式，`x_vector_only=false`）。
  - **概念边界**：本版契约以节点为准——`FB_Qwen3TTSVoiceClone`（吃 `ref_audio` + `ref_text`）；“VoiceDesign” 指模型家族的宽泛音色设计能力，不作为本版接口契约。若未来接入 `FB_Qwen3TTSVoiceDesign`（只吃 `instruct`、无参考音频），另行定义。
  - 依据（实测）：CustomVoice 只锁“音色身份”，韵律由目标文本驱动；同一讲 6 页中位 F0 极差约 3.7 个半音（第 5 页 +1.1 st、第 6 页 +2.2 st），人工可辨“换人格”。加 instruct、调 temperature/top_p 只能减轻、不能消除；`language=Chinese` 只消除第 6 页中英混排导致的“尖”。VoiceClone 以参考音频的语音码为韵律锚点，同讲页间更稳。
- **配置与默认值**
  - `voice.json.provider=comfyui-tts` 时启用；默认仍是 `browser`，插件不自动探测 ComfyUI、不因本机开着 8188 端口就切换。发布包缺默认工作流或默认参考时该 provider 置灰并提示重装（`E_TTS_UNCONFIGURED`），不影响云端与浏览器朗读。
  - 地址、超时、并发、串行队列、局域网提示：沿用 v1.2（与配图共用 `image.json.host/port`，默认 `127.0.0.1:8188`；单页 180s；并发 1；全局串行）。
  - `voice.json` 新增可选字段 `comfyRefVoice`（参考 voice `id`，默认 `builtin-vivian`）；`textNode` 保存手选的文本节点 id；**删除 `comfyVoice`**（v1.2 遗留字段迁移见 §6.1）。`voice.json.model` 只对 `qwen3-tts` 有效；克隆模型由工作流决定（`model_choice=1.7B`），插件不改。
- **默认工作流与默认参考（必须）**
  - 包内目录 `workflows/qwen3-tts-通过克隆配音/`：`qwen3-tts-通过克隆配音.json`（**API 格式**）、2 组参考（`qwen3-tts-1.7B_vivian.flac` / `qwen3-tts-1.7B_Uncle_fu.flac`，各带同名 `.txt`）、`README.md`。该目录同时是“默认工作流 + 默认参考 voice”的唯一来源。
  - 默认工作流节点：`LoadAudio(audio=<文件名>)` → `FB_Qwen3TTSVoiceClone(target_text, ref_audio, ref_text, model_choice=1.7B, language=Chinese, x_vector_only=false, instruct, seed…)` → `SaveAudio(filename_prefix="audio/ComfyUI")`；`textNode=6`、`outputNode=7`、`refAudioNode=8`。
  - **默认参考（2 项）**：均 24kHz 单声道、同一段 134 字参考文本（便于 A/B 对比）：

    | id | 文件 | 参考文本 | 时长 | 默认 |
    |---|---|---|---|---|
    | `builtin-vivian` | `qwen3-tts-1.7B_vivian.flac` + `.txt` | 同名 `.txt`（134 字） | ≈21.3s | ✅ |
    | `builtin-uncle-fu` | `qwen3-tts-1.7B_Uncle_fu.flac` + `.txt` | 同名 `.txt`（134 字） | ≈22.0s | — |

  - **风险**：两个内置参考都超出推荐 5–15s，v1.3 发布前应替换为 8–12s 片段（见 §12.6），替换时同步替换 `.txt`；`Uncle_fu` 参考实测中位 F0 约 190Hz（YIN），比 Vivian 低约 3.4 个半音，但不算“低沉醇厚”，发布前需人工确认音色是否符合预期。
  - 工作流/参考库/参考文件与 `voice.json` 同级存放于数据根或包内，不属于任何书，**不入书档**；「恢复默认」只恢复 `comfy-tts-workflow.json` 与内置参考，不动 `image.json` 地址与 `voice.json` 的 Key。
- **导入其它工作流**
  - 沿用 v1.2 的 `POST /voice/workflow`、格式要求、≤1 MB / 2–2000 节点校验、BOM、失败不覆盖、`reset` 规则；识别口径按下面调整。
  - 识别规则：TTS 节点 = `class_type`/`type` 含 `Qwen3TTS`（默认 `FB_Qwen3TTSVoiceClone`）；**文本入口白名单 = `text` 或 `target_text`**，绝不把 `ref_text`/`instruct` 当文本入口；参考节点 = 沿 `ref_audio` 链接找到的上游音频输入节点（默认 `LoadAudio`），其文件名可写；音频输出 = 优先 `SaveAudio`，其次 `PreviewAudio`，再其次任一 `AUDIO` 输出节点。
  - 校验新增：克隆节点必须存在 `ref_audio` 输入且其上游可写文件名；`x_vector_only` 缺省或为 `false`；为 `true` → `E_TTS_WORKFLOW_NODE`（只克隆说话人、参考文本失效，与本版目标冲突）。
  - 参数覆盖：只改 `target_text`、`ref_text`、`ref_audio` 上游文件名（及存在时的 `language`）；`seed`/`model_choice`/`precision`/`max_new_tokens`/`temperature`/`top_p`/`top_k`/`instruct` 一律沿用工作流值。
- **参考 voice 库（必须，v1.3 取代 v1.2 音色表）**
  - **作用**：参考库是“可切换音色 + 韵律”的唯一来源；换参考只把选中项的 `(参考音频, 参考文本)` 注入请求，**不重写 `comfy-tts-workflow.json`**；`workflowHash` 不变时音频缓存按 `refVoiceId`/`refAudioSha256`/`refTextSha256` 区分。
  - **成对约束（必须）**：`(参考音频, 参考文本)` 是不可拆资产；`ref_text` 必须是**参考音频的逐字转写**，与目标文本无关；替换音频必须同时替换/确认 `ref_text`；`ref_text` 为空 → `E_TTS_VOICE_REF`；文本与音频不匹配无法机检，界面明确提示“必须逐字一致”。
  - **文件契约**：`{version, name, model?, voices:[{id, name, label?, audio, ref_text, lang?, duration_ms?, sha256?, source, default?}]}`；`id` 唯一、1–64；`name` ≤64；`ref_text` 1–2000 字；`audio` 为数据根 `voices/` 下相对路径或包内路径；`source ∈ builtin|imported`；至多一个 `default`；≤256 KB、1–50 项；读文件剥 BOM。
  - **音频约束**：单声道、≥16kHz、无噪声/混响、单人；时长建议 5–15s（<3s 或 >30s 给 warning，不阻断）；格式 `wav|flac|mp3|ogg`、≤32 MB；导入时读取时长与 `sha256` 落盘到表。
  - **默认表**：内置 2 项（来自包内目录，`source=builtin`；Vivian 为 `default`）；用户导入的表存 `comfy-tts-refvoices.json`，参考文件存 `voices/`；缺表时从包内目录兜底，不阻塞试听/配音。
  - **导入/恢复**：`POST /voice/refvoices {table, reset?}`；导入先校验后落盘，失败不覆盖旧表（`E_TTS_VOICE_REF`）；`reset=true` 恢复内置 2 项（Vivian 默认、Uncle_fu）。
  - **选择与回落**：`voice.json.comfyRefVoice` 保存选中 id；不在表内 → 回落 `default`，UI 标注“已回落到 X”，不静默改写文件；显式指定不存在/不可解码 → `E_TTS_VOICE_REF`。
  - **一致性校验**：克隆没有 `speaker` 枚举可校验，改为校验 ① 工作流含 `FB_Qwen3TTSVoiceClone`（或 TTS 节点含 `ref_audio`）；② `x_vector_only=false`；③ `ref_audio` 上游是可写文件名的音频输入节点；④ 参考文件可读且时长在允许范围。不满足分别给 `E_TTS_WORKFLOW_NODE` / `E_TTS_WORKFLOW` / `E_TTS_VOICE_REF`。
  - **v1.2 迁移**：旧 `comfy-tts-voices.json` 与 `voice.json.comfyVoice` 只读保留、不再使用；首次以 v1.3 启动时若 `provider=comfyui-tts` 且无 `comfyRefVoice`，回落内置参考并在设置页提示“音色表已由参考 voice 库取代”。
- **请求注入（必须）**
  - 文本：写 `target_text`（是链接时沿链改上游字符串节点的值）；**不得**写 `ref_text` 或 `instruct`。
  - 参考音频：沿克隆节点 `ref_audio` 链接找到上游 `LoadAudio`，把 `inputs.audio` 写成**当前参考在 ComfyUI input 目录中的文件名**；`ref_audio` 链接本身不改。
  - 参考文本：写 `ref_text`（选中项的表内值）；`language` 写目标语言（默认 `Chinese`）；`x_vector_only` 必须为 `false`（缺失时写入 `false`）。
  - 参考文件传输：优先 `POST /upload/image`（ComfyUI 通用上传到 input 目录，按音频扩展名）→ 用返回文件名写 `LoadAudio`；同机部署可配置直接落盘到 ComfyUI `input/`；**跨机禁止直接写路径**。上传失败 → `E_TTS_VOICE_REF` / `E_TTS_CONNECT`。
- **执行与落盘**
  - `POST /prompt {prompt: apiPrompt, client_id}` → 轮询 `GET /history/{prompt_id}`（1s）→ 从 outputs 取音频 `{filename, subfolder, type}`（兼容 `SaveAudio` 的 `audio` 列表）→ `GET /view` 下载字节；outputs 无音频条目或下载非音频 → `E_TTS_BAD_RESPONSE`。
  - 单页超时 180s（首次含模型加载）、并发 1；失败重试 1 次（网络/超时/5xx/坏响应），4xx、工作流错误、缺模型、参考错误不重试。
  - 取消只停止轮询与落盘，**不调用 `/interrupt`**（避免打断同队列的配图作业）；已完成页保留，再点「补配音」从未完成页继续。
  - 落盘 `audio/NNN.<ext>`（扩展名随返回文件名），回填 `audio_file`/`audio_provider:"comfyui-tts"`；`audio_ms` 优先 WAV 头，否则按字数估。
  - 播放器按 `<audio>` 原生支持格式播放；导出 PPT 只嵌 `.wav`/`.mp3`，其它格式在导出计划给 warning“N 页音频为 flac，未嵌入”，并提示把 `SaveAudio` 输出改成 wav。

- **状态与失败**
  - 五态（`none|voicing|ready|partial|failed`）与四态按钮（生成/补/重新/强制）同 FR-23；`voice_error` 必须含具体码与失败页数。
  - 作业开始前先做一次连接/工作流/参考校验；失败则整讲/整系列直接 `failed` + `E_TTS_CONNECT`/`E_TTS_WORKFLOW*`/`E_TTS_MODEL_MISSING`/`E_TTS_VOICE_REF`，不逐页重复失败。选了 `comfyui-tts` 但 ComfyUI 未启动 → `failed`（不是 `none`）；部分页失败 → `partial`，成功页保留；**不自动回退**云端或浏览器。

- **边界**
  - ComfyUI 不可用不阻塞文本生成与播放；文本 `ready` 与 `voice_status` 仍相互独立。
  - 切回 `browser`/`qwen3-tts` 只改后续配音行为，不迁移、不删除已有 `comfyui-tts` 音频。

### FR-24 配图（P1）

- **策略**：提示词占位 / 本地 ComfyUI；默认占位，不联网、不产生图片文件。

- **单页「换一张」（必须）**：`content_text` 页的配图位在 `image_status=ready` 时提供「换一张」，对**已就绪页**也重新出图：调用 `POST /image/regen {seriesId, lecture, slide, force:true}`，该页 `image_nonce+1` 换种子并重写该页 `image_file`/`image_seed`；**只替换该页**，同讲其它页文件与 `mtime` 不变。`failed` 页显示「重试配图」；`force` 不带 `slide` 时为整讲/整系列重出。

- **按钮状态机（必须）**：无图 →「生成配图」；有缺失页/讲（`partial`/`failed`）→「补配图」；全部就绪 →「重新配图」（二次确认：将重跑页数）；**长按 3s** →「强制重新配图」（二次确认：清空本讲 `images/`、重置 `image_nonce` 并删除该种子缓存后全量重出），按住期间同样显示进度条与剩余秒数。文案随状态变化，禁止任何状态都用同一个「补配图」。

- **AC-136** UI 反馈：按 §7.10 C1–C14 逐项走查，每项有 loading/成功/失败/取消/刷新证据，缺一项即不通过。
- **AC-137（重配音作业）**
  - **构造**：`POST /revoice`；轮询 `/revoice/job`；取消；对比前后讲输出。
  - **断言**：① 返回 `jobId`；② job 有 `status/done/total` 进度；③ 取消后 `cancelled`，已落盘页保留；④ 只改 `audio_file/audio_provider/audio_ms`，文字与锚点逐字不变。
  - **判定**：无进度、取消无效、改文字/锚点 → 不通过。
  - **机检入口**：`node test/v2-revoice.test.mjs`（AC-137 用例）。
  - **人工边界**：重配后音色与所选参考一致。
- **AC-138（回收站恢复冲突）**
  - **构造**：删书 A 进回收站；再导入同 `sha256` 的书；从回收站恢复 A。
  - **断言**：① 恢复返回 `E_BOOK_EXISTS` 与已有 `bookId`；② 不覆盖、不产生第二份；③ UI 只提供「打开已有/取消」。
  - **判定**：覆盖已有书、产生重复 id、静默合并 → 不通过。
  - **机检入口**：`node test/v2-trash.test.mjs`（AC-138 用例）。
  - **人工边界**：冲突弹窗文案是否讲清“打开已有即可”。
- **AC-139（容器/计划/启动解耦）**
  - **构造**：`POST /series` 不带 plan；带 plan；未 plan 直接 `/series/start`；`POST /series/plan` 后再启动。
  - **断言**：① 不带 plan → `draft`，带 plan → `planned`；② 两者都不返回 `jobId`、不起作业；③ 未 plan start → `E_SERIES_UNPLANNED`；④ plan 后 `planned` 才可启动；⑤ Part 与 `part_version` 不变。
  - **判定**：建容器即触发作业、未 plan 可启动、改 Part → 不通过。
  - **机检入口**：`node test/v2-m2.test.mjs`（AC-139 用例）、`node test/v2-m3-server.test.mjs`（draft 不能 start）。
  - **人工边界**：无（纯接口契约）。
- **AC-140（单讲生成）**
  - **构造**：ready 系列；`POST /series/lecture/generate {n:2}`；再用 `/series/start {lectures:[1]}`。
  - **断言**：① 只重跑第 2 讲，第 1 讲 `lecture.json`/`slides.json` mtime 不变；② 第 2 讲 mtime 变化、状态 `ready`；③ `{lectures:[1]}` 同效（只动第 1 讲）。
  - **判定**：动了别的讲、整系列重跑 → 不通过。
  - **机检入口**：`node test/v2-m3-server.test.mjs`（单讲重跑与显式 `lectures` 用例）。
  - **人工边界**：无（纯接口契约）。

## 6 数据与契约

### 6.1 磁盘布局（同根，schema=2）

```
~/.dsh/book-slides/                ← 与 1.x 同根
├── meta.json                      ← schema=2、版本
├── preference.json                ← 分隔条/语速/静音/上次位置
├── voice.json                     ← 语音配置（0600；含 ComfyUI 文本节点与参考 voice 选择）
├── image.json                     ← 配图配置（P1）
├── comfy-workflow.json            ← ComfyUI 配图工作流（P1）
├── comfy-tts-workflow.json        ← ComfyUI 配音工作流（P1，FR-23.1；v1.3 默认 API 格式克隆工作流）
├── comfy-tts-refvoices.json       ← ComfyUI 参考 voice 库（P1，FR-23.1；v1.3 取代音色表；默认 2 项）
├── voices/                        ← 导入的参考音频与同名 .txt（P1；不入书档）
├── audio-cache/                   ← TTS 缓存（含云端与 ComfyUI）
├── trash/<bookId>/                ← 软删除（7 天可恢复）
└── books/<bookId>/
    ├── book.json                  ← 标题/作者/sha256/chapter_source/封面
    ├── chapters.json              ← 章：标题、起止页、字数、source/manual
    ├── pages.json                 ← 逐页文字
    ├── source.pdf                 ← 原件副本
    ├── cover.png                  ← 排版书封
    ├── parts.json                 ← Part 登记
    ├── briefs.json                ← 章介绍缓存
    ├── practice/                  ← 题库、掌握度、场次（P1）
    └── series/<seriesId>/
        ├── series.json            ← 讲纲、讲次、接缝、状态
        ├── stitch.json            ← 后验缝报告（可重算）
        ├── progress.json          ← 系列进度
        └── lectures/<n>/
            ├── lecture.json       ← 讲元数据（页数、字数、状态）
            ├── slides.json        ← 该讲幻灯片
            ├── audio/…            ← 该讲配音
            └── images/…           ← 该讲配图（P1）
```

没有独立的 `modules/` 目录：讲只能存在系列之下（D76）。`meta.json.schema=2` 是 2.0 数据的唯一标记；升级备份在**同父目录** `book-slides.backup-<时间>/`，不在本树内；`trash/`、`audio-cache/`、`comfy-tts-workflow.json`、`comfy-tts-refvoices.json` 与 `voices/`（配置，非书籍数据）不进入书档（FR-22）。

**配置契约**（v1.2 新增字段均为可选，`voice.json.version` 保持 `2`）：

| 文件 | 字段 | 说明 |
|---|---|---|
| `voice.json` | `{version, provider, model, voice, apiKey, rate, comfyRefVoice, textNode}` | 0600；`provider ∈ qwen3-tts\|comfyui-tts\|browser\|off`；`comfyRefVoice` 为参考 voice `id`（默认内置项）；`textNode` 可空（为空时自动识别）；v1.2 的 `comfyVoice` 只读保留、不再使用。 |
| `image.json` | `{provider, host, port, styleSuffix, promptNode}` | ComfyUI 地址与配音共用；`host` 默认 `127.0.0.1`、`port` 默认 `8188`。 |
| `comfy-tts-workflow.json` | `{name, format, savedAt, workflow}` | `format ∈ ui\|api`；坏文件/校验失败不覆盖旧值；不存在时用包内默认。 |
| `comfy-tts-refvoices.json` | `{version, name, model?, source, savedAt, voices[]}` | `source ∈ builtin\|imported`；内置 2 项（Vivian 默认、Uncle_fu）；`voices[]` 每项 `{id, name, label?, audio, ref_text, lang?, duration_ms?, sha256?, default?}`；`ref_text` 是**参考音频的转写**，与目标文本无关；`comfy-tts-voices.json`（v1.2 音色表）只读保留、不再读取。 |

### 6.6 不变式

| 编号 | 不变式 |
|---|---|
| I0 | 同书内任意两个 Part 的 `chapters` 交集为空 |
| I1 | 讲覆盖完备且不重叠：`∪lectures[].chapters = series.chapters` |
| I2 | 讲按章号升序；相邻讲章不重叠；章号连续时页区间相接；切点落在页内时允许相邻讲共享该页（至多重一页） |
| I3 | 每讲章数 ∈ [1,6]，页数 ∈ [6,30] |
| I4 | 每讲字数 ≤ 8 万（工程上限），超出必须再拆 |
| I5 | 相邻讲有且仅有一条 seam，`seam.from=i`、`seam.to=i+1` |
| I6 | 接缝句两处逐字复用（cover 开头 / 末页结尾） |
| I7 | cover 存在且为第 1 页（沿用 `validateSlideSet`） |
| I8 | `terms[].forbid` 在系列内出现次数为 0 |
| I9 | 每讲 ρ ∈ [2.5,8]（越界告警，不阻塞） |
| I10 | N=1 不产生 seam，但仍生成系列（单讲）；无独立模块路径 |
| I11 | 页级 `audio_provider ∈ {qwen3-tts, comfyui-tts}` ⇒ `audio_file` 非空且文件存在；`none` ⇒ `audio_file=null`；`browser` 允许 `audio_file=null`（浏览器朗读） |
| I12 | `comfyui-tts` 页的音频扩展名 ∈ {wav, flac, mp3, ogg}，且生成时 `comfyRefVoice` 属于当前参考库、`ref_text` 非空、`x_vector_only=false`；换工作流/参考库不自动改写已有 `audio_file`/`audio_provider`（仅 `/revoice` 可改） |

### 6.8 状态机

```
系列：draft ─▶ planned ─▶ drafting ─▶ stitching ─▶ ready
                    │            │
                    │            ├─▶ partial
                    │            └─▶ failed / cancelled
                    └─▶ cancelled（未开始）
讲：  queued → structuring → validate → anchor → ready / ready_degraded / failed / cancelled
语音（独立于文本）：none → voicing → ready / partial / failed
```

- `draft`：`POST /series` 已建容器，尚无 plan；不可启动生成。
- `planned`：`POST /series/plan` 已写入 plan；可启动。
- 文本作业与配音作业分离：系列/讲 `voice_status` 独立记录，不阻塞文本 `ready`。语音状态以**讲**为最小持久单位（`lecture.json.voice_status`）；系列级 `series.voice_status` 由讲汇总：任讲 `failed` 或 `partial` 且并非全部就绪 → `partial`；全部讲 `failed` → `failed`；全部 `ready` → `ready`；没有任何音频 → `none`。汇总时必须保留失败码与失败页数到 `voice_code`/`voice_error`（FR-23）。
- ComfyUI 配音在 `queued`（等待配图或其它配音）期间不改写讲 `voice_status`；真正开始执行才置 `voicing`。ComfyUI 配音与配图共用**全局串行队列**：跨系列也只允许一个 ComfyUI 作业（与 FR-23.1 一致）。
- DSH 重启后，未完成的配音作业（含 ComfyUI `queued`/执行中）归一为 `partial`/`failed`（已完成页保留），不得把 `voicing`/`queued` 持久留在 `voice_status`；用户可「补配音」继续。

- 同一系列同一时间只允许一个作业；同一讲同一时间只允许一个生成作业。
- DSH 重启后：`drafting`/`stitching` → `interrupted`，可续跑（已完成讲跳过）。
- `partial`：至少一讲 `ready` 且至少一讲未就绪；允许播放与导出已完成讲。

### 6.9 幂等与缓存键

```
briefsKey   = sha256(bookId | chapters | prompt_version | model)
seriesKey   = sha256(bookId | part 快照 chapters | briefsKey | plan_version | model | prompt_version)
lectureKey  = sha256(seriesKey | lecture.chapters | pages | plan 切片摘要)
audioKey     = sha256(provider | model | voice | format | sample_rate | text)                 // qwen3-tts / browser
comfyAudioKey = sha256('comfyui-tts-clone' | workflowHash | textNode | refVoiceId | refAudioSha256 | refTextSha256 | model | text)  // workflowHash = sha256(工作流原文)；model = model_choice
```

- `POST /series` 幂等键 = `sha256(bookId | partId | part_version | plan | title)`；同键返回已有 `seriesId`，不改变状态、不起作业。
- `POST /series/start` 命中 `seriesKey` 且状态为 `ready`/`partial` → 返回 `cached=true`，不重复调用模型。
- `part_version` 变化只影响新建系列；已建系列沿用快照，UI 标“基于旧快照”。
- 讲内批检查点沿用 `batches/`，重试只补未完成批。
- 参考 voice 库改名不改变键（键不含表名）；换参考（`refVoiceId` 或音频哈希变化）或改 `ref_text` 即换键，自然分缓存。

### 6.11 长任务、取消、续跑与批量契约

**通用规则**

- 所有可能超过 2 秒的操作必须给出 `jobId` 或可中止的请求标识，并有 `status`：`queued/running/cancelled/failed/done`。
- 取消必须幂等；取消后返回 `E_CANCELLED`（或 `{ok:true,status:'cancelled'}`），不产生半截新数据；已落盘的旧数据保留。
- 取消生成不删除、不回滚 Part；Part 只由用户显式编辑/删除改变。
- 只有声明“可续跑/可重试”的操作才保留中间状态；其余取消即清理 staging。
- 超时由服务端兜底，UI 显示“已超时，可重试”；超时与取消都不得留下半截 Part/series/book。

| 操作 | 接口 | 进度 | 取消 | 续跑 / 重试 | 超时 |
|---|---|---|---|---|---|
| 导入解析 | `POST /import` | 上传字节 + 解析页 | 客户端 abort（连接断开即停），服务端清理 staging | 重新导入 | 120s |
| 分章构建 | `POST /chapters/build` | 阶段 + 已处理页 | 客户端 abort | 重新构建 | 120s |
| 封面生成 | `POST /cover` | — | 客户端 abort | 重新生成 | 30s |
| 讲纲预览/保存 | `POST /plan/preview`（草稿）或 `POST /series/plan`（写系列） | 阶段 + 已处理章数 | 客户端 abort | 重新预览/重算 | 120s |
| 系列文本生成 | `POST /series/start`（series 已 planned、Part 已确认）→ job；`GET /series/job` | 第 k/N 讲、页 | `POST /series/cancel` | `POST /series/resume`；`POST /series/retry` | 单讲 10min |

**系列删除**

- `DELETE /series?seriesId=`：先取消运行中作业，再删除该系列目录；返回 `{ok, cancelledJob}`；不删书、不删 Part。
- 删除书（`DELETE /book`）先取消该书所有作业，再进回收站；取消失败则中止删除。

**练习断点**

- `GET /practice/session?seriesId=` 返回当前未完成场次（含已答题、`plan`、下一题）；`POST /practice/session` 有未完成场次时复用，不新建。
- `POST /practice/answer` 同 `qid` 幂等；`POST /practice/finish` 写 summary。

**回收站冲突**

- `POST /trash/restore`：若目标 `sha256` 已在书架，返回 `E_BOOK_EXISTS` 与已有 `bookId`；UI 只能「打开已有」或「取消」，不自动复制/覆盖。

### 6.14 版本与预发布跟踪

**目标**：明确四个独立维度——**产品版本 2.0**（产品线）、**插件包版本 2.0.0**（可安装 SemVer）、**文档版本 v1.11**（本 SRS）、**数据 schema 2**；正式发布前用可排序、可追溯的预发布包版本。

| 阶段 | 版本示例 | 准入 | 承诺 |
|---|---|---|---|
| Alpha | `2.0.0-alpha.1` | 功能未齐，可安装构建 | 不承诺数据/schema 兼容；可重置环境 |
| Beta | `2.0.0-beta.1` | P0/P1 功能齐，进入缺陷修复 | `schema=2` 冻结；只修 bug，不加功能 |
| RC | `2.0.0-rc.1` | 内容/接口冻结，发布门待跑 | 只修发布阻塞问题 |
| 正式 | `2.0.0` | AC-92 ~ AC-156 全绿 | 最终发布，无预发布后缀 |

**规则**

- `package.json.version` 必须是合法 SemVer：`2.0.0-alpha.N` / `beta.N` / `rc.N`；不得使用 `2.x.y-alpha` 这类占位符版本。
- `N` 从 1 开始只增不减、不复用；每次打 tag `v<version>`，tag 必须与 `package.json.version` 一致。
- Alpha 可按里程碑/可安装构建打；Beta 在 P0/P1 功能齐后打；RC 在内容与接口冻结后打。
- 预发布期间 `meta.json.schema=2` 固定；若 schema 变更，必须升 `schema` 并按 FR-20 自动备份，不得用包版本掩盖 schema 变化。
- `GET /meta` 必须返回 `{version, product_version, schema, ...}`：`version` 是插件包版本（如 `2.0.0-alpha.7`），`product_version` 固定 `2.0`，`schema=2`；设置页诊断同时显示包版本与 `schema`；`CHANGELOG` 按包版本记录。
- 2.0 未发布前不得出现 2.1；最终 `2.0.0` 不得带 `-alpha`、`-beta`、`-rc` 后缀。
- 预发布之间不承诺数据兼容；升级到正式版前必须保留备份。

- **AC-141** 版本一致性：`package.json.version`、git tag、`GET /meta.version` 三者相同；`GET /meta.product_version='2.0'`、`GET /meta.schema=2`；alpha/beta/rc 的 `N` 递增且不复用；最终 `2.0.0` 无预发布后缀；出现 `2.x.y-alpha` 或版本不一致时发布检查失败。

## 7 界面规格

**UI 基线**：2.0 必须沿用 1.x 的书架卡面、分屏播放器与设置分组；功能对等不等于可以用骨架 UI 替换。允许改版式细节，不允许把“卡片 + 封面 + 分屏 + 设置页”降级为纯文本或单栏。

### 7.1 详情页（章节选择）

- 章节列表有**两层状态**：**临时勾选**（尚未提交，底部汇总条）与**已确认 Part**（已落盘，组头 + 徽标）。两者不得混用。
- 已确认 Part 按组展示：标题、章数、字数、系列数、「已确认」徽标；组内章显示为选中态并标“属于《…》”，**始终不可直接取消勾选**；编辑/删除走组头菜单。这是预防式禁选：正常 UI 不提供制造 Part 冲突的路径。
- 用户勾选并点「确认此部分」后，界面必须立即用 `GET /parts` 的最新数据重渲染：Part 出现在列表顶部（或按章号就位），临时勾选清空，滚动到该组；**不得只保留临时勾选态**。
- 未确认 Part 时，可直接对草稿调用 `/plan/preview` 预览讲纲（不落 Part）；「开始生成讲义」仍需已确认 Part。
- 底部操作：勾选后显示「预览讲纲（草稿）」「确认此部分」。确认成功后，该 Part 组出现「预览讲纲」「编辑」「删除」；保存为系列后由系列卡「开始生成讲义」启动生成。
- 预览、生成、取消生成都不改变 Part；删除 Part 走独立操作。
- 刷新、重开面板、切换书再回来，已确认 Part 的组头与章归属保持一致。
- 改归属只走组头「编辑」：先移出原 Part，再加入目标 Part；UI 不提供“再勾选已属 Part 的章”。若 API/并发仍返回 `E_PART_CONFLICT`，只提示先移出，不自动并入/移出；取消不写盘。
- 编辑/删除 Part 成功后组头与章归属立即更新；删除只移除分组，不删系列。
- 创建失败（冲突/校验）不产生幽灵组，保留当前勾选以便重试。
- 底部汇总条从“已选 3 章 · 4.2 万字 · 预计 12 页”改为“已选 7 章 · 8.4 万字 · 将生成 2 讲 · 42 页 · 约 40 分钟”。
- “全选”不再按 5 章截断，改为按 48 章 / 8 讲上限截断并说明。

### 7.2 生成前预览

点击草稿或已确认 Part 的「预览讲纲」出预览层（**不写 Part、不写 series**；可取消；服务端中止模型调用）：

| 内容 | 说明 |
|---|---|
| 讲次表 | 第 1 讲：第 4–8 章 · 30 页；第 2 讲：第 9–10 章 · 12 页 |
| 总时长 | 页数 × 60 秒（±10%，页均约 1 分钟） |
| 计划来源 | `planSource=model/rule`；规则降级时显示“本系列未做衔接（unstitched）” |
| 接缝与术语 | 接缝句列表、术语表；缺失时说明原因 |
| 切点提示 | `cut_warn`（如“第 3/4 章可能属同一主题”） |
| 取消 | 取消即关闭预览，不改 Part、不写 series |
| 操作 | 「开始生成讲义」（需已确认 Part）/「调整切点」（拖动讲边界，只在章末）/「取消」；取消只关闭预览，不影响已确认 Part |

### 7.3 冲突提示（API/并发兜底）

默认 UI 已对已确认 Part 的章禁选，正常操作不会出现冲突框。仅当 API 直调、并发或数据竞态导致 `E_PART_CONFLICT` 时，界面显示一条**提示**（不弹三选对话框）：

> 第 5 章已属于《函数》；请先在该 Part 的「编辑」中移出冲突章。

提示不提供“并入/移出”动作，不写盘、不调模型；用户关闭提示后，草稿保留，便于先编辑原 Part 再重试。生成不是这里的前置条件。

### 7.4 系列卡

模块列表上方新增系列卡：标题、`N 讲 · 总页数 · 约 X 分钟`、缝合状态徽标（已衔接 / 未衔接 / 部分就绪）、「继续听」「练一练」「导出」「⋯（重规划/删除）」。Part 改名或增删章后，系列卡显示「基于旧快照（vN）」；系列内容不变。

- 「删除」需二次确认；运行中先取消作业再删，删除后列表立即移除。
- 「重规划」先展示受影响的讲（k..N）与预计重跑页数，确认后才调用。
- 「导出」进入导出对话框（按讲/整套/批量 ZIP），显示页数、音频/配图/体积 warning。
- `partial/failed/unstitched` 卡片显示下一步动作：续跑、重试失败讲、查看缝合报告。
- `draft/planned` 卡片：`draft` 显示「编辑讲纲」，`planned` 显示「开始生成讲义」；`drafting` 显示进度与取消。
- 音频独立：系列卡/讲菜单的音频按钮按状态显示「生成配音」/「补配音」/「重新配音」（二次确认）/ 长按 3s「强制重新配音」（二次确认），调用 `/revoice`（`force` 见 §6.7）；失败时显示配音徽标 + 具体错误码 + 失败讲数 + 「补配音」入口（FR-23）；文本 `ready` 不等待配音。当前 provider 为 `comfyui-tts` 时，作业排队显示“排队中（配图/配音）”；参考 voice 不可用（缺失/不可解码）或工作流 `x_vector_only=true` 时，按钮旁显示警告，试听/生成配音禁用并指向设置页。
- 配图同构：按钮按状态显示「生成配图」/「补配图」/「重新配图」（二次确认）/ 长按 3s「强制重新配图」（二次确认），调用 `/image/regen`；失败时显示配图徽标 + 错误码；单页入口见 FR-24。
- 讲级操作：每讲可单独「生成本讲」「重试」；只影响该讲，不阻塞其他讲。

### 7.5 播放器

- 布局：左 55% 原文 / 右 45% 幻灯片，分隔条可拖并记忆；<1040px 上下堆叠。
- 原文：按 `source_pages` 渲染 PDF 视觉版式；`source_anchor` 段落高亮并滚入视野；`unanchored` 提示“本页未定位到原句”；顶部页码 chip + 「打开原始 PDF」。
- 顶部：`第 2 讲 · 3/18 页 · 系列 24/42`，右侧「系列目录」按钮。
- 讲末页播完 → 过渡卡 5 秒（可点跳过）→ 下一讲 cover。
- 系列目录抽屉：每讲显示标题、章、页数、进度；点击跳讲。
- 从系列目录打开某一讲：仍带系列上下文（进度、下一讲）；N=1 时隐藏“下一讲”与过渡卡。
- 底部：开始听/暂停、上一页/下一页、语速、静音、页码；**逐页缩略图条**（16:9 迷你版式、当前页高亮、点击跳页并停旧音频、原文同步）；键盘空格/←/→/F/Esc。
- 配图提示词：点击配图位展开 `image_prompt` 全文并可「复制提示词」；「收起」/点面板外任意区域/`Esc`/翻页均能收起，且不吞这次点击；面板打开时 `Esc` 先收面板，再退全屏/返回。

### 7.6 练习与导出入口

- 系列卡「练一练」：组卷范围 = 系列全部章；准备页显示“覆盖 2 讲 · 7 章”。
- 练习：先展示题库状态（已有题数/覆盖章），「准备题库」「开始练习」是两个独立动作；题库不足时开场提示先准备/补题，不自动生成；出题进度、补题二次确认、判题反馈、点击讲解后的 pending/失败、结束总结、续做与错题本按 §7.10 C9。
- 「导出」：默认“按讲导出（推荐）”；勾选“合并为一个文件”后展示页数 = Σ讲页数 + (N−1) 过渡页。
- 导出对话框显示音频/配图/备注开关、体积 warning、下载进度/失败重试；批量导出给 ZIP，按 §7.10 C11。

### 7.7 书架与书籍管理（P0）

- 书架为卡片网格：封面、书名、作者（有则显示）、`N 章 · M 页`、`K 个系列`、最近系列“继续听”。
- 排序：最近打开优先；无系列的书排在后面；>200 本时 200 条上限 + 提示。
- 封面由 `POST /cover` 独立生成；无封面时显示书名 + 首章标题占位，不阻塞导入/分章/生成。
- 卡片菜单：重命名、删除（进回收站）；书架顶部有「回收站」入口；菜单点外部/Esc 可关且不吞点击。
- 操作显示进行中/成功/失败；恢复遇同 `sha256` 显示 `E_BOOK_EXISTS` 与「打开已有/取消」。
- 回收站列出已删书，可恢复；恢复后卡片回到原位置，系列与进度保留；7 天内可恢复，不自动清理。

### 7.8 分章构建与校准（P0）

- 导入只入库；详情页无章节时显示「生成章节目录」，选择 `自动`（默认）/ `目录`（书签或印刷目录）/ `机械`（固定页数或字数）后才调用 `/chapters/build`。
- 目录模式先指定目录页码范围；解析后展示“标题 + 印刷页”，可校准为物理页。
- 构建后进入“章预览”：每行显示序号、标题、起止页、字数、来源徽标（书签/目录/机械/手动）；同时显示 `confidence` 与 `warnings`，目录解析回退机械时显式提示。
- 封面是独立动作：卡片无封面时显示占位，可点「生成封面」调用 `/cover`；不阻塞分章与生成。
- 支持改起止页、合并相邻章、拆分一章、重命名；保存前做覆盖与递增校验。
- 有目录页码时提供“按目录页码校准”按钮，显示校准前后差异；失败给出具体章号。

### 7.9 设置与作业（P0）

- 设置分四组：语音、模型（只读）、配图（P1）、存储与诊断。
- 语音：供应商四选一（浏览器朗读 / 千问 Qwen3-TTS / 本地 ComfyUI（Qwen3-TTS）/ 关闭）；选本地 ComfyUI 时同组展示地址（与配图共用，默认 `127.0.0.1:8188`，可改）、工作流（当前名 + 导入/恢复默认）、**参考 voice 库**（下拉显示 `name · 语种 · 时长`；默认内置 2 项（Vivian / Uncle_fu）；导入 `comfy-tts-refvoices.json` / 导入参考音频 + 同名 `.txt` / 删除 / 恢复默认；条目详情只读展示 `ref_text` 并提示“这是参考音频的转写，不是要配音的正文”；时长不在 5–15s 给黄色 warning；`x_vector_only` 固定 `false` 且只读；不再展示音色表）、**连接测试**与**试听测试**；保存/试听/配音显示进行中与结果；失败显示具体错误码与失败讲数（FR-23）；Key 只显示尾号，空输入不覆盖旧 Key；ComfyUI 不填 Key。
- 存储：同根下的 2.0 数据路径、占用空间、回收站条目数、「清空回收站」；诊断：插件包版本、产品版本 `2.0`、`schema`、DSH/pdfjs 版本、最近 5 条错误（不含正文）与语音 provider/工作流/参考 voice 摘要。
- 导出默认：是否含音频/配图/备注；配图设置随 FR-24。
- 生成中系列卡显示“第 k/N 讲 · 第 p/P 页”，提供「取消」（停止可续跑 / 放弃并删除该系列；Part 保留）；取消后状态为 `cancelled` 或直接删除。
- 配音作业独立显示第 k/N 页与作业状态 `queued/running/done`；讲 `voice_status` 为 `voicing/ready/partial/failed`；ComfyUI 排队显示“排队中”，可取消；失败给具体 `E_TTS_*`。
### 7.10 操作反馈契约（C1–C14）

所有操作统一要求：按钮进入 loading、禁用重复提交、错误可读、成功后刷新对应数据；取消与失败不得留下半截状态。二次确认与输入类操作（如重命名）统一用**插件内居中弹窗**（复用遮罩层，非浏览器原生 `confirm`/`prompt`）：`Esc` 或点遮罩 = 取消，默认焦点在「取消」（输入框例外）。

| # | 操作 | 必须出现 | 成功后 | 失败/取消 |
|---|---|---|---|---|
| C1 | 导入/分章/封面 | 导入进度；分章模式与 `warnings`；封面独立生成 | 打开详情/章预览 | 错误码 + 重试；staging 清理 |
| C2 | 讲纲预览 | 草稿或已确认 Part；加载/取消、讲次/页数/时长、seam、terms、`cut_warn`、`planSource`/降级提示 | 「开始生成讲义」可用（需 Part） | 可重试；不改 Part |
| C3 | Part 编辑/冲突兜底 | 默认对已确认 Part 的章禁选；API/并发冲突只提示先移出，不自动并入/移出 | 组头与草稿刷新 | 取消不改任何 Part |
| C4 | 章校准 | 保存中/成功；受影响系列“基于旧快照”徽标与入口 | 列表刷新 | 校验失败定位到章号 |
| C5 | 后验缝 | 六项指标、失败讲/页、建议动作 | 修复后报告刷新 | 未修复项保留并标注 |
| C6 | 系列作业 | 第 k/N 讲、页进度、取消（停止可续跑 / 放弃并删除该系列） | 系列卡状态刷新 | 网络中断提示；可续跑；Part 不受影响 |
| C7 | 语音 | 保存/试听/配音进度；按钮四态文案（生成/补/重新/强制）；失败徽标 + 具体错误码 + 失败讲数；重新配音二次确认；**连接测试/试听测试**结果（版本、工作流、节点、缺失项、耗时）；**参考 voice 库**导入/恢复默认/回落提示/时长 warning/`ref_text` 提示/`x_vector_only=false` 校验；ComfyUI 排队状态 | Key mask、工作流摘要、参考库与状态刷新 | 错误可读（含 `E_TTS_QUOTA`/`E_TTS_CONNECT`/`E_TTS_VOICE_REF` 等具体码）；失败不静默；不泄露 Key |
| C8 | 配图 | 逐页状态/整体进度、单页「换一张」/重试/取消；按钮四态文案（生成/补/重新/强制）；失败徽标 + 错误码 | 图状态刷新 | 失败页留白且可见；不阻塞文字；失败不静默 |
| C9 | 练习 | 题库状态、出题进度、补题确认、判题反馈、讲解需点击「查看讲解」、结束总结 | 场次/错题本刷新 | 题库不足提示先准备，不自动生成 |
| C10 | 书档 | 导入/导出进度、冲突策略、逐本结果 | 书架刷新 | 单本失败不影响其它本 |
| C11 | 导出 | 计划（页/音频/配图/体积）、warning、下载进度 | 文件完成 | 失败可重试；批量给 ZIP |
| C12 | 升级备份 | 备份路径提示、失败阻断与重试 | 进入空书架 | 备份失败原根不动 |
| C13 | 书籍管理 | 重命名/删除/恢复的进行中与结果 | 书架/回收站刷新 | 恢复冲突提示已有书 |
| C14 | 系列卡/讲 | `draft/planned` 的编辑讲纲/开始生成；`partial/failed/unstitched` 的下一步动作；讲级「生成本讲/重试」；删除/重规划确认与影响讲列表 | 列表刷新 | 删除取消运行中作业 |

| 类别 | 要求 | 度量 |
|---|---|---|

| 存储 | 每 100 页原文新增派生数据 <5 MB（不含音频与图） | 体积测量 |

## 9 错误码（2.0）

| 码 | 触发 | 用户可见文案 |
|---|---|---|
| `E_BAD_ID` | bookId / partId / seriesId 非法 | 参数不合法 |
| `E_NOT_FOUND` | 书不存在 | 找不到这本书 |
| `E_PART_EMPTY` | `chapters` 为空 | 先勾选至少一章 |
| `E_PART_INVALID` | 章号不是非负整数 | 章节参数不合法 |
| `E_NO_CHAPTER` | 章号不在本书 | 找不到第 N 章 |
| `E_CHAPTER_EMPTY` | 空白章（<50 字） | 第 N 章是空白页 |
| `E_NO_TEXT` | 书没有可用的逐页文本 | 这本书没有可用的文本，重新导入后再试 |
| `E_LLM_JSON` | 重试后仍不是合法 JSON | 模型输出格式异常，已重试 |
| `E_LLM_SCHEMA` | 修复后仍不合规 | 生成内容不合规 |
| `E_LLM_FAIL` | 模型调用失败 | 模型调用失败，可重试 |
| `E_LECTURE_EMPTY` | 讲没有幻灯片 | 这一讲还没有生成内容 |
| `E_DUPLICATE` | 相邻讲重复率 >0.5 | 相邻两讲重复太多，建议重生成衔接页 |
| `E_TERM` | 出现禁用术语 | 术语写法不一致，可一键修正 |
| `E_COVERAGE` | 有章未被任何讲覆盖 | 有章没有被覆盖，需要重新规划 |
| `E_ORDER` / `E_PAGES` | 讲序或页区间不合法 | 页面与章序对不上，需要重生成该讲 |
| `E_PART_FRONT` | 含 `front` 章 | “前文”不能单独成部分 |
| `E_PART_DUP` | 章重复 | 选择有重复，刷新后再试 |
| `E_PART_TOO_MANY` | >48 章 | 一个部分最多 48 章，建议拆分 |
| `E_PART_CONFLICT` | 与已有 Part 相交 | 第 X 章已属于《…》 |
| `E_PART_NOT_FOUND` | partId 不存在 | 找不到这个部分 |
| `E_SERIES_TOO_MANY` | 规划讲数 >8 | 这个部分太大，建议拆成两个部分 |
| `E_PLAN_FAILED` | 讲纲两次失败 | 讲纲没生成出来，已按规则切分 |
| `E_PLAN_INVALID` | 讲纲校验不过 | 讲纲不合规，已重试 |
| `E_SERIES_BUSY` | 系列有作业在跑 | 正在生成，请稍候 |
| `E_SERIES_NOT_READY` | 未就绪就导出/练习 | 还没生成完，完成后才能用 |
| `E_SERIES_EMPTY` | 无一讲就绪 | 这个系列没有可用讲次 |
| `E_SEAM_MISSING` | 缺少 seam | 本系列未做衔接 |
| `E_SEAM_MISMATCH` | 断言不通过 | 第 N 讲衔接句不一致，已尝试修复 |
| `E_REPLAN_RANGE` | `from` 越界 | 调整范围不合法 |
| `E_EXPORT_SERIES_LIMIT` | 导出超上限（默认 150MB，含整套合并） | 文件太大：按讲导出，或勾掉「含音频」 |
| `E_UPGRADE_BACKUP_FAILED` | 旧根自动备份失败 | 备份失败，升级已中止；请检查权限/磁盘后重试 |
| `E_CANCELLED` | 用户取消/客户端 abort | 已取消，可重试 |
| `E_SERIES_UNPLANNED` | 系列尚无 plan 就启动 | 先生成/保存讲纲，再开始生成 |
| `E_BANK_INSUFFICIENT` | 题库不足就开场 | 先准备题库或补题 |
| `E_NO_SESSION` | 没有未完成练习场次 | 当前没有可继续的练习 |
| `E_BOOK_EXISTS` | 恢复时同 `sha256` 已在书架 | 打开已有书，或取消恢复 |
| `E_TTS_UNCONFIGURED` | 未配置 Qwen Key / 未选 ComfyUI 工作流 | 还没配置语音：填 Key、配置 ComfyUI 或改用浏览器朗读 |
| `E_TTS_AUTH` | 语音服务 401/403 | 语音服务鉴权失败，检查 Key |
| `E_TTS_QUOTA` | 语音服务 429 / 额度耗尽 | 语音额度已用完，充值或改用浏览器朗读 |
| `E_TTS_TIMEOUT` | 单页超时（云 60s / ComfyUI 180s） | 第 N 页配音超时，可重试 |
| `E_TTS_NETWORK` | 网络失败 | 网络异常，配音可重试 |
| `E_TTS_BAD_RESPONSE` | 返回结构异常 | 语音服务返回异常，可重试 |
| `E_TTS_FAIL` | 单页重试后仍失败 | 第 N 页配音失败，其余可听 |
| `E_TTS_CONNECT` | 连接测试/作业预检连不上 ComfyUI（网络错误/超时） | 连不上 ComfyUI，确认地址、端口与服务是否在运行 |
| `E_TTS_WORKFLOW` | 工作流不是 JSON / 缺节点 / 引用不完整 | 工作流格式不对，请用「保存（API 格式）」重新导出 |

## 附录 B 核心算法（与 `series.js` 当前实现一致）

```
planLectures(chapters, pages, opts):
  N_est = max(1, ceil(totalChars / 60000))        # 仅作容量估计；实际讲数由装章决定
  for ch in chapters by n:
      if chars(ch) > 60000:                       # 单章 >6 万就章内拆（6 万 ≈ 30 页上限）
          flush(current)
          for seg in splitChapter(pages, ch, 60000):
              push lecture(ch=[ch.n], seg.from..seg.to, seg.chars)
      else:
          if current.length = 6: flush()                                           # ① 章数上限
          if current 非空 and current.chars + chars(ch) > 80000: flush()          # ② 硬上限 I4
          if current 非空 and current.chars + chars(ch) > 60000
             and current.chars >= 42000: flush()                                  # ③ 目标 6 万
          append ch to current
          if current.length = 6 or current.chars >= 60000: flush()                # ④ 装满
  if len(lectures) > 8: throw E_SERIES_TOO_MANY   # 不静默截断
  for L: L.pages = clamp(round(L.chars / 2000), 6, 30)
  assert I1..I4
  return {lectures, totalChars, totalPages, estMinutes, warnings, estimatedLectures}

# 注：cut_warn / cut_line / density_warn 是规范意图，当前 rulePlan 未实现；
#     真书验收只核对已实现的不变量，未实现项单列风险，不得用“AC 通过”掩盖。

splitChapter(pages, ch, limit):
  cut = 离中点最近的节标题行（第X节 / X.Y / 一、 / 【…】）
        没有节标题 → 中点附近的行边界；再没有 → 中点
  head = ch[:cut]，tail = ch[cut:]
  任一段 > limit 时对这一段继续二分（同一规则），直到每段 ≤ limit
  2 段记 上/下；>2 段记 1/N
  切点在页内时相邻两讲共享该页（至多重一页）

assertSeams(lectures, plan):
  for i in 1..N-1:
      seam = plan.seams[from=i, to=i+1]            # 缺失 → E_SEAM_MISSING
      sentence 非空且 ≤ 60 字                       # 否则 E_SEAM_LENGTH
      cover.audio_script.trim().startswith(sentence)  # 否则 E_SEAM_COVER
      last.audio_script.trim().endswith(sentence)     # 否则 E_SEAM_LAST
      两处朗读稿 ≤ 220 字                            # 否则 E_SEAM_AUDIO_LENGTH
  return {ok, checked, failures[]}

replanFrom(k):                                      # 规范已定，本期未实现
  保留 lectures[1..k-1]；重算 k..N 的装章、页预算与 seams；只失效 k..N 的缓存
```
