## 0. 一页速览

**一句话**：把 PDF 书拆成章，让用户勾几章合成一个「精讲模块」，模型把它改写成一套幻灯片文字 + 逐页配音稿，浏览器里左边原文、右边 PPT 加音频地听下去。

**演示路径（5 步）**：拖入 PDF → 自动列出章节 → 勾选第 1、2、3 章 → 点「生成精讲」→ 进入分屏播放。

```
PDF 上传 ──▶ 文本提取 ──▶ 章节正则 ──▶ 勾选合并 ──▶ LLM 分块改写 ──▶ TTS 逐页合成 ──▶ 分屏播放
            pages.json    chapters.json   module.json    slides.json     audio/*.mp3
```

**交付物**

1. 一个可 `dsh plugin install` 的插件包 `dsh-book-slides`
2. Host 半体（Node/ESM，零构建）+ Client 半体（`window.__ModuleLoader__.load`，单文件，无打包器）
3. 左侧栏独立面板「精讲」：书架 → 书籍详情 → 勾选章节 → 生成进度 → 分屏播放器
4. 本文档第 9 节的验收清单（AC-1 ~ AC-24）

**里程碑**：M1 书架与导入（2d）→ M2 解析与勾选（1.5d）→ M3 生成流水线（3d）→ M4 播放器（3d）→ M5 打磨与验收（1.5d）。

| **D3** | 「章节（Chapter）列表」「第1、2、3章」 | 什么算一章？`第X节`/`第X回`/`序章`/`番外`/`Chapter 1`/无标题散文算不算？ | v1 认 **`第X章` / `第X节` / `第X回` / `第X讲` / `第X篇` / `第X卷` / `序章·序言·前言·引子·楔子·尾声·后记·附录·番外` / `Chapter N` / `Part N`**；识别为「行首、长度 ≤ 40 字、无句末标点」的短标题行。见附录 A 正则与算法。 | 覆盖中文书绝大多数形态；英文只做 `Chapter/Part` 最小支持，不做多语言 |
| **D4** | 「对应的页码位置」 | 是章节标题所在页，还是章节正文起始页？印刷页码还是物理页？ | 统一使用 **PDF 物理页序号，1-based**（即 pdf.js 的 `pageNumber`）。章节区间 = `[本章标题页, 下一章标题页)`。**不解析印刷页码**（脚注页码与物理页常常错位，收益低、易错）。 | 物理页是唯一能直接驱动渲染与跳转的坐标，印刷页码无法保证可计算 |
| **D5** | 「简单的正则匹配」 | 目录页里的「第一章 …… 3」也会命中，产生假章节 | 增加 **目录页剔除**：某页文本含 `目录/目 录/Contents` 且该页候选 ≥ 3 条时，该页候选标记 `toc=true` 不建章；再对标题相同的相邻重复候选去重。 | 不做这一步，几乎每本书都会多出「目录」这一章并挤掉真第一章 |
| **D6** | （未提）没有章节标题的书 | 散文集、小说、合同、报告没有「第X章」 | **兜底为全书 1 章「全文」**；若总页数 > 60，面板提示可切换「按 10 页切块」的降级模式（生成「第 1 部分…」）。兜底不报错。 | 报错会让用户以为导入失败；切块上限保证生成不被上下文限制卡死 |
| **D7** | 「干净文本」 | 干净到什么程度？页眉页脚、页码行、软换行、零宽字符怎么处理？ | 定义清洗规则：①去掉在 ≥60% 页面重复出现的短行（页眉页脚）②去掉纯数字且 ≤ 4 字符的孤立行（页码）③合并中文软换行（行尾非句末标点则与下一行拼接）④全角/半角标点归一、连续空白压成一个、删零宽字符。清洗只作用于**送给模型的文本**，原文显示用未清洗版本。 | 清洗提升正则与生成质量，但原文窗格必须保持可对照的真实原文（D15 视觉版式） |
| **D8** | JSON 中 `page_index` | 是幻灯片第几页，还是 PDF 第几页？ | 拆成两个字段：**`slide_index`（1-based，幻灯片序号）** 与 **`source_pages: {from, to}`（PDF 物理页）**。原文中的 `page_index` 字段废弃。 | 一个字段两种含义是这份 JSON 最大的坑，前端取页必然取错 |
| **D9** | `layout: cover` / `quote` | 三种版式的边界、字段要求未定义 | `cover` **只允许出现在 `slide_index = 1`**；`quote` 额外必填 `quote_text` 与 `quote_source`；`content_text` 的 `bullet_points` 限 **1–5 条**、每条 ≤ 40 字；`title` ≤ 24 字。 | 版式没有硬约束，模型会随机产出「第二页封面」或 12 条要点 |
| **D10** | 「`source_text` 用于前端字符串匹配定位」 | 匹配算法未定义；模型会改字、换行、加省略号，直接 `indexOf` 命中率很低；一章里同一句话可能出现多次 | **改为锚点回填**：模型只输出 `source_quote`（原文片段，≤ 200 字）；宿主在生成后做**归一化匹配**（去空白、去标点、繁简不转换），定位到 `{page, para_index}` 并写入 `source_anchor`。命中率 < 90% 触发一次「锚点修复」调用；仍有未命中的条目标记 `anchor_status: "unanchored"`，播放器降级为**按页定位**（不高亮）。 | 让可验证的机器做定位，让不可靠的模型只做摘抄；90% 是可测的量化门槛 |
| **D11** | （未提）长文本 | 勾 3 章可能 6 万字，单次调用必然超限或被截断 | **分块生成**：按章节边界累积，单批 ≤ 12000 字符；单章超限则章内按段落切 8000 字批，批间带前批末尾 300 字做衔接上下文。目标密度 1 页 / 1500–2500 字符，单模块 6–24 页，硬上限 30 页。超出章节数上限（5 章）或字数上限（6 万字）时，生成按钮给出明确提示并禁止提交。 | 分块是唯一能同时保住质量和上下文安全的做法；上限让失败发生在点击前而非生成中 |
| **D12** | 「发送给 LLM 生成」「转化为音频」 | 同步还是异步？耗时多长？失败了怎么办？ | 一律**异步作业**：`POST /generate` 立即返回 `{moduleId, jobId}`，前端 1s 轮询进度；支持取消；作业状态机 `queued → structuring → validate → anchor → voicing → ready / ready_degraded / failed / cancelled`（见 §5.4）。LLM 成功而 TTS 部分失败 → `ready_degraded`，播放器对无音频页显示「仅文字」。 | 6 页模块 LLM+TTS 实测量级在 60–180s，同步按钮会撞 30s 超时与浏览器断开 |
| **D13** | （未提）重复生成与花费 | 同一模块点两次「生成」是否重复烧钱 | 模块缓存键 = `sha256(bookId + 章节列表 + 模型 + promptVersion)`；命中直接秒开已有结果；面板提供显式「重新生成」（带二次确认，覆盖旧结果）。音频按 `sha256(文本+音色+语速+供应商)` 单独缓存，换模块也能复用。 | 用户会反复点；不缓存等于把成本交给误操作 |
| **D14** | 「`image_prompt`」 | 本轮既然不生成图片，这个字段给谁用？ | v1 **只展示不使用**：幻灯片右侧留「配图位」占位卡，鼠标悬停/点击显示 `image_prompt` 全文并提供「复制」。字段仍必填（≤ 60 字），保证 P2 接文生图时数据已在。 | 不出图但也不能把字段做成死数据，否则等于白让模型写 |
| **D15** | 「PPT 形式播放图文及音频」「分屏播放」 | 左右比例、原文显示范围、是否同步高亮、快捷键 | 左 55% 原文窗格（**按 PDF 视觉版式，非提取的文本流**），右 45% 幻灯片舞台（16:9 等比缩放）；顶部页码 chip + 「打开原始 PDF」；原文按 `source_pages` 取页，命中 `source_anchor` 的段落高亮并自动滚入视野；键盘：`空格` 播放/暂停、`←/→` 翻页、`Esc` 退出、`F` 全屏；宽度 < 1024px 时上下堆叠。 | 视觉版式保留原书排版与图表位置，用户能按版面找到原句；代价是高亮要在渲染页上叠加坐标层（需要 pdf.js 渲染与文本坐标映射），并放弃文本流的搜索/无障碍便利。本项为 2026-11-03 用户明确变更，替代原「文本流」方案 |
| **D16** | 「逐页调用 TTS API」 | 供应商？音色？失败重试？并发？ | 支持两类：**Qwen3-TTS**（云端，v1.2 先支持 `qwen3-tts-flash`）与**浏览器 Web Speech**（零成本备选），可关闭。逐页合成，并发 2，单页超时 60s，失败重试 1 次；单页文稿 ≤ 300 字。未配置 Qwen 或合成失败**不阻断生成**，直接进 `ready_degraded` 只出文字。 | 本地单机场景下，语音是最容易缺配置的一环，做成可降级比做成硬依赖更好用 |
| **D17** | 「AI 模型切换」 | 是切换生成文案的 LLM，还是切换语音合成模型？ | 面板里的「AI 模型」**只指语音合成模型**；文本生成仍走 DSH 默认模型（D1 / FR-5），**不新增 LLM Key**。v1.2 只开放 `qwen3-tts-flash`，后续模型以白名单扩展，不提供任意模型名输入。 | 两个模型都叫「模型」会让人误以为要再填一个 LLM key；分开命名避免双份配置与双份计费 |
| **D18** | 「API Key 配置，存入本地文件，面板隐藏」 | 存哪个文件？隐藏到什么程度？怎么换 key？ | Qwen API Key 存 `$DSH_HOME/book-slides/voice.json` 的 `apiKey` 字段，文件权限 **0600**；不写环境变量、不写日志、不进 URL。`GET /voice` 只返回 `hasKey` 和 `apiKeyMask`（末 4 位）；面板用 `type=password`，已保存时显示「已保存 · 尾号 xxxx」+「更换」，空输入不覆盖旧 key。 | 「面板隐藏」= 不回显完整 key；本地文件仍是明文，靠 0600 与单机边界保护，不做假加密 |
| **D19** | Qwen3-TTS HTTP 接口 | 端点、请求、响应、音频格式、失败怎么办？ | `POST https://maas.qianwenaiapi.com/api/v1/services/aigc/multimodal-generation/generation`，`Authorization: Bearer <apiKey>`；body `{model, input:{text, voice, language_type}}`；**不要传 `format` / `sample_rate`**（Qwen3-TTS 不接受，会返回 400）。响应 `output.audio.url` **24 小时后过期**，必须立即下载到模块 `audio/NNN.wav`（接口返回 WAV）。单页超时 60s、失败重试 1 次、并发 2；401/403 → `E_TTS_AUTH`，429 → `E_TTS_QUOTA`，超时/网络 → `E_TTS_TIMEOUT` / `E_TTS_NETWORK`，结构/参数不对 → `E_TTS_BAD_RESPONSE`（带上千问返回的 message 便于排查）。错误文案去敏，不打印 Authorization。 | 官方 Qwen3-TTS API 参考的 curl 就是 `multimodal-generation/generation` + `input.text/voice/language_type`；把 Qwen-Audio-TTS 的 `format/sample_rate` 混进来会 400 |
| **D20** | 音色下拉列表 | 用哪些音色？名称/描述从哪来？ | v1.2 只列 **Qwen3-TTS 非实时系统音色**（文档中的 48 个：Cherry、Serena、Ethan 等），下拉显示「名称 · 描述 · 性别」；`voice` 原样传 API，大小写敏感。不做复刻音色、声音设计、实时接口、方言指令。 | 文档把实时与非实时分成两张表；非实时表才是 `qwen3-tts-flash` 的可用集合，混用会 400 |
| **D21** | 语音失败与播放器 | Qwen 失败时回退浏览器吗？播放器怎么显示？ | **不自动回退**到浏览器（避免用户不知情地换了声音）。未配置 key → `E_TTS_UNCONFIGURED`；部分页失败 → 成功页 `audio_file:"audio/NNN.wav"`、`audio_provider:"qwen3-tts"`，失败页 `audio_provider:"none"`，模块 `ready_degraded`；播放器对无音频页显示「本页无配音」并跳过。 | 自动回退会让「我选了 Qwen」变成「实际在浏览器念」，且难以排查；显式降级更可控 |
| **D22** | 重复合成花费 | 重新生成模块会不会重复调用 Qwen？ | 音频缓存键 = `sha256(provider + model + voice + language_type + text)`，缓存目录 `$DSH_HOME/book-slides/audio-cache/`；命中直接复制到模块 `audio/`，不重复请求；只缓存成功结果，不缓存 401/429。 | 重新生成、重试同一模块很常见；按文本+音色缓存能同时省费用与等待 |

## 2. 范围

### 2.1 目标（v1 必须做到）

1. 拖入一份**带文本层**的 PDF，15 秒内看到书籍卡片和章节清单。
2. 勾选 1–5 个章节，一次点击得到一个可播放的「精讲模块」。
3. 播放页左原文、右幻灯片，音频自动翻页，讲到哪段原文亮到哪段。
4. 关闭面板再打开，书、模块、进度都还在。
5. 全流程数据只在本机；除「章节文本 → 模型」「配音稿 → 语音服务」外不外发。

### 2.2 非目标（明确不做，避免范围蔓延）

| 不做 | 说明 |
|---|---|
| OCR / 扫描件 / 版面分析 | 原文已声明；无文本层的 PDF 直接拒绝并给出原因 |
| 文生图 | 只出 `image_prompt`，占位卡展示 |
| EPUB / TXT / Markdown | 这些是「书库」插件的领域；本插件 v1 只吃 PDF |
| 多用户 / 账号 / 云同步 | 本地单机，无服务端 |
| 与「书库」互读数据 | 见 D2 |
| 移动端适配 | 桌面优先，< 1024px 仅做上下堆叠 |
| 导出 PDF/HTML/PPT 文件 | P2 候选，见 Q5 |
| 逐句字幕与音频时间戳对齐 | 需要 TTS 返回词级时间戳，v1 字幕只显示整页文稿 |
| Agent 工具入口（`present_slides`） | v1 只有面板按钮入口，避免双写面板状态；P2 再加 |

### 2.3 用户与场景

只有一个用户：装了 DSH 的本人。典型场景是「我有这本书的 PDF，我想让人讲一遍给我听」。因此：不要登录、不要配额、不要多租户，要的是**快、离线可用、失败可恢复**。

## 3. 术语

| 术语 | 定义 |
|---|---|
| 书（Book） | 一份导入的 PDF，对应一个 `bookId`，有 `book.json` |
| 章（Chapter） | 书内按标题正则切出的顺序单元，编号 `n` 从 1 开始，有 `chapters.json` |
| 精讲模块（Module） | 用户勾选的一到多个章组成的生成单位，是播放的最小单元 |
| 幻灯片（Slide） | 模块内的一页，含标题、版式、要点、配音稿、配图提示词、原文锚点 |
| 锚点（Anchor） | `{page, para_index}`，把幻灯片指回原文的具体段落 |
| 作业（Job） | 一次生成流程的运行实例，有进度、可取消 |
| 降级产出（Degraded） | 文字齐了但部分页没有音频的模块状态 |

## 4. 功能需求

> 每条格式：**描述 → 规则 → 验收（AC-n）**。AC 都是可手动复现的判据。

### FR-1 书架

- **描述**：面板打开即书架。卡片流展示封面、书名、作者（有则显示）、章节数、已生成模块数、「继续听」按钮。
- **规则**
  - 排序：最近打开优先；无模块的书排在后面。

### FR-8 AI 语音（Qwen3-TTS，v1.2）

- **描述**：在现有浏览器朗读之外，接入千问 Qwen3-TTS 非实时语音合成；用户在「设置 → 语音」里切换供应商与模型、配置 API Key、选择音色；生成模块的 `voicing` 阶段逐页合成 WAV 并落盘，播放器直接播放音频文件。
- **规则**

  - **Key 存储**：Key 存 `voice.json.apiKey`，文件 0600；保存后 `GET /voice` 只返回 `apiKeyMask`（例如 `••••a1b2`），不返回明文；面板输入框 `type=password`，空输入不覆盖旧 key；日志/错误文案不得包含 key 或 Authorization。

  - **失败与降级**：未配置 key → 本次 `ready_degraded` + `E_TTS_UNCONFIGURED`；部分页失败 → 成功页保留音频，失败页 `audio_provider:"none"`，整模块 `ready_degraded` + `E_TTS_FAIL`；**不自动回退浏览器**。播放器按 `audio_file` 播放，缺文件显示「本页无配音」并跳过。
  - **缓存**：音频缓存键 = `sha256(provider|model|voice|format|sample_rate|text)`，目录 `audio-cache/`；命中直接复制到模块 `audio/`，不调用 API；401/403/429 不写缓存。
  - **安全边界**：Key 只发给 `maas.qianwenaiapi.com`；不写入 `slides.json`、`module.json`、URL 或日志；卸载插件不删除 `voice.json`。

## 5. 数据与契约

### 5.1 磁盘布局

```
$DSH_HOME/book-slides/
├── voice.json                         # 语音配置（0600；Qwen key 只存这里）
├── preference.json                    # 分隔条比例、字号、上次播放位置
├── progress.json                      # 书架「继续听」位置
├── audio-cache/<sha256>.wav           # Qwen 合成缓存（按文本+音色+模型）
├── trash/<bookId>/                    # 软删除
└── books/
    └── <bookId>/                      # 12 位小写字母数字，如 k3m9x2p1q8za
        ├── book.json                  # 书名、作者、页数、sha256、导入时间、原始文件名
        ├── source.pdf                 # 原件副本
        ├── pages.json                 # [{page:1, text:"..."}, ...] 未清洗
        ├── chapters.json              # [{n:1, title:"第一章 …", from:1, to:18, chars:9123, manual:false, toc:false}]
        └── modules/
            └── <moduleId>/
                ├── module.json        # 勾选章节、状态、错误码、模型、promptVersion、时间戳
                ├── slides.json        # 规范化的幻灯片数据
                └── audio/001.wav …    # Qwen 合成，按 slide_index 命名
```

**约定**
- 所有写入走临时文件 + 原子 rename，避免半截 JSON。
- `bookId` / `moduleId` 只允许 `^[a-z0-9]{8,16}$`，所有读接口先用该正则校验再拼路径（防目录穿越）。
- `book.json` 存在即视为导入完成（`pages.json`、`chapters.json` 先写，`book.json` 最后写）。

### 5.2 `slides.json` 规范（对原文 JSON 的替换）

原文的 `page_index` 被拆分为 `slide_index` + `source_pages`；新增 `source_anchor`、`audio_ms`、`module_id`、`prompt_version`、`schema_version`。

```json
{
  "schema_version": 1,
  "module_id": "m7fk2a9d",
  "book_id": "k3m9x2p1q8za",
  "module_title": "精讲：第 1–3 章",
  "chapters": [1, 2, 3],
  "generated_at": "2026-11-03T12:00:00+08:00",
  "model": "deepseek-chat",
  "prompt_version": "b2p-v1",
  "slides": [
    {
      "slide_index": 1,
      "layout": "cover",
      "title": "电影导演：不止是「咔嚓」一声",
      "subtitle": "第 1 章至第 3 章",
      "bullet_points": [],
      "quote_text": null,
      "quote_source": null,
      "image_prompt": "手绘风格的红色胶卷指向一台电影摄影机，暖色调",
      "audio_script": "大家好，今天我们来讲第一部分……",
      "source_quote": "导演的工作，远不止喊一声「开机」。",
      "source_pages": { "from": 1, "to": 4 },
      "source_anchor": { "page": 2, "para_index": 3 },
      "anchor_status": "anchored",
      "audio_ms": 18400
    }
  ]
}
```

**校验规则（零依赖手写实现，违反即触发修复调用）**

| 字段 | 规则 |
|---|---|
| `schema_version` | 必须为 `1` |
| `slides` | 数组长度 6–30；`slide_index` 连续从 1 开始 |
| `layout` | ∈ `cover` / `content_text` / `quote`；`cover` 仅允许 `slide_index=1` |
| `title` | 必填，1–24 字，不含换行 |
| `bullet_points` | `content_text` 必填 1–5 条，每条 ≤ 40 字；其余版式必须为 `[]` |
| `quote_text` / `quote_source` | `quote` 版式必填，`quote_text` ≤ 120 字 |
| `image_prompt` | 必填，1–60 字，中文 |
| `audio_script` | 必填，40–220 字，**不得出现**「如下图所示」「看幻灯片」之类依赖视觉的表述 |
| `source_quote` | 必填，10–200 字；**必须是该批原文的连续子串**（归一化后） |
| `source_pages.from/to` | 整数，`1 ≤ from ≤ to ≤ 书总页数` |

### 5.3 HTTP 接口

所有路由前缀 `/dsh-book-slides/`，仅接受同源请求（校验 `Origin`/`Sec-Fetch-Site`），方法不符返回 405。

| 方法 | 路径 | 请求 | 响应 |
|---|---|---|---|
| POST | `/import` | multipart：`file` | `{ok, bookId}` 或 `{ok:false, code}` |

### 5.4 作业状态机

```
queued ──▶ structuring ──▶ validate ──▶ anchor ──▶ voicing ──▶ ready
   │            │             │            │          │
   └────────────┴─────────────┴────────────┴──────────┴──▶ cancelled
                └──▶ failed（任一步不可恢复）        └──▶ ready_degraded（部分音频失败）
```

- 同一模块同一时间只允许一个作业（重复提交返回当前作业）。
- 作业态存内存 + `module.json` 快照；DSH 重启后处于 `structuring/voicing` 的模块标为 `interrupted`，可一键重跑。

## 附录 A 章节识别

**主正则**（在清洗后的行文本上逐行匹配，`m` 模式）

```js
const CHAPTER_RE = /^\s*(?<head>第\s*[0-9一二三四五六七八九十百千零〇两]+\s*[章节回讲课篇卷部]|(?:序章|序言|前言|引子|楔子|尾声|结尾|后记|附录[一二三四五六七八九十\d]*|番外(?:篇)?[一二三四五六七八九十\d]*)|(?:chapter|part)\s+[0-9ivxlcdm]+)\s*(?<tail>.*)$/i;
```

**候选过滤**：`tail`（标题尾巴）长度 ≤ 40；整行 ≤ 60 字；整行不以 `。！？.!?` 结尾；不是纯页码行。

**切分算法**

1. 逐页逐行产出候选 `{page, lineIndex, text, n?}`。
2. 若某页含 `目录|目\s*录|contents` 且该页候选 ≥ 3 → 该页候选标 `toc=true`；紧随其后含候选且标 `toc` 的页同样处理（最多 3 页）。
3. 丢弃 `toc=true` 的候选。
4. 相邻候选标题完全相同 → 保留先出现的。
5. 按出现顺序编号 `n=1..k`；区间为 `[page(n), page(n+1))`，末章到末页。
6. `k < 2` → 全书 1 章（D6）。

**清洗规则**（D7）

1. 按 `\n` 切行，去首尾空白。
2. 统计每行文本（去数字后）在所有页面中出现的页数；出现在 ≥ 60% 页面的短行（≤ 30 字）判定为页眉页脚，删除。
3. 删除 `^\d{1,4}$` 的孤立行（页码）。
4. 中文行尾不是 `。！？；：」』”` 且下一行首字不是标题候选 → 合并为一行（去软换行）。
5. `\u3000` → 空格；连续空白压成一个；删除 `\u200b-\u200f\ufeff`。

## 附录 F 目录驱动的切章（v1.1 重构）

> 状态：**待实现**。本节取代 FR-3 的主路径；现有机械切章保留为回退路径。
> 触发原因：机械切章在同一本书上连续三次出现结构性错误，且每次修复都引入新回归（附录 D/E 与后续两次 fix 均有记录）。

### F.0 换掉机械切章的理由

不是「规则还不够多」，是**找结构的地方错了**。章节结构印在目录页上，正文页眉只是它的影子，而影子会被 OCR 打散：

| 真实现象 | 机械路径的处理 | 后果 |
|---|---|---|
| 页眉只剩「第6章」，标题在下一行或根本没有 | 与下一行粘连 | 图表标签「多发射和深流水线」变成第 7 章的标题 |
| 正文里「第6章中主要内容……」这类跨章引用 | 被当成标题候选 | 抢走章节起点与标题 |
| 译注/索引照抄章号 | 章号重复 → 判为引用 | 靠补丁才勉强压住 |
| 附录 A/B/C/D 只差一个字母 | headKey 相同 → 并成一章 | 四个附录变一章 |

每压住一条，就在别处冒出新的。**目录页是唯一一处把「章节 + 顺序 + 页码」放在一起印刷的地方**，读它比拼页眉稳得多。

### F.1 目标与不变量

- **目标**：给定一本带目录页的 PDF，切出的章节标题与顺序和目录一致，误差为 0 页。
- **人工只出一次手**：导入时指出目录在哪（两个数字），之后全自动。
- **不变量**
  1. 目录解析失败时，**必须**回退到机械路径，且用户在 UI 上看得到「已回退」。
  2. 模型只负责「读懂目录文字」，**不负责**定位物理页；定位由可验证的校准算法完成。
  3. 每一条章节边界都能被「标题在该页区间内出现」这一事实校验，校验率写入结果。

### F.2 流程

```
① 预填目录范围 ──▶ ② 用户确认 ──▶ ③ 抽目录原文 ──▶ ④ 模型抽取
   (自动猜)          (可跳过)                          │
                                                       ▼
                            ⑥ 落盘 + 抽查 ◀── ⑤ 校准印刷页→物理页
                                    │
                         失败 ──▶ 回退机械切章（附录 A）
```

| 步 | 做什么 | 失败怎么办 |
|---|---|---|
| ① | 用现有 `looksToc` 猜目录页码范围，填进导入表单 | 猜不出就留空 |
| ② | 用户确认或修改范围；也可勾「没有目录页」 | 勾了就直奔回退路径 |
| ③ | 只取该范围的逐页文本（不发给模型以外的任何地方） | 范围为空 → 回退 |
| ④ | 调一次模型，要求严格 JSON | 超时/坏 JSON → 重试 1 次 → 回退 |
| ⑤ | 印刷页 → 物理页（F.4） | 校准失败 → 回退 |
| ⑥ | 写 `toc.json` / `chapters.json`，跑标题抽查 | 命中率低 → 标 `unverified`，仍可用 |

### F.3 需求条目

**FR-3R.1 指定目录范围**
「按目录切章」面板放在**书籍详情页顶部**（不是导入表单），两个数字框，预填第 ① 步的猜测值；旁边一句「建议 9–15 页（共 608 页），猜得不对就改」。附「看这几页」按钮，抽目录原文前 800 字给用户确认。
> 与最初设想的偏差：原计划放在导入表单里。实现时改成入库后：用户导入时通常还没翻到目录页，而目录范围往往要试一两次才能对；放在详情页可以反复调，且老书也能用。
验收 AC-R1。

**FR-3R.2 目录抽取**
把该范围逐页文本（保留行号）交给模型，得到 `[{title, printed_page, level}]`。
硬约束：
- 只取**大章节**：`第X章 / 第X部分 / Chapter N / Part N / 序章 / 前言 / 附录X`；**不取节、小节、习题**。
- `printed_page` 必须来自原文；只允许纠正明显的字符混淆（`O→0`、`I/l→1`、`S→5`、`Z→2`），并在条目上标 `fixed_char: true`。
- 按页码升序排列，不得编造条目。
验收 AC-R2、AC-R3。

**FR-3R.3 目录结果校验**
模型返回后逐条校验：页码单调递增、数量在 3–60 之间、`title` 非空且 ≤ 40 字、`level` 在枚举内。
不合格 → 把「原文 + 上一次输出 + 具体错误」一起回灌重试 1 次；仍不合格 → 回退。
验收 AC-R4。

**FR-3R.4 校准印刷页 → 物理页**
见 F.4。校准结果（`offset`、每章 `anchor`）写入 `toc.json`。
验收 AC-R5。

**FR-3R.5 章节落盘**
`chapters.json` 的 `from/to` 由校准后的物理页决定；`to = 下一章 from - 1`，末章到全书末页。第一章之前的页面归「前文」（`n=0`，不可勾选）。
验收 AC-R6。

**FR-3R.6 标题抽查**
对每条章节，在 `[from, to]` 的正文里做标题模糊匹配（去空白、容错 2 字）。命中率 = 命中数 / 章节数。
- 命中率 ≥ 0.8 → `status: verified`
- < 0.8 → `status: unverified`，面板显示黄条「N 章未校验」，但仍可生成

**FR-3R.7 失败回退**

验收 AC-R8。

**FR-3R.8 手工修正**
沿用现有章节操作（改名/拆分/合并/排除），新增 `setRange {n, from, to}`：手工改页范围。
被手工改过的章打 `manual: true`；再次执行目录解析时**只重算未手改的条目**，手改条目保留。

### F.4 校准算法（印刷页 → 物理页）

目录给的是**印刷页码**，与 PDF 物理页之间差一个偏移 `offset`（前置版权页、罗马数字页、插页都会造成偏移，且可能分段）。

**证据 A：页眉页码（默认）**
1. 扫每页的首行与末行，取其中的 1–4 位数字作为该页的印刷页码候选（要求数字位于行首或行尾，且该行不是纯数字行）。
2. 计算 `physical - printed`，取出现次数最多的差值作为全局 `offset`。
3. 众数占比 ≥ 0.6 才算成立。

**证据 B：标题锚定（校验与补救）**
1. 对每个目录标题，在正文里找**首次命中**的页（去空白后容错 2 字，且命中行必须是页面首行或次行）。
2. 该页即该章的物理起点候选，`offset_B = 物理页 - 印刷页`。
3. 若 `|offset_B - offset_A| > 2`，该章改用 `offset_B` 定位，并标 `anchor: "title"`。

**证据不足时**
证据 A 不成立（众数占比 < 0.6）、且某章证据 B 也无命中 → 该校准失败，走回退。

**不做的事**：不假定 offset 全章恒定而直接相加；每章都要能被证据 A 或 B 单独定位。

### F.5 目录抽取提示词契约

文件：`prompts/toc-extract-v1.md`（版本号进缓存键；改提示词必须改版本号）。

输入：

```
【目录原文】每行前带行号，便于引用
【书名】…
【已知】这本书共 N 页
```

输出（严格 JSON，无围栏、无解释）：

```json
{
  "entries": [
    { "title": "第1章 计算机概念和技术", "printed_page": 1, "level": "chapter", "fixed_char": false },
    { "title": "附录C 控制器的硬件实现", "printed_page": 537, "level": "appendix", "fixed_char": true }
  ]
}
```

提示词要点（写死在文件里）：
1. 只输出大章节；「1.1 / 6.9 / 习题」这类小节一律跳过。
2. 标题照抄目录原文，不改写、不润色；明显的 OCR 混淆字符可纠正并置 `fixed_char`。
3. 页码取该条目右侧最近的数字；没有页码的条目**丢弃**，不要猜。
4. 目录里重复出现的同号条目（目录页被排了两遍）只保留第一条。
5. 输出按页码升序；无法确定顺序时保持原文顺序。

为什么不用 DSH 的 skill 机制挂载：面板流程要可重复、可测试、可离线跑用例，直接 `ctx.llm` 调用更可控。提示词以文件形式存放，将来要做成 skill 只是加一层包装。

### F.6 数据与接口

`toc.json`（与 `book.json` 同目录）：

```json
{
  "range": { "from": 9, "to": 15 },
  "prompt_version": "toc-extract-v1",
  "model": "deepseek-flash",
  "status": "verified",
  "offset": 27,
  "hit_rate": 0.92,
  "entries": [
    { "title": "第1章 计算机概念和技术", "printed": 1, "physical": 28, "anchor": "header", "fixed_char": false },
    { "title": "附录C 控制器的硬件实现", "printed": 537, "physical": 575, "anchor": "title", "fixed_char": true }
  ]
}
```

接口：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/toc?bookId=` | 返回三样：`range`（用户上次填的）、`suggested`（`looksToc` 的猜测）、`toc`（上次解析结果）。**客户端优先用 `range`** |
| POST | `/toc/range` | `{bookId, from, to}` → 把范围写进 `toc.json` 的 `range`。面板改了页码 600ms 后自动调它 |
| POST | `/toc/preview` | `{bookId, from, to}` → `{preview, chars}`，回前 800 字用于确认 |
| POST | `/toc/parse` | `{bookId, from, to, force?}` → 同步返回结果（模型 30s 内完成），带 `status/offset/hitRate/chapters` |
| POST | `/chapters` | 新增 `op: "setRange"`，`{n, from, to}` |

> **范围必须落盘**（FR-3R.1 的实现细节）：最初范围只存在面板状态里，退出再进来就被建议值覆盖，「看这几页」的内容也一起没了。现在改页码后防抖写 `toc.json.range`，重新进入时用它还原输入框，并据此重新生成预览——预览文字本身不存，是算出来的。

缓存键：`sha256(pdf_sha256 + range + prompt_version + model)`。命中缓存直接复用，不重复花 token。

### F.10 对你四条提议的审阅意见

| 你的提法 | 判断 | 补充 |
|---|---|---|
| （1）导入时指定目录页码范围 | **采纳**，这是整套方案的锚点 | 必须给预填值（复用现有 `looksToc`），否则用户不知道页码从哪数起 |
| （2）抽目录文字交给 LLM，识别标题与起页 | **采纳** | 只发目录页文本；必须要求严格 JSON 并做二次校验，模型会漏章、会瞎编页码 |
| （3）「起页有偏移，但能确定一章有多少页」 | **只对一半** | 页码差只能算**长度**，算不出**起点**。要真正定位，必须再加一次校准（F.4：页眉页码众数 + 标题锚定）。这一步是整个方案里唯一需要"可验证证据"的地方，不能省 |
| （4）「然后再解析」 | **采纳** | 这里的"解析"= 校准 + 落盘 + 标题抽查，不是把机械切章再跑一遍 |

另外补三条你没提但会踩的：

1. **目录页码本身会被 OCR 认错**（真书里 `175` 被认成 `IZ5`、`150` 认成 `15O`）。所以页码必须允许字符纠正，且纠正后的页码要过单调性检查。
2. **目录可能被排了两遍**（简目 + 详目），同号条目要去重。
3. **不是每本书都有目录**。回退路径必须保留且被测着，不能因为新路径上线就把老路径删了。

| 新增 `bindPopupDismiss(doc, {menu, toggle, onDismiss})` | 菜单打开时在 `document` 上挂两个捕获监听：`click` 与 `keydown`。target 落在菜单或「⋯」内 → 不动（交给各自 `onClick`）；其余一律 `onDismiss('outside')`；`Esc` → `onDismiss('escape')`。返回清理函数，关掉即摘监听 |
| `BookCard` | 新增 `menuRef` / `moreRef`；`useEffect([menu])` 里绑定与清理；`closeMenu()` 顺带复位删除的二次确认态（`armed`）；`Esc` 关闭后把焦点还给「⋯」；「⋯」按钮补 `aria-expanded` |

**为什么挂在 `document` 的捕获阶段、用 `click` 而不是 `pointerdown`**：面板外的点击也要能关，所以只能挂 `document`；卡片里的「⋯」「继续听」自己会 `stopPropagation`，冒泡阶段的监听会被截断，捕获阶段才收得到。用 `click` 而不是 `pointerdown`，是为了只认真实点击——拖滚动条、选字、右键按下都不会误关菜单。这条修复**只关菜单、不吞这次点击**：点卡片本体时菜单收起后，点击照常走到卡片自己的 `onClick`，于是直接打开这本书（实测即如此，用户已确认这是想要的行为）；点别的卡片、顶栏按钮同理。为此没有写任何「拦截这一下点击」的代码。

**关闭路径**

| 操作 | 结果 |
|---|---|
| 再点「⋯」 | 关闭（原行为保留） |
| 点菜单里的「改名 / 删除」 | 执行原逻辑，菜单关闭 |
| 点卡片本体（封面、标题、空白） | 收起菜单，这次点击照常打开这本书 |
| 点别的卡片、顶栏按钮、面板空白 | 收起菜单，被点的东西照常响应 |
| 点面板外（对话框、聊天区等） | 收起菜单 |
| `Esc` | 收起菜单，焦点回到「⋯」 |

**验收**：AC-31。`npm test` 全绿（162 项通过、2 项按环境跳过，与修复前一致）。`panel.test.mjs` 新增 2 项：①卡片默认不渲染菜单且「⋯」是 `aria-expanded="false"`；②`bindPopupDismiss` 覆盖「菜单内不关 / 「⋯」上不关 / 外部关 / `Esc` 关 / unbind 后不再响应 / 无 `document` 时安全空操作」。浏览器内的真实点击已由用户复核：点外部能关，点卡片本体收起菜单并打开书（与上表一致）。

## 附录 L M5 体验修复：生成后自动定位到「生成中」条目（2026-11-03）

**用户验收意见（FR-5 生成流水线 / AC-14）**：点底部「生成精讲」后，界面停在章节列表底部，模块列表里的「生成中」条目在视野之外，用户找不到「取消」。要求生成后**自动定位到对应条目**。

**根因**：`JobBox` 原先渲染在模块列表上方，是一块独立卡片；用户勾完章节点底部固定的生成按钮时，进度卡片出现在页面顶部，不在当前视野。模块列表本身也要等轮询进入终态才刷新，所以生成期间列表里没有对应条目可找。

**修法**（`client.js` 单文件；Host 半体与数据格式零改动）

| 位置 | 改动 |
|---|---|
| `JobBox` | 改成模块列表里的一行（`.bl-mod.bl-mod-run`，琥珀色高亮 + 左侧竖条），显示标题、阶段、进度条、当前/总数和「取消」；补 `data-job-item` / `data-job-cancel` 供定位与聚焦 |
| `ModuleList` | 接收当前 `job`，把生成中模块固定渲染在列表第一行，并从普通行里过滤掉，避免重复；真实记录尚未刷新时用合成条目占位，计数也算上它 |
| `startGenerate` | 拿到 `moduleId` 后立刻 `setRefresh` 拉真实模块记录（标题/章数不必等轮询），并递增 `jobFocus` 触发定位 |
| `Detail` + `focusJobEntry` | 用 `.bl-body` 容器查 `[data-job-item]`，`scrollIntoView({block:'center', behavior:'smooth'})` 滚到条目，焦点落到取消按钮；不支持 smooth/参数的嵌入环境退回普通滚动，找不到条目时静默放弃 |
| 详情页载入态 | 刷新同一本书时不再切回「正在打开」把列表卸掉；刷新失败保留已显示的书与模块列表，避免生成中的条目被错误卸载 |

**验证**：`npm test` 全绿（162 项通过、2 项按环境跳过）。`panel.test.mjs` 新增 2 项：①生成中的模块留在列表里（带进度/取消、不重复、计数正确、有定位属性），列表尚未刷新时先渲染合成条目；②`focusJobEntry` 覆盖滚动 + 聚焦、`smooth` 不支持时回退、找不到条目/无容器时安全空操作。Client 改动需重启 DSH 后生效；浏览器内真实滚动待用户复核。
