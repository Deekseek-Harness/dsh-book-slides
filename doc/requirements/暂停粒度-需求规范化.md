## 1. 原文与现状

### 1.1 原文

> “暂停”粒度升级：
>
> - 现在的“暂停”时机（没有问题，保留）：插件页面离开播放页、点击暂停按钮
> - 但是暂停的“粒度”太粗——页：每次继续播放，都是该页整页从头开始重新播放，我希望既然是音频，就按音频的“粒度”实现才符合最佳实践

### 1.2 现状（代码证据）

- 播放 effect 以 `playing` 为依赖；暂停时 cleanup 调 `stopAudio()`，下一次 effect 把 `bar` 归零；继续时新建 `Audio`，从 0 开始。`client/index.js:2387-2484`、`2533-2537`。
- 进度只记 `lecture + slide`；`progress.json` 没有页内时间。`host/progress.js:91-98`、`host/api.js:1113-1125`。
- 离开播放页 = Player 卸载；`handleBack` 只 `stopAudio()`，不记录页内时间。`client/index.js:2786-2789`、`8196-8204`。
- 浏览器朗读用 `speechSynthesis.cancel()`，没有暂停/恢复位置。`client/index.js:1216-1248`。
- 现有 AC-108 只保证“回到该讲该页”，不保证“该页第几秒”。SRS FR-18 / AC-108。

### 1.3 问题

- **页是现在的最小播放单元**：长页 3–5 分钟，暂停一次就要重听整页；页面越长，代价越大。
- **暂停被做成了停止**：`stopAudio()` 移除 `src` 并 `load()`，所以“继续”只能新建元素从 0 开始。
- **进度条暂停即归零**，用户看不到“听到哪”，也不符合音频播放器的一般预期。
- 这是**续播状态**缺陷，不是**暂停时机**缺陷；不要在“什么时候暂停”上改。

## 2. 规范后的需求

### 2.1 定义

- **播放位置** `P = (lecture, slide, offset_ms)`：`lecture/slide` 定位页；`offset_ms` 是**当前页音频文件内**的媒体时间（从该文件开头起算，单位毫秒）。不是系列总时长，也不是句子序号。
- **暂停**：停止发声并保存 `P`；同一页内不销毁音频上下文，不把“暂停”做成“停止”。
- **继续**：从 `P.offset_ms` 接着发声；不回到 0，不重新加载整页，不先响页首再跳转。
- **音频粒度**：续播的最小单位是媒体时间（毫秒），不是页、不是句。句级/词级高亮与 TTS 对齐不在本次范围。
- **显式翻页**：点缩略图、上一页/下一页、键盘 `←/→`、系列目录跳讲、换讲、从目录/缩略图明确选页。显式翻页到**不同页**时，新页从 0 开始；点当前页缩略图维持现状（不重播、不改变位置）。
- **离开播放页**：Player 组件卸载（返回系列/书架、切到设置等视图、关闭面板）。切到后台标签页不算暂停（维持现状）。

### 2.2 必须行为

| # | 场景 | 必须发生 | 不得发生 |
|---|---|---|---|
| M1 | 同页暂停 → 继续 | 记下 `audio.currentTime`；继续从该秒接着播；进度条停在原位 | 新建音频源、从 0 开始、进度条归零、先响页首再跳 |
| M2 | 播放中离开播放页 → 重新进入 | 离开前保存 `P`；回到该讲该页，停在离开时的秒；不自动播放；点「继续听」从该秒继续 | 回到页首、丢页、自动播放 |
| M3 | 暂停后离开 → 重新进入 | 同 M2，位置精确到暂停点 | 把“暂停点”退化成“页首” |
| M4 | 关闭 DSH/浏览器 → 重新打开（D1=B） | 从 `progress.json` 恢复页 + 秒；不自动播放；播放中未暂停时以最后一次周期保存为准（±5s） | 恢复成页首、恢复成别的页 |
| M5 | 显式翻页 | 新页从 0；播放中翻页先停旧音频，再播新页；暂停中翻页停在新页 0 | 把旧页 offset 带到新页、旧音频残留 |
| M6 | 音频变更 | `playbackKey`（`audio_file` / `audio_provider` / `audio_ms` / `audio_script`）变化时旧 offset 失效，按 0 处理，并提示“配音已更新，从本页开头播放” | 用旧 offset 去 seek 新音频、越界播放 |
| M7 | 语速/静音变更 | 就地改 `playbackRate` / `volume`，保持 `currentTime`；暂停中改，继续时仍从原位置 | 重建音频、回到页首 |
| M8 | 页结束 / 连播 | `ended` 后当前页视为完成，自动翻页，下一页从 0；最后一页按现有收尾 | 把旧 offset 写到下一页、循环回页首 |
| M9 | 浏览器朗读 | 不纳入秒级续播保证；同页暂停/继续、跨页、重启均按页重播；暂停时提示“浏览器朗读不支持精确续播” | 伪造秒级续播、静默回到页首 |

### 2.3 位置的生命周期

**采集点**

- 点「暂停」/空格暂停：立即保存。
- 离开播放页：在卸载前保存；用 `keepalive` / `sendBeacon`，失败不阻塞返回。
- 页面隐藏/关闭（`pagehide` / `visibilitychange=hidden`）：保存一次。
- 播放中：每 5 秒节流保存一次（只在文件音频且 `currentTime > 0` 时）。
- `ended`：当前页位置清零，再走自动翻页。

**失效点**

- 显式翻到不同页、换讲、换系列：`offset_ms = 0`。
- `playbackKey` 变化：`offset_ms = 0`。
- `ended`：`offset_ms = 0`。
- 浏览器朗读跨页/重启：`offset_ms = 0`。

**归一化**

- `offset_ms = max(0, min(round(ms), 24h))`；负数/非数字按 0。
- `offset_ms < 500ms` 按 0（避免“刚播就暂停”存一个无意义的小数）。
- 元数据加载后若 `offset_ms >= duration`，按 0 处理；若 `duration` 尚不可知，先保留，加载后再夹。
- 跨会话恢复时不得先 `play()` 再从 0 seek；应在 `loadedmetadata` 后先 seek 到目标位置，再 `play()`。同页暂停后的继续不需要 seek（元素还在暂停点）。

**写入**

- `progress.json` 增加可选 `offset_ms`（整数毫秒）+ 音频身份 `audio_file` / `audio_ms` / `audio_provider`；`schema` 仍为 1，旧文件缺字段按 0/空，属于向后兼容的加法，不触发数据根迁移。
- 音频身份只用于“重新配音/换音频后旧位置失效”：`offset_ms > 0` 时随位置一起写，`offset_ms = 0` 时清空。
- `GET /series/progress` 返回 `offsetMs` / `audioFile` / `audioMs` / `audioProvider`；`POST /series/progress` 接受同名参数（缺省时：同 `lecture+slide` 保留旧值，换页则归 0 并清空身份）。
- 不改变 `heard` 的口径（仍记“听到的最大页码”）。
- offset 的周期写入不应反复改 `preference.json` 的 `lastSlide` / 更新时间；只在页/讲真正变化时写 preference。
- 恢复过程不得用缺省 0 覆盖已保存的 offset；初始 hydration 要跳过“清零写入”，或直接带恢复后的 offset 写入。

**失败与并发**

- 写入失败不阻塞播放/返回；下次成功写入覆盖。
- 同一系列多标签页同时播放时最后一次写入生效（已知限制，不在本次解决）。

### 2.4 UI 反馈

- 按钮：播放中「暂停」；暂停且 `offset_ms > 0`「继续听」；新页/`offset_ms = 0`「开始听」。
- 进度条：暂停不归零；重新进入加载元数据后直接停在保存位置；翻页才归零。
- 时间：`mm:ss / mm:ss`（SHOULD）；浏览器朗读可用估算时长或 `--:--`。
- 状态：`已暂停 · 01:23`；重新进入时 `上次听到 01:23`；浏览器朗读暂停时提示“不支持精确续播”。
- 拖动 seek：本期不做（D4=A）；进度条仍只读。

### 2.5 非目标

- 不改变暂停触发点：不新增“切后台/失焦自动暂停”。
- 不做每页历史位置：显式翻页后旧页不保留（D2=A）。
- 不做句级/词级高亮、TTS 对齐。
- 不做跨设备/跨账号同步；`progress.json` 仍不入书档。
- 不做拖动进度条 seek（D4=A）。
- 不改“每页一个音频文件”的数据模型；不改连播/过渡规则。
- 不引入新服务、新数据根。

## 3. 验收标准

> 并入 SRS 时顺延为 AC-166 起；编号以合并时为准。

### AC-P1（同页暂停/继续，音频粒度）

- **构造**：选一页有 `audio_file` 的页，播到约 8s，点「暂停」，等 3s，点「继续听」。
- **断言**：① 暂停后进度条停在约 8s，不归零；② 继续后首个 `timeupdate` 的 `currentTime` 在 7.5–9.0s；③ 没有新的 `loadstart` / `emptied`（仍是同一个音频元素）；④ 状态文案出现 `已暂停 · 00:08`。
- **判定**：从 0 开始、进度条归零、重建音频、或先响页首再跳 → 不通过。
- **机检入口**：纯函数 `resolveResumeOffset` / `formatClock` 单测 + 播放器 source 断言；实际出声走人工边界。
- **人工边界**：继续处是否无缝、无爆音、无“从头闪回”。

### AC-P2（离开播放页再进入）

- **构造**：播到 30s 暂停，返回系列，再进同一系列；另跑一次“播到 30s 直接返回”。
- **断言**：① 回到同讲同页；② 进度条停在 30s（有计时则显示 `00:30`），不自动播放；③ 点「继续听」从 30s 开始；④ `progress.json` 的 `offset_ms` ≈ 30000，且 `audio_file` / `audio_ms` / `audio_provider` 与本页一致。
- **判定**：回页首、丢页、自动播放 → 不通过。
- **机检入口**：`test/parity-settings.test.mjs` 的进度往返扩展，或新增 `test/v2-player-resume.test.mjs`。
- **人工边界**：重新进入时进度条是否立刻显示保存位置。

### AC-P3（重启后继续，D1=B）

- **构造**：播到 30s 暂停，重启 DSH，从书架「继续听」进入。
- **断言**：① `progress.json` 仍有 `offset_ms`；② 回到该讲该页该秒；③ 不自动播放；④ 点「继续听」从该秒继续。
- **判定**：恢复成页首、或恢复成别的页 → 不通过。
- **机检入口**：宿主 `readProgress` / `saveProgress` 单测 + 浏览器人工走查。

### AC-P4（音频变更失效）

- **构造**：`offset_ms = 30000`，音频身份记录为当前 `audio_file` / `audio_ms` / `audio_provider`；重新配音或改掉任一身份字段；重开播放器。
- **断言**：① 身份不一致 → offset 按 0 处理；② 出现“配音已更新，从本页开头播放”；③ 不 seek 到越界位置、不崩溃；④ 再次暂停时写回新的身份与位置。
- **判定**：旧 offset 被继续使用 → 不通过。
- **机检入口**：`resolveResumeOffset({ savedMs, durationMs, audioKey, savedAudioKey })` 单测。

### AC-P5（显式翻页从 0，D2=A）

- **构造**：第 3 页播到 30s；点第 5 页缩略图；再回第 3 页。
- **断言**：① 第 5 页从 0；② 回第 3 页也从 0；③ `progress.json` 的 `offset_ms = 0`；④ 旧音频立即停，无残留声。
- **判定**：旧页 offset 带到新页、旧音频残留 → 不通过。
- **机检入口**：`test/parity-player.test.mjs` 的翻页/缩略图回归 + 人工试听。

### AC-P6（语速/静音不重置位置）

- **构造**：播放到 10s，切到 1.2×，再静音。
- **断言**：① `currentTime` 不回退；② 不重建音频；③ 继续后从 10s 之后接着播。
- **判定**：重播、回页首 → 不通过。
- **机检入口**：source 断言“播放 effect 不依赖 rate/muted 重建”；人工试听。

### 回归

- AC-107 连播过渡仍 5 秒；AC-108 页码续播仍成立；AC-109 无音频降级不变；AC-123 PDF 高亮不变；AC-142 缩略图“先停旧音频”不变；`playbackKey` 对配图变化不敏感仍成立；预加载下一页不变。
- `npm run test:v2` 全绿。

## 5. 实现记录（已完成）

- **client**：把“建源”和“播放/暂停”拆成两个 effect；暂停只 `audio.pause()`，继续只 `play()`；跨会话恢复在 `loadedmetadata` 后先 seek 再 `play()`；`handleBack` / `pagehide` / 5s 节流写位置；语速/静音只改属性；显式翻页走 `stopAudio()` + 新页 0。
- **修复（2026-11-10 真机复现）**：初始恢复时 `slides` 先到、`index` 下一帧才切到目标页；旧 index 的建源 effect 会先跑，把 `resumeRef` 当成“页不匹配”清掉，表现为**页对、秒丢**。现在 `resolvePendingResume` 在目标页仍存在时保留 pending，等目标页那一帧再恢复；新增“两帧 hydration”回归用例。
- **host**：`progress.js` 增加 `offset_ms` 与音频身份字段的读写、归一化与“换页归零/同页保留”规则；`api.js` 的 GET/POST 透出 `offsetMs` / `audioFile` / `audioMs` / `audioProvider`。
- **测试**：`test/parity-player.test.mjs` 补页内位置/时钟/续播裁决、两帧恢复与“暂停不重建音频”契约；`test/parity-settings.test.mjs` 补 offset + 音频身份往返、同页保留、换页清零。`npm run test:v2` 全绿。
- **已知限制**：同一系列多标签页同时播放时最后一次写入生效；浏览器朗读不保证秒级；显式翻页不保留旧页位置（D2=A）。
- **发布**：随包 `2.2.0`（tag `v2.2.0`，2026-11-10）发布；产品 `2.2`、schema `2` 不变。
- **估点**：约 1 人日（0.5 代码 + 0.5 测试/走查）。

## 6. 已确认的行为

1. 暂停/继续以**当前页音频的媒体时间**为单位；暂停后进度条不归零、时间显示停在原位，继续不从头。
2. 离开播放页、重启 DSH 后，回到**该讲该页该秒**；不自动播放。
3. 显式翻页/换讲从 0；回旧页也从 0（不保留每页历史）。
4. 文件音频才保证秒级续播；重新配音后音频身份不一致，旧位置失效；浏览器朗读按页重播并提示。
5. 语速/静音就地生效，不重置位置；本期不做拖动 seek。
