## 1. 背景

- 现状：设置 → 用量与费用 → 查看历史的每一行可点击，但点击后 `GET /usage/job` 的结果被写进单个 `detail`，渲染在整个列表之后，见 [client/index.js:6537–6712](../../client/index.js#L6537-L6712)、[详情块 6677–6710](../../client/index.js#L6677-L6710)。因此详情**永远固定在列表底部**，与所点条目脱节。
- 行本身是 `<button>`（[6638](../../client/index.js#L6638)），详情里又有「收起」按钮（[6686](../../client/index.js#L6686)）；详情不能直接塞进行内，否则是按钮嵌套按钮，必须改为「行容器 + 摘要按钮 + 详情区」。
- 当前没有同条切换、加载态、错误态；快速点 A→B 时，A 的响应可能后到并覆盖 B；`detail` 没有 `jobId` 绑定，无法校验明细归属。
- 切换类型筛选、刷新列表都不会清掉 `detail`，详情可能与当前列表对不上。
- 详情使用 `.blm-note`（[140](../../client/index.js#L140)），视觉上只是列表下方另一块提示，与概览行没有“属于同一条”的连接感。

## 2. 范围

**做**

1. 历史列表条目改为**行内展开**：详情紧贴被点条目的下沿，作为该条目的下一个兄弟节点；删除列表末尾的全局详情块。
2. **单开互斥**：同一时刻最多展开一条；点同条切换；点另一条收旧开新。
3. 收起入口：同条点击、面板内「收起」、`Esc`（焦点在条目内）、点列表/页面空白；点详情面板内部不收起；滚动不收起。
4. 详情面板与概览行明确分层：浅 accent 激活底、更深 tint、顶部分隔、左侧 accent 条、「明细」标题；浅色/暗色都可辨。
5. 加载态、行内错误与重试；请求序号/`jobId` 校验，迟到响应丢弃。
6. 筛选、刷新、清空的生命周期收敛；展开/收起不重新拉列表，只按需拉一条 `/usage/job`。
7. ARIA 与键盘：`aria-expanded`/`aria-controls`、`role=region`、焦点回归；320–1440px 响应式。

**不做**

1. 不改详情字段（时间、状态、billing、价格版本、逐模型明细、分阶段）；不新增/删除数据。
2. 不改 `host/*`、`host/api.js`、`index.js`、`usage/*` 与 schema=2；不新增接口。
3. 不做多开、URL 深链、展开状态持久化、展开高度动画、自动滚动、详情预取缓存。
4. 不顺手实现时间筛选与「其他」默认折叠（既有缺口，见 §11）。
5. 不改设置页「用量与费用」总览、价格表、作业卡「本次用量」摘要。

## 3. 交互规格

| 操作 | 结果 |
|---|---|
| 点收起状态的摘要行 | 展开该条，立即显示加载占位，再拉取 `/usage/job` |
| 点已展开的同一条摘要行 | 收起 |
| 点另一条摘要行 | 当前条收起，新条展开（单开互斥） |
| 点详情面板内部 | 不收起；允许选中、复制文字 |
| 点列表空白 / 页面空白 | 收起 |
| 点顶部工具栏（返回/刷新/筛选/清空） | 不按“外部点击”处理；筛选变化立即收起；清空成功后收起；刷新按下方规则 |
| `Esc`（焦点在条目内） | 收起，焦点回到该条摘要按钮 |
| 点面板内「收起」 | 收起，焦点回到摘要按钮 |
| 滚动 | 不收起 |

**状态与生命周期**

- 展开后立即渲染面板与「正在读取明细…」，固定最小高度约 44px，避免跳动；成功后替换为明细。
- 失败：面板内显示错误与「重试」，不弹全局 toast；重试成功后替换；错误文案说明“只影响明细，不影响列表”。
- 请求序号：每次打开/收起递增；只有当前序号且 `openJobId` 匹配的响应才允许写入；迟到响应丢弃。
- 筛选变化：立即收起，随后重拉列表；不保留已展开状态。
- 刷新：列表返回后，若 `openJobId` 仍在新列表，保持展开并重拉该条明细；否则收起。刷新失败保留现有列表与详情并提示。
- 清空成功：收起；清空失败或取消：保留当前展开状态。
- 离开历史页：组件卸载，展开状态自然丢失；不做持久化。
- 展开/收起不触发 `/usage/jobs` 或 `/usage/summary` 重拉，只按需请求 `GET /usage/job?jobId=`。

## 4. 视觉规格

- 行容器 `.blm-usage-item`：摘要按钮与详情面板同属一个容器，展开时形成一个连续卡片。
- 摘要行：沿用现有信息层级（类型 · 时间 · 书/系列 · 数量摘要 · 金额）；行尾增加 `▸/▾`（`aria-hidden`），展开时旋转 90°，120–160ms；`prefers-reduced-motion: reduce` 下取消旋转过渡。
- 展开态摘要行：浅 accent 激活底（约 3–5%），与详情面板上沿相连。
- 详情面板：更深一层 accent tint（约 6–8%）+ 1px 顶部分隔 + 2–3px 左侧 accent 条 + 「明细」小标题；圆角只在下沿；无阴影、无浮层、无嵌套卡片感。
- 暗色主题：使用 `color-mix(in oklab, ...)` 与现有 CSS 变量（`--blm-accent` / `--blm-card` / `--blm-line` / `--blm-text` / `--blm-dim`），不硬编码浅色。
- 文字：详情 11–12px，行高 1.5；标签用 `--blm-dim`，值用 `--blm-text`；长 `provider/model` 与金额允许换行（`overflow-wrap:anywhere`），不得横向撑破。
- 不自动滚动：被点行位置保持，详情自然向下展开；详情高于视口时由页面正常滚动。

## 5. 可访问性与 DOM

- 结构：`div.blm-usage-item` > `button.blm-usage-summary`（`aria-expanded` / `aria-controls`）+ `div#blm-usage-detail-<jobId>`（`role=region` / `aria-labelledby` / 收起时 `hidden`）。
- 不得把详情嵌进摘要 `<button>`；面板内的「重试」「收起」保持独立可聚焦。
- 收起时详情 `hidden`，不可 Tab；展开时 `Tab` 可进入面板控件。
- 加载态 `role=status`（`aria-live=polite`）；错误 `role=alert`。
- `Esc`/「收起」后焦点回到摘要按钮；点其他位置收起时不抢焦点。
- 摘要按钮保留可见焦点环；`aria-label` 由内容自然生成，不额外覆盖。
- 读屏语义：同一个条目展开时只改变 `aria-expanded`，不重建整页；`jobId` 不进入可见文案。

## 6. 数据与接口边界

- 只复用既有 `GET /usage/job?jobId=`；`/usage/jobs`、`/usage/summary`、价格表接口的调用时机不变。
- 不改 `usage/jobs/*.json` 字段，不改 `usageSchema`；不新增客户端持久化键。
- `host/*`、`host/api.js`、根 `index.js` 零 diff；数据 schema 仍为 `2`。
- 详情内容与 2.1 现有实现逐项一致；只改变承载位置、视觉与交互。

## 7. 验收

### AC-175（历史详情内联展开与开合矩阵）

- **构造**：造 3 条以上 `usage/jobs` 记录（至少含 `lecture` 与 `other` 两类）；进入设置 → 用量与费用 → 查看历史；依次点第 2、第 3、第 2 条；点列表空白；点工具栏「刷新」；按 `Esc`；点详情面板内部文字；用键盘 `Tab` → `Enter`/`Space`。
- **断言**：① 详情渲染在被点条目的下一个兄弟节点（间距 0），第 3 条被下推，不出现在列表末尾/固定底部；② 同一时刻最多一条展开；点同条收起；点第 3 条时第 2 条收起且第 3 条展开；点空白/`Esc`/「收起」收起；点面板内部不收起；滚动不收起；③ 展开只新增 `GET /usage/job?jobId=` 请求，不重拉 `/usage/jobs`；收起不发请求；④ 点工具栏按钮不因“外部点击”误收起；筛选变化/清空成功按 §3 生命周期收起；⑤ 详情字段与 2.1 现有实现一致。
- **判定**：详情仍在底部、可同时展开多条、点同条不收起、点面板内部误收起、展开触发列表重载 → 不通过。
- **机检入口**：`node test/v2-usage-ui.test.mjs`（SSR 渲染 `UsageRow` 收起/展开两态，断言详情为行内下一个兄弟节点、`aria-expanded`/`hidden`、无列表尾部详情节点；源码契约断言单开/切换/空白/Esc 处理）。
- **人工边界**：真机点击空白与滚动的手感；被点行是否跳动。

### AC-176（详情面板视觉分层与响应式）

- **构造**：浅色与暗色主题；展开一条含长 `provider/model` 的记录；窗口 320 / 768 / 1040 / 1440px；检查摘要行、详情面板与页面背景的计算样式。
- **断言**：① 详情面板背景与摘要行、页面背景可辨；有 1px 顶部分隔与 2–3px 左侧 accent 条；面板头有「明细」标识；② 展开的摘要行有浅激活底，与详情形成同一卡片；详情紧贴行下沿、无缝隙/重叠、仅下沿圆角；无阴影/浮层/嵌套卡片感；③ 暗色主题文字与强调色可读，样式使用 `color-mix`/CSS 变量而非硬编码浅色；④ 320px 无横向溢出，长 provider/model 与金额换行正常；⑤ 焦点环可见。
- **判定**：详情与概览行混为一体、看起来像浮层、出现横向滚动或暗色不可读 → 不通过。
- **机检入口**：`node test/v2-usage-ui.test.mjs`（详情/摘要 CSS 类、`color-mix`/变量、`border-top`、左侧 accent、下沿圆角、`[hidden]` 契约）；真机截图走查浅色/暗色与 320–1440px。
- **人工边界**：详情底色深浅是否“有区分但不抢眼”。

### AC-177（竞态、生命周期、可访问性与零后端变更）

- **构造**：让 `/usage/job` 响应按 A→B→C 逆序延迟；快速点 A、B、C；展开后切换类型筛选、点刷新、清空；注入 `/usage/job` 500；纯键盘操作；跑完整回归并看 `git diff --stat`。
- **断言**：① 只显示最后点击的 C 的明细，A/B 的迟到响应被丢弃；② 打开即出现加载态，失败在面板内显示错误与「重试」，重试成功替换；③ 筛选变化收起；刷新时条目仍在则保持展开并更新明细，否则收起；清空成功后收起；刷新失败保留现有列表/明细；④ 摘要 `aria-expanded` 与 `aria-controls`、详情 `role=region`/`hidden` 正确；`Esc`/「收起」焦点回摘要；加载 `role=status`、错误 `role=alert`；⑤ 无新增/修改接口、数据文件与字段，`host/*`、`host/api.js`、`index.js` 无 diff，schema 仍为 2；`npm run test:v2` 全绿。
- **判定**：看到错条明细、迟到响应覆盖、刷新后详情错位、键盘不可用、动到宿主/接口/数据 → 不通过。
- **机检入口**：`node test/v2-usage-ui.test.mjs`（SSR + 源码/CSS/ARIA 契约；竞态与生命周期用注入的延迟 Promise 或源码契约断言）；`npm run test:v2`；`git diff --stat` 人工确认。
- **人工边界**：快速连点的观感；错误文案是否说明“只影响明细、不影响列表”。

## 11. 既有缺口（不属 2.5.1）

- **时间筛选**：SRS FR-27.6 / §7.9 曾写“按 `kind`/时间筛选”，2.1 实现只有 `kind` 下拉，没有时间范围筛选。
- **「其他」默认折叠**：SRS 曾要求“其他默认折叠”，2.1 实现默认平铺全部记录；选中「其他」可单独查看，但没有默认折叠。

两项都会改变列表的信息架构与筛选逻辑，和本次“只改展开呈现”不是同一件事；本次不实现，建议单独开需求条目跟踪。2.5.1 只把 SRS 中这两处改为“已知缺口”措辞，避免继续把未实现写成已实现。

## 12. 实现记录（2026-11-11）

- **代码**：`UsageView` 的单个 `detail` 改为 `openJobId` + `detailState` + `detailSeqRef`；列表请求另加 `loadSeqRef`，避免快速切筛选时旧响应覆盖新列表。`UsageRow` 为纯组件，摘要 `<button>` 与详情 `role=region` 是兄弟节点；详情不再渲染在列表末尾。
- **交互**：同条点击收起、点其它条收旧开新；`Esc`/「收起」收起并把焦点还给摘要按钮；列表/页面空白点击收起；工具栏（返回/刷新/筛选/清空）与确认弹窗不触发外部收起；点面板内部不收起。
- **生命周期**：筛选变化立即收起；刷新时条目仍在列表则保持展开并重拉该条明细，否则收起；`/usage/jobs` 刷新失败保留现有列表/明细并提示；清空成功后收起。
- **竞态**：`detailSeqRef` 丢弃迟到明细响应；`loadSeqRef` 丢弃迟到的列表响应；加载态/错误态均在面板内呈现。
- **视觉**：展开行浅 accent 底；详情 7%（暗色 12%）accent tint + 1px 顶部分隔 + 3px 左侧 accent 条 + 「明细」标题；暗色主题走 `color-mix`，无硬编码浅色。
- **测试**：`node test/v2-usage-ui.test.mjs` 9 项全绿；`npm run test:v2` 43 文件 / 398 项（396 通过 / 2 跳过）全量通过（含 `release-version`、`parity-baseline`、`v2-usage`）。
