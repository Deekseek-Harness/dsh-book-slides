## 0. 一页结论

- ✅ **三部分正好是 PPTX 的三个独立部件**，不是三个视觉区块：
  - 演示页面 → `ppt/slides/slideN.xml`（文本框 / 形状 / 图片）
  - 声音媒体 → `ppt/media/audioN.wav` + 幻灯片里的 `a:audioFile` 媒体对象 + rels
  - 底部台词 → `ppt/notesSlides/notesSlideN.xml`（备注，不是幻灯片内容）

  这决定了三件事：能不能改字、能不能出声、观众看不看得到台词。
- ✅ **内容不需要重跑模型**：标题、要点、引文、配图、逐页 WAV、台词都在 `slides.json` 与模块目录里
  （`generate.js:797`、`tts.js:546`、`imaging.js:58`）。
- ⚠ **截图只证明结构，不证明样式。** 截图是毛笔手写标题 + 三张彩色虚线卡片 + `[AI生成]` 水印；
  插件现有舞台是米色底 + 宋体标题 + 要点列表 + 右侧配图位 + 右下页码（`client.js:211-237`）。
  按截图 1:1 复刻 = 新视觉设计 + 字体授权 + 可能要改内容结构；按现有舞台映射 = 零设计成本。
- ⚠ **「每页都有声音媒体」对已有模块不成立。** 只有生成时用了 Qwen 且合成成功才有 `audio/NNN.wav`；
  浏览器朗读与「关闭」都不落文件。截图里每页都有喇叭，但现实里整本可能一页都没有。
- ⚠ **「底部的台词」在 PPT 里默认是备注。** 放映时观众看不到；只有演讲者视图、打印「讲义」时才出现。
  如果目的是让读者看台词，就不是备注，而是页内文本或另一份讲义。
- ⚠ **给谁看决定兼容性边界。** PowerPoint（Win）、WPS、Mac PowerPoint、Keynote、Google Slides
  对嵌入音频的支持并不一样；Google Slides 尤其通常不保留导入的音频。
- 可以先用默认值冻结的：16:9、原生可编辑文本、单模块导出、有 WAV/MP3 才嵌音频、台词进备注、
  点击喇叭播放、浏览器下载、不要水印（§10）。

## 1. 需求重述

**FR-10.0（草案，待你确认）**

1. 在已生成的「精讲模块」上提供「导出 PPT」，一个模块产出一个 `.pptx`。
2. PPT 的页序与 `slide_index` 一致，页数等于模块页数（6–30），不增页、不合并。
3. 每一页包含：
   - **演示页面**：该页的标题、要点或引文、可选配图；
   - **声音媒体**：该页的朗读音频，作为页内可播放对象；
   - **台词**：该页的 `audio_script`，放在该页备注里（位置见 Q3）。
4. 导出是**只读**：不调 LLM、不重生成文案、不改 `slides.json` / `module.json`。
5. 既有导入、切章、生成、播放、书档、配图的行为与数据格式不变。

**「精讲」在这里指模块，不指整本书。** 若你要的是「整本书所有模块各出一份 PPT」，那是另一个范围
（§4 P1-1）。

## 2. 截图能证明什么、不能证明什么

| 截图里的东西 | 能推出 | 不能推出 |
|---|---|---|
| 红框圈住整块 16:9 画面 | 你要的是一页一页的幻灯片 | 页面比例是否必须 16:9；截图边缘被裁过，比例不精确 |
| 标题 + 三张虚线卡片（蓝 / 绿 / 红小标题） | 正文页需要「标题 + 若干分点」 | 是否必须复刻卡片样式；现有 `bullet_points` 是**扁平列表，没有卡片小标题**（`slides.js:371-389`），复刻要改数据结构 |
| 红圈里的喇叭图标 | 音频是**页内可见对象**，不是整段背景音乐 | 是点击播还是自动播；放映时是否隐藏；图标放哪 |
| 幻灯片下方独立的四行台词 | 台词与画面分离，最像 PPT 的备注栏 | 是不是备注；也可能是页面下方第二个文本框 |
| 右下 `[AI生成]` | 截图来自某个 AI 生成工具 | 我们是否也要水印 / 署名 |
| 毛笔手写字体 | 来源工具的模板字体 | 目标机器有没有这套字体；有没有商用授权 |

**结论：把截图当结构参考，不要当视觉验收基准。** 如果一定要它当视觉基准，需求要从「导出」升级为
「PPT 模板设计 + 内容结构改造」，工作量与风险都不是一个量级（§3 Q1）。

## 3. 三个根问题（P0）

> 下面 Q1–Q3 是三个根问题；另有 2 个跨切面问题（用途、兼容目标）在 §11，合起来是本轮的 5 个 P0。

### Q1 画面按哪套视觉？文字可编辑还是整页图片？

| 方案 | 做法 | 优点 | 代价 |
|---|---|---|---|
| **A. 复用现有舞台**（推荐） | 米色底、宋体标题、要点列表、右侧配图位、右下页码；PPT 里用原生文本框 / 形状复刻 | 与面板所见一致；零设计；文字可改、可搜索；体积小 | 和截图长得不一样；目标机缺 `Noto Serif SC` 时回落到宋体，版式会轻微走样 |
| B. 复刻截图 | 毛笔标题、彩色虚线卡片、彩色小标题；需要字体文件与授权 | 好看、像「成品」 | 字体授权 / 嵌入；卡片布局要处理 1–5 条要点；**卡片小标题在现有 schema 里不存在**，要改 prompt 并重新生成模块，旧模块无法复刻 |
| C. 新做 PPT 专用模板 | 投影优先：大字号、高对比、少装饰；与面板不同但受控 | 比 B 省，比 A 更适合讲台 | 需要一版设计稿与排版规则；仍是新工作 |

**可编辑性**（与视觉方案正交）：

| 方案 | 优点 | 缺点 |
|---|---|---|
| **原生文本 / 形状**（推荐） | 能改字、能搜索、体积小 | 跨机器字体缺失会变版；复杂卡片要靠多个形状拼 |
| 整页图片 | 100% 还原，不受字体影响 | 不能改字；30 页 PNG 体积大；备注与音频仍要单独加 |
| 混合（背景图 + 原生文字） | 折中 | 最复杂，先不做 |

**需要你定**：A / B / C？如果选 B，是否接受「旧模块导不出截图效果、要重生成」？

### Q2 音频从哪来？没有音频的页怎么办？怎么播？

**现状（这是需求里最容易落空的一条）**

| 生成时的语音选择 | `slides.json` | 有音频文件？ |
|---|---|---|
| Qwen 成功 | `audio_file: "audio/001.wav"`、`audio_provider: "qwen3-tts"` | 有 |
| Qwen 部分失败 | 失败页 `audio_file: null`、`audio_provider: "none"` | 部分有 |
| 浏览器朗读 | `audio_provider: "browser"`、`audio_file: null` | **没有** |
| 关闭 | `audio_provider: "none"` | **没有** |
| 旧模块 | 可能是 `audio/001.mp3` | 有 mp3（`index.js:1179` 兼容） |

所以「每页都有声音媒体」只能对「生成时用了 Qwen 且成功」的模块成立。**导出功能必须定义缺音频页的行为。**

| 子问题 | 选项 | 建议 |
|---|---|---|
| 缺音频页 | A 跳过该页、照常导出，结束时提示「12/18 页含音频」；B 阻断导出，先补配音；C 导出时现场调 Qwen 补齐 | **A**（只读、可预期）。C 要花钱、要 Key、要等，且会让「导出」变成「生成」；可作为后续可选功能 |
| 播放方式 | A 点击喇叭播放；B 进入页面自动播放；C 自动播放并自动翻页 | **A**。B 需要 `p:timing`，翻页快会叠音 / 截断；C 已经是视频，不是 PPT |
| 翻页时 | A 离开该页就停止；B 继续播到结束 | **A**。否则快速翻页会叠音；自动播放时更明显 |
| 喇叭图标 | A 页内可见、固定右下（或左下），放映时也可见；B 放映时隐藏、靠自动播放 | **A**，与截图一致，演讲者可控 |
| 音频格式 | A 原样嵌 WAV（示例 24kHz/16bit 单声道，约 48KB/s；实际以 Qwen 返回为准，30 页约 40–70MB）；B 转 MP3（约 1/10 体积，需编码器 / 新依赖） | **A**。先给体积预估；超过阈值提示 |
| 是否给开关 | A 默认含音频，可勾「不含音频」；B 总是含 | **A**，与书档导出一致 |

**额外风险**：Qwen 返回的字节是否真是 RIFF/WAV，目前只在播放器里按 MIME 播，没在导出前校验。
PPT 对扩展名敏感，一个「.wav 里装 MP3」的文件会让 PowerPoint 报无法播放。导出前应读文件头，
非 WAV 就按实际格式处理或跳过该页音频（详见 §8）。

### Q3 台词放备注还是页内？

| 方案 | 观众看得到？ | 适合 | 代价 |
|---|---|---|---|
| **A. 备注（`notesSlide`）**（推荐） | 放映时看不到；演讲者视图、打印讲义可见 | 讲课的人自己看词，观众看画面 | 备注不参与排版，不能做样式 |
| B. 页内文本框 | 看得到 | 发给别人自学、当讲义读 | 占版面，和「演示页面」重复；30 页都要排 |
| C. 两者都要 | 看得到 | 既要讲又要读 | 内容重复，排版翻倍；不建议 v1.5 做 |

补充：

- **内容**：只放 `audio_script` 原文，不加「第 N 页」前缀、不改写、不截断（截图就是整段台词）。
  是否在末尾附「原文 P152–153」一行，见 §4 P1-7。
- **所有页都放**：封面和引文页也有 `audio_script`（`validateSlides` 对每页都要求），保持一致。
- 如果目标是「读者自学时看台词」，备注不够——那应该考虑页内文本或另出讲义 PDF，这是另一个需求。

| 编号 | 问题 | 选项 | 建议 | 影响 |

| P1-5 | 配图 | `ready` 的页嵌图；缺图留白；或把 `image_prompt` 印在页上 | **嵌 ready；缺图时正文占满整宽，不留空图位**；不把提示词给观众 | 决定 PPT 看起来是否完整 |
| P1-6 | 封面 | 只放模块标题 / 加书名、作者、章节范围、生成日期 | **封面加「《书名》」小字，其余不加** | 分享出去时能认出是哪本书 |

## 5. 数据映射（建议）

| `slides.json` / 模块 | PPT 里落到哪 | 备注 |
|---|---|---|
| `book.title` + `module_title` | 文件名、封面小字 | 书名不进正文页 |
| `slide_index` | 页序、页脚「第 N 页」 | 不重排 |
| `layout` | `cover` / `content_text` / `quote` 三种版式 | 与面板一致 |
| `title` / `subtitle` | 标题 / 封面副标题 | 标题 ≤24 字、不换行 |
| `bullet_points` | 正文项目符号（1–5 条，每条 ≤40 字） | 现有数据是扁平列表，不做卡片小标题 |
| `quote_text` / `quote_source` | 引文页居中引文 + 出处 | ≤120 / ≤60 字 |
| `image_file` + `image_status` | 配图（仅 `ready` 且有文件）；无图时正文占满整宽 | `pending`/`failed`/`none` 都不留空图位 |
| `audio_file` / `audio_provider` / `audio_ms` | 页内音频对象 | 只认磁盘上真实存在的文件；兼容 `.mp3` |
| `audio_script` | 备注正文 | 逐字，不加前缀 |
| `source_pages` / `source_quote` | 默认不导出 | 需要时作为备注附加行（P1-7） |
| `image_prompt` | 默认不导出 | 避免把提示词给观众 |
| `source_anchor` / `anchor_status` / `model` / `voice` | 不导出 | 可写进 `docProps` 元数据，便于追溯 |

> 映射的原则：**PPT 是给人看的成品，不是数据备份。** 锚点、提示词、模型名这些内部字段留在 `slides.json`，
> 不进画面。导出物只带「观众需要看到的」和「演讲者需要听到 / 读到的」。

## 6. 建议的 MVP 边界

**做**：单模块、16:9、现有舞台视觉、原生可编辑文本、可选的配图、有 WAV/MP3 才嵌音频、
台词进备注、点击喇叭播放、流式下载、错误与降级、自动测试 + PowerPoint/WPS 真机验收。

**不做（v1.5）**：整本 / 多选批量、新视觉模板、字体嵌入、自动播放 / 自动翻页、MP4 / 视频、
PPT 导入或反向编辑、讲义 PDF、章节分隔页（会改变 1:1 页序）、`[AI生成]` 水印、Google Slides 兼容。

这张表是给你砍范围用的；如果其中哪条其实必须有，告诉我，它就会变成 P0。

## 8. 技术可行性（只做判断，不实施）

**三个 part 的难点不一样**：

1. **幻灯片文本**最容易：矩形 / 文本框 + 字号 / 颜色，`yazl` 直接写 XML。
2. **音频对象**中等：需要一个 `<p:pic>`，`<p:nvPr><a:audioFile r:link="rIdX"/></p:nvPr>`，
   rels 指向 `../media/audio1.wav`（关系类型 `.../audio`），`[Content_Types].xml` 注册 `wav`，
   再加一张喇叭 PNG 作为对象封面。点击播放不需要 timing；自动播放才要 `p:timing`。
3. **备注**中等偏繁：`notesSlide` 要配 `notesMaster`，否则有修复风险。
   这是手写 OOXML 的主要成本，不在文本排版。

**路线对比**：

| 路线 | 优点 | 缺点 |
|---|---|---|
| 手写 OOXML + 现有 `yazl` | 不新增依赖；沿用书档的流式导出与内存控制；完全可控 | notesMaster / 媒体关系要自己写；XML 错一处就「需要修复」 |
| `pptxgenjs` | `addNotes` / `addMedia` 现成；少踩 XML 坑 | 新增依赖；媒体自动播放能力弱；大文件在内存里拼，30 页音频要评估内存 |
| LibreOffice / soffice 转换 | 排版能力强 | 目标机不一定装；重依赖；与「零构建」冲突 → **不做** |

**建议**：先按「手写 + `yazl`」评估 1 天 spike，能稳定打开就继续；如果 notesMaster / 媒体关系卡住，
再引入 `pptxgenjs`。这个选择不影响需求，但要你先回答 P1-16。

**两个具体风险**：

- **WAV 真伪**：`wavDurationMs` 对非 RIFF 返回 0（`tts.js:255-275`），代码对读不出的头有兜底，
  但导出前仍应读一次文件头确认格式；非 WAV 的 `.wav` 要么按实际格式处理，要么跳过并提示。
- **Protected View**：浏览器下载的 pptx 在 Windows 上默认进「受保护的视图」，音频可能要先「启用编辑」。
  这不是 bug，但要在提示里写一句。
