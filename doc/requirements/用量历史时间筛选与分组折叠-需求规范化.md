## 1. 背景

- SRS v1.21 ~ v1.27 的 FR-27.6 / §7.9 要求历史页“按 `kind`/时间筛选；「其他」默认折叠”，AC-164 也断言“「其他」默认折叠”。
- 2.1 实现只做了 `kind` 下拉（[client/index.js](../../client/index.js) `UsageView`），时间控件缺失，「其他」随「全部类型」平铺。
- v1.28（2.5.1）把 FR-27.6 改为“按 `kind` 筛选”，并在 FR-27.6 / §7.9 / §12.14 / AC-164 / 测试表标注“既有缺口”，**没有补代码**。
- 2026-11-11 拍板：**恢复需求并落地**，同时修正历史时间的 UTC 显示与 `from`/`to` 的日界口径。

## 2. 决策（已冻结）

| 编号 | 决策 | 结果 |
|---|---|---|
| D1 | 需求状态 | **恢复**：时间筛选与「其他」折叠重新成为 FR-27.6 的正式要求；SRS 升 `v1.29`，新增 AC-178 / AC-179 |
| D2 | 时间筛选方案 | **A：日粒度预设**——全部时间 / 近 7 天 / 近 30 天 / 本月 / 自定义；自定义为起止两个日期；**最小粒度 1 天**，不做分钟/小时级；复用既有 `from`/`to`（ISO 日期），接口零变更 |
| D3 | 「其他」折叠形态 | **分组折叠**——「全部类型」下把 `kind='other'` 归入列表末尾独立分组，默认收起，组头显示「其他（N 条）」；类型选「其他」时平铺 |
| D4 | 相邻缺陷 | **同批修**：列表/详情的 `startedAt`/`finishedAt` 改本地时区显示；`from`/`to` 改按本地日比较，使「本月」与列表日界一致 |

## 3. 范围

**做**

1. 时间筛选：五个预设 + 自定义起止日期；默认「全部时间」；闭区间、单边可空、`from ≤ to`。
2. 请求口径：`/usage/jobs` 与 `/usage/summary` 使用同一 `from`/`to`（`YYYY-MM-DD`）；「本月」「累计」总览卡片保持原口径。
3. 「其他」分组：主列表（讲义/配音/配图）与「其他」分组分离；组头可展开/收起；组内仍支持行内明细。
4. 计数准确性：组头条数取同一时间范围、不带 `kind` 的 `/usage/summary.byKind` 的 `other` 合计，不受列表 500 条上限影响。
5. 生命周期：类型/时间变化收起已展开详情，并把「其他」分组重置为收起；折叠分组时若展开条目在组内，先收起详情。
6. 时间显示：列表与详情的起止时间按本地时区格式化到分钟（`YYYY-MM-DD HH:mm`）。
7. 日界：`host/usage.js` 的 `dayOf` 由 UTC 日改为本地日；`from`/`to` 按本地日闭区间比较。

**不做**

1. 不做分钟/小时级筛选、不做“近 1 分钟/近 1 小时”预设；不引入时间戳参数。
2. 不改 `/usage/*` 接口契约、`usage/*` 数据文件与字段、schema=2、`index.js`。
3. 不改总账/本月/累计/价格表/作业卡「本次用量」的口径；「其他」仍计入总账（Q34）。
4. 不做分组内分页、不做服务端分组、不做筛选条件持久化/URL 深链。
5. 不改行内展开的字段与视觉（AC-175 ~ AC-177 继续有效）。

## 4. 交互规格

### 4.1 时间筛选

| 选项 | `from` | `to` | 说明 |
|---|---|---|---|
| 全部时间（默认） | 空 | 空 | 不传参数 |
| 近 7 天 | 今天 − 6 天 | 今天 | 含今天共 7 个本地日 |
| 近 30 天 | 今天 − 29 天 | 今天 | 含今天共 30 个本地日 |
| 本月 | 本地月首日 | 今天 | 与「本月」金额卡片同界 |
| 自定义 | 用户输入 | 用户输入 | 两个 `<input type="date">`；任一边可空 |

- 预设区间在每次加载时按“现在”重算，跨零点刷新不会停留在旧范围。
- 自定义输入非法（非 `YYYY-MM-DD` 或 `from > to`）时：就地提示、**不发请求**、保留现有列表与详情。
- 时间或类型变化：立即收起已展开详情，并把「其他」重置为收起；随后按新条件重拉。

### 4.2 「其他」分组

| 类型筛选 | 列表形态 |
|---|---|
| 全部类型 | 讲义/配音/配图平铺；末尾「其他（N 条）」分组，默认收起 |
| 讲义 / 配音 / 配图 | 平铺；不显示「其他」分组 |
| 其他 | 平铺全部 `other` 记录；不显示分组头 |

- 组头：`<button>` + `aria-expanded` + `aria-controls`；`▸/▾` 指示，展开旋转 90°。
- 展开后按 `startedAt` 倒序显示组内记录（与主列表同序），行内明细行为不变。
- 收起分组时，若当前展开条目属于该组，先收起详情。
- 组内条数取 `byKind` 的 `other` 合计；若列表因 500 条上限被截断，组内提示「仅显示最近 N 条」。
- 总账、本月/累计金额与次数仍包含 `other`，不因折叠变化。

### 4.3 时间显示

- 列表摘要行：`formatUsageTime(startedAt)` → `YYYY-MM-DD HH:mm`（本地时区）。
- 详情：`formatUsageTime(startedAt) → formatUsageTime(finishedAt)`；空值显示 `—`。
- 不改变存储格式：账本仍是 ISO UTC。

## 5. 接口与数据口径

- `GET /usage/jobs?kind?&from?&to?&limit?&offset?` 与 `GET /usage/summary?from?&to?` 保持原签名；`from`/`to` 仍为 `YYYY-MM-DD`。
- 语义：闭区间，按**本地日**解释（用户系统时区；本机为 `Asia/Hong_Kong`）；非法/空值不报错，空值表示不设边界。
- 列表 `limit` 由客户端固定为 500（SRS 允许上限），避免分组计数与展示明显脱节；接口默认值仍为 50。
- 账本 `startedAt`/`finishedAt` 仍为 ISO UTC；只在展示层本地化。

## 6. 视觉

- 组头：虚线边框、透明底、dim 文字；悬停用 `--blm-btn-hover`；展开时 caret 旋转 90°；`prefers-reduced-motion` 下取消过渡。
- 组体：纵向 gap 6px，与主列表同宽；`[hidden]` 时 `display:none`。
- 日期输入：复用 `.blm-input`，宽度约 132px，窄屏随 `.blm-row` 自动换行；不引入新配色。
- 暗色主题沿用 `color-mix` / CSS 变量，不硬编码浅色。

## 8. 风险与边界

- **时区**：本地日语义依赖运行机器时区；桌面插件即用户本机，可接受。测试用“本地构造 → 本地断言”避免 CI 时区差异。
- **计数与截断**：组头条数来自 summary（准确），组内行数受 500 上限；截断时明示，不静默少显示。
- **筛选组合**：类型与时间叠加时，组头计数只用于「全部类型」；其它类型不显示组头，避免双重过滤歧义。
- **回归面**：AC-175 的展开生命周期新增“时间变化”与“分组折叠”两个收起入口；`test/v2-usage-ui.test.mjs` 中 `api('/usage/jobs?limit=100'` 的字面量断言需同步为结构化请求断言。
