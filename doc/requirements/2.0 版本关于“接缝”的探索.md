## 1 背景

### 1.1 现状

1. **书按“部分”组织，插件按“章”选择。** 实际教材中常有连续若干章讲同一主题（如“函数”7 章），而当前一次精讲最多勾 5 章、6 万字（[generate.js:49-50](dsh-book-slides/generate.js#L49-L50)、[generate.js:105](dsh-book-slides/generate.js#L105)）。超出后只能手动拆成两三次生成，得到若干互不相关的模块。
2. **单章体量超过单讲容量。** 技术书单章 5–8 万字并不少见，超过 6 万字即被选择上限拒绝，功能上表现为“不能精讲”。
3. **“部分”尚未成为插件实体。** 当前生成单元是“一次勾选的章集合”，随用随弃：没有名字、没有归属，也不与其它选择做冲突检查。目录里虽有 `level='part'` 条目（[index.js:964](dsh-book-slides/index.js#L964)），但那是书的排版结构，不能代替用户的意图（见 §2.6）。

### 1.2 问题陈述

两个现象指向同一件事：**限制的对象错了。**

- 单次模型调用的上下文早已由分块解决（单批 ≤1.2 万字，章内 ≤8 千字，[slides.js:23-24](dsh-book-slides/slides.js#L23-L24)），6 万字并非上下文上限。
- 6 万字实际是 **30 页 × 每页对应原文 2000 字** 的交付带宽（§2.3）。5 章上限是它的近似换算。
- 真正缺失的是 **“模块”之上的一层容器**，下文称 **部分（Part）**：当用户要覆盖一组章时，既不能一次勾选（超限），也不能拆开（拆完不连续）。

因此 2.0 的核心命题不是“怎么把长书塞给模型”，而是：**如何让 N 个独立生成的讲，读起来像同一个人备的一门课。**

### 1.3 目标与非目标

| 类别 | 内容 |
|---|---|
| 目标 | 一个部分（Part）可一次规划为 N 讲；Part 之间不共享章；讲间有可验证的衔接；单章超长时自动章内拆分而非报错；接缝失败不阻塞播放 |
| 非目标 | 不做整本书一次性生成；不做跨部分主线；不做“部分语义”推断（不判断这些章为何归为一组）；不做有声书的连续合成（讲间仍有边界）；**不兼容 1.x 且不与 1.x 并存**（新数据根、不迁移、无独立单讲，见 §6 D10/D14） |

## 2 概念模型

### 2.1 层级

```
部分 Part  →  讲 Lecture  →  批 Batch  →  页 Slide
（用户勾选）    （交付单元）     （调用单元）   （阅读单元）
```

- **讲**是用户感知的原子：听完可停、可续。
- **批**是模型的原子：一次调用只写一段，失败只重写这一段。
- **接缝**发生在讲与讲之间，但病根常埋在批与批之间和切点上。

### 2.2 名词表

| 术语 | 含义 | 现有实现对应物 | 备注 |
|---|---|---|---|
| 部分 Part | 用户人工勾选的一组原章节，插件不解释其语义；同一本书内 Part 两两无交集 | 无（2.0 新增 `parts.json`） | 单讲也是 Part；书中的“第 X 部分”仅作勾选便利（§2.6） |
| 讲 Lecture | 一次独立交付的精讲 | 2.0 中为 `series/<id>/lectures/<n>` | 不再是独立 module；必属系列（D10） |
| 批 Batch | 一次模型调用覆盖的原文块 | [planBatches](dsh-book-slides/slides.js#L196)：≤1.2 万字，章内 ≤8 千 | 已有检查点与断点续跑 |
| 页 Slide | 一页讲义 | `slides[]`，三种 layout | 字段上限见 §2.3 |
| 讲纲 Syllabus | 系列的单一事实源：主线、讲次、接缝句、术语、切点 | 无（2.0 新增） | 一次调用，全系列共享 |
| 章介绍 Brief | 每章 60–100 字的定位说明 | 无（可由节标题与首尾段生成） | 供讲纲判断切点 |
| 接缝句 Seam sentence | 相邻讲之间的一句过渡话，两处逐字复用 | 无（2.0 新增） | 一次生成、两处引用 |
| 预缝 Pre-stitch | 生成时即按接缝契约书写 | 无 | 不做事后补写 |
| 后验缝 Post-stitch | 生成后的机检与定点修复 | 部分（锚点修复为同类思想） | 先机检，后调模型 |
| 压缩率 ρ | 本页对应原文净字数 ÷ 本页讲义字数 | 隐含于 `CHARS_PER_SLIDE=2000`（[slides.js:44](dsh-book-slides/slides.js#L44)） | 见 §2.3；分子不是物理 PDF 页字数 |

### 2.3 压缩率 ρ 与讲容量

```
ρ（本页）= 本页对应原文净字数 ÷ 本页讲义字数
```

ρ 的分子是**本页对应原文净字数**：该页 `source_pages`（及 `source_anchor`）覆盖、并被本页实际讲解的原文段落净字数——去掉页眉页码与空白后计数，不等同于物理 PDF 页的整页字数。一页讲义可能对应半页、一页或多页原文；无锚点时以该页 `source_pages` 区间内的原文估算。

分母是**本页讲义字数**：标题 + 要点 + 引文 + 朗读稿（不含 `image_prompt` 与 `source_quote`，二者不面向读者）。按字段上限（[slides.js:32-41](dsh-book-slides/slides.js#L32-L41)）计算：

| 字段 | 上限 |
|---|---|
| `title` | 24 字 |
| `bullet_points` | 5 条 × 40 字 = 200 |
| `quote_text` + `quote_source` | 120 + 60 |
| `audio_script` | 40–220 字（所有页，cover 不豁免） |
| **合计** | **≈ 624，按 600 计** |

由此得到三档口径：

```
讲容量（设计值）   = 30 页 × 每页对应原文 2000 字 = 60000 字   （ρ = 3.3）
讲容量（工程上限） = 30 页 × 每页对应原文 2667 字 = 80000 字   （ρ = 4.4，30 页为硬顶）
理论警戒          = 30 页 × 每页对应原文 3600 字 = 108000 字  （ρ = 6，不建议逼近）
```

工程上限取 8 万字而非理论警戒的 10.8 万，原因有二：一页对应原文达 3600 字时，220 字朗读稿仅覆盖约 6%，已无法“讲解”；锚点修复只读取前 2 万字（[generate.js:60](dsh-book-slides/generate.js#L60)），越长越不可控。

例：一页对应原文 2000 字、讲义约 600 字，ρ≈3.3；同样 2000 字只写 200 字，ρ=10，属拒收。反之，原文 400 字、讲义 200 字时 ρ=2 看似正常，页面本身却信息量偏低——ρ 只约束比例，绝对信息量由字段下限（如 `audio_script` ≥40 字、要点 1–5 条）与页数预算共同保证。

ρ 的分级与动作：

| ρ | 判定 | 动作 |
|---|---|---|
| < 2.5 | 偏松 | 允许，提示可再压缩 |
| 2.5–4.5 | 健康 | 正常 |
| 4.5–8 | 警戒 | 记录 `density_warn`，界面提示“本讲偏摘要” |
| > 8 | 拒收 | 该讲必须再拆，或转“速览模式”并明示 |

**结论：现行 6 万字并非任意取值，它等于 30 页 × ρ=3.3。问题不在数值，而在超出后只能报错、不能拆讲。**

### 2.4 三阶段

```
[定部分] → [章介绍] → [讲纲] → [分配] → [逐讲生成·预缝] → [后验缝] → 系列就绪
   规划 Plan ─────────────────────┘        └── 生成 Draft ──┘   └─ 缝合 Stitch ─┘
```

- **规划阶段不写正文**，只产出结构与契约：讲纲、切点、接缝句、术语。成本低、可重跑、可人工修改。
- **生成阶段**每讲独立运行，沿用现有分批、检查点与幂等；差异是每讲多携带一段契约（§4.7）。
- **缝合阶段**先做机检（零模型成本），仅当机检不通过才定点调用模型，且优先只修衔接页。

### 2.5 接缝的五处与三态

| 接缝 | 位置 | 缝合者 |
|---|---|---|
| 播放缝 | 讲 N 播完 → 讲 N+1 第 1 页 | 播放器（连播） |
| 内容缝 | 讲 N 的落点 → 讲 N+1 的起点 | 讲纲（接缝句） |
| 切点缝 | 章与章、章内部的切分处 | 讲纲与规则（弧边界优先） |
| 批缝 | 同一讲内批与批之间 | 生成时的上下文注入 |
| 术语缝 | 同一概念在不同讲中的叫法 | 术语表（机检） |

接缝三态决定“部分可用”是否成立：

| 状态 | 含义 | 表现 |
|---|---|---|
| `unstitched` | 有讲但无接缝句（如讲纲失败后规则切分） | 连播可用，标注“本系列未做衔接” |
| `stitched` | 接缝句已注入并通过机检 | 正常 |
| `verified` | 机检与抽听均通过 | 正常，可导出 |

### 2.6 部分（Part）的定义

**定义。** Part 是用户人工勾选的一组原章节：`part = {id, title, chapters: number[]}`。章节取自本书 `chapters.json` 中的内容章（`front` 除外），勾选顺序无关，插件按章号升序使用。Part 标题只是用户标签，插件不据此推断内容。

**插件不解释语义。** 以下三件事明确不做：

1. 不判断“这些章为什么在一起”：它可能是教材的一个知识块，也可能是用户为某次分享随手挑的几章；
2. 不从书的“第 X 部分”、页眉或目录层级自动切出 Part：书的排版结构只是候选，不是事实；
3. 不因两章标题相似、术语重合而建议合并或拆分：语义判断一旦出错，会经讲纲放大到整个系列。

**唯一硬约束。** 同一本书内，任意两个 Part 的章集合两两不相交：

```
∀ i ≠ j:  parts[i].chapters ∩ parts[j].chapters = ∅
```

推论：

- **章的归属唯一。** 一章最多属于一个 Part；要换组，须先从原 Part 移出。
- **单讲也是 Part。** N=1 的生成同样登记为 Part（`chapters` 即本次勾选），只是不产生接缝；否则“讲”与“Part”的层级会含混。
- **Part 可编辑。** 可改名、可增删章；增删须重新执行不相交校验，并将该 Part 已生成的系列标记为“基于旧快照”（不自动重生成，D13）。
- **Part 可删除。** 删除只删分组，不自动删系列；系列保留章快照（§4.2）。
- **1.x 数据不进入 2.0。** 2.0 用独立数据根 `book-slides-2/`，不读、不迁移旧模块；不存在“旧模块回填 Part”（D10）。

**与书中“第 X 部分”的关系。** 目录中的 part 条目可作为“一键选中该组章”的便利入口，也可作为 Part 标题的默认建议；但它不构成 Part 的定义，插件不得据此自动合并或拆分用户的勾选。

**生命周期。** 创建（首次勾选生成）→ 编辑（改名、增删章）→ 删除。Part 持久化于 `books/<bookId>/parts.json`，与 `chapters.json` 同级；系列通过 `part_id` 引用，并保存创建时的章快照。

## 3 问题清单

| 编号 | 问题 | 根因 | 影响 | 现状证据 |
|---|---|---|---|---|
| P1 | 讲数不可预知 | 讲数由字数推导，界面只显示选中章数 | 用户无法预估时长与等待 | 面板仅有“预计 N 页”（[client.js:3442](dsh-book-slides/client.js#L3442)） |
| P2 | 切点语义信息不足 | 讲纲只能看标题与首尾段 | 切在论证中间，缝合无法弥补 | 首尾段多为过渡句 |
| P3 | 接缝句字数预算紧 | cover 仅 220 字，需容纳承接与导览 | 承接句易退化为套话 | [slides.js:38-39](dsh-book-slides/slides.js#L38-L39) |
| P4 | 讲纲与正文漂移 | 讲纲是计划，正文为另一次生成 | 讲纲声明不涉及的章被写入正文；术语两套写法 | 无约束机制 |
| P5 | 重规划级联 | 改一讲切点会牵动相邻讲的接缝、页码与页预算 | 改一处即整系列重生成 | 模块缓存键为章集合（[generate.js:119](dsh-book-slides/generate.js#L119)），无局部性 |
| P6 | 修复范围难定 | 无法判断应修一页、一讲或整系列 | 修轻无效，修重昂贵 | 现有粒度仅“批”与“整套”两档 |
| P7 | 系列状态缺语义 | 播放器、练习、导出均只认 module | 连播、系列进度、跨讲组卷、合并导出缺失 | 播完即停（[client.js:2131](dsh-book-slides/client.js#L2131)） |
| P8 | 用户手动切点 | 用户可能要求“切在第 3 章后” | 与自动切点冲突，易破坏不变式 | 无入口 |
| P9 | 单章节边界不可靠 | 只有章级正则（含 `节`，[text.js:21](dsh-book-slides/text.js#L21)），无“节”实体 | 章内只能按段落 8000 字硬切 | [splitLongText](dsh-book-slides/slides.js#L149) 按段落累计 |
| P10 | 成本与时延放大 | 新增 briefs、讲纲与多讲 | 7 章 8.4 万字约由 14 次调用增至 16 次 | 见 §4.14 |
| P11 | 老数据如何处置 | 1.x 模块、书档、缓存键都与 2.0 模型不同 | 若兼容则出现两套数据模型与两条播放路径 | 已决策：不兼容、不迁移（D10） |
| P12 | 质量不可观测 | 接缝质量无指标 | 优化缺少依据 | 无 |
| P13 | Part 相交无处理路径 | 无 Part 实体，选择集合随用随弃 | 同一章可能落入两个系列，练习、进度与导出出现归属歧义 | 现仅以章集合作缓存键（[generate.js:119](dsh-book-slides/generate.js#L119)），不校验归属 |

### 3.1 四个关键问题

**P2 切点：信息不足是结构性的。** 章标题只给名称，首尾段常为“本章小结”“下一章将……”一类过渡句，代表性有限。判断“第 4 章开头是否为转折”需要章的结构信息（节标题）。章介绍可补足，但其自身由模型生成，错误会向切点传播；因此须以原文首尾段交叉验证（§4.4）。

**P4 漂移：契约必须可机检。** 术语表与“已讲概念”均可断言，正文出现第二种写法即应被识别。仅“主线是否连贯”这类不可断言的项才交由模型或人工。原则：**能用字符串或集合判断的，不调用模型。**

**P5 级联：重规划必须可局部化。** 修改第 k 讲切点，理论上只影响 k−1、k、k+1 三讲的接缝、页码与页预算。算法因此需支持 `replanFrom(k)`：保留 1..k−1，仅重算 k..N。否则手动切点不可用。

**P13 归属：冲突必须显式选择。** 若勾选的章已属于另一个 Part，插件不得静默允许，也不得自动改归属；交互层应给出三选：并入已有 Part（本次生成成为该 Part 的新系列）、改选、或先把冲突章从原 Part 移出。判定只需集合运算，不调用模型。

## 4 算法设计

### 4.1 流程总览

| # | 步骤 | 输入 | 输出 | 调模型 | 失败降级 |
|---|---|---|---|---|---|
| 1 | 定部分（Part） | 用户勾选的章 + 已有 Part 列表 | `part{id, title, chapters[]}`，并完成不相交校验 | 否 | 冲突则要求用户选择（P13） |
| 2 | 章介绍（Briefs） | 章标题 + 节标题 + 首段 + 末段 | `briefs[{n, gist, sections[], role, turning}]` | 1 次（≤10 章） | 退回“标题 + 首尾段” |
| 3 | 讲纲（Plan） | briefs + 预算参数 | `plan{throughline, lectures[], seams[], terms[]}` | 1 次 | 规则切分（无 seam） |
| 4 | 分配与体检（Allocate） | plan + 字数 | `lectures[].pages`、ρ 预估、不变式校验 | 否 | 修正或触发重规划 |
| 5 | 开讲（Draft） | 每讲章集合 + 契约切片 | `series/<id>/lectures/<n>`（讲） | N × 批 | 单讲失败，系列 partial |
| 6 | 预缝（Pre-stitch） | seam 句与首末页约束 | 注入后的提示词 + 断言 | 0（复用 5） | 页级重试，退化为批级 |
| 7 | 后验缝（Post-stitch） | 系列成品 | 指标与修复动作 | 0 或 1 次 | 标 `unstitched`，不阻塞 |

```jsonc
      "sentence": "上一讲把函数当机器；这一讲只问一件事：输入靠近某点时，输出会去哪？" }
  ],
  "terms": [ { "name": "定义域", "forbid": ["定义区间"] } ]
}
```

### 4.3 不变式

以下条件全部可机检，建议直接落为单测：

| 编号 | 不变式 |
|---|---|
| I0 | Part 归属唯一：同一本书内任意两个 Part 的 `chapters` 交集为空（§2.6） |
| I1 | 讲覆盖完备且不重叠：`∪lectures[].chapters = series.chapters`（Part 章快照），相邻讲无交集 |
| I2 | 讲按章号升序；相邻两讲章不重叠；章号连续时页区间相接；切点落在页内时允许相邻讲共享该页（至多重一页） |
| I3 | 每讲章数 ∈ [1,6]（常态 3–5），页数 ∈ [6,30] |
| I4 | 每讲字数 ≤ `LECTURE_HARD_MAX`（8 万字），超出必须再拆 |
| I5 | 每对相邻讲有且仅有一条 seam，`seam.from=i`、`seam.to=i+1` |
| I6 | 接缝句两处复用：讲 i+1 的 cover `audio_script` 以其**逐字开头**；讲 i 末页 `audio_script` 以其**逐字结尾** |
| I7 | cover 必须存在且为第 1 页（沿用 `validateSlideSet`） |
| I8 | 术语：`terms[].forbid` 中的写法在系列内出现次数为 0 |
| I9 | ρ：每讲对应原文净字数 ÷ 该讲讲义字数 ∈ [2.5, 8]（越界只告警，不阻塞） |
| I10 | 讲数 N=1 时不产生 seam，但仍生成系列（单讲）；无独立模块路径 |

### 4.4 步骤 1–2：定部分与章介绍

**定部分。** Part 由用户勾选直接确定（§2.6），插件不做语义归并。生成前执行两步纯规则校验：

1. 集合校验：`chapters` 非空、无重复、均属本书内容章（`front` 除外），且不超过系列容量上限（8 讲 × 每讲 6 章 = 48 章，见 Q6）；
2. 不相交校验：与本书已有 Part 求交集；非空即冲突，交由交互层三选（并入 / 改选 / 移出），不得静默放行。

通过后登记 `part`（新建或复用），再以章号升序与字数汇总得到 `chars`；`range` 仅作包络推导，不要求章连续。标题默认按章号拼接（连续用 `–`，不连续用 `、`），用户可改。此步不调用模型。

**章介绍。** 用于给讲纲提供结构信息。方案取舍：

| 方案 | 信息量 | 成本 | 失真风险 | 可复用 |
|---|---|---|---|---|
| 仅首尾段 | 低：中段转折不可见，首尾多为过渡句 | 0 | 无 | 否 |
| 仅章介绍 | 高：含节标题、核心概念、前后关系 | 1 次 / ≤10 章 | 有：摘要错误传导至切点 | 是 |
| 章介绍 + 首尾段（采用） | 最高 | 1 次 | 可控（原文兜底） | 是 |

brief 结构：

```jsonc
{ "n": 6, "gist": "极限的 ε-δ 定义与几何直观",
  "sections": ["6.1 数列极限", "6.2 函数极限", "6.3 无穷小"],
  "role": "承接第 5 章的连续性讨论，为第 7 章的导数铺垫",
  "turning": true }   // 本章开头是否为转折点（切点候选）
}
```

约束：

1. `sections` 必须逐字取自该章原文中的行（机检：能在原文中检索到），防止模型编造小节；
2. `turning` 仅作参考，讲纲仍以首尾段原文交叉验证；
3. briefs 落盘为 `briefs.json`，可复用、可人工修改；修改后使下游 plan 缓存失效。

成本：7 章一次调用，输入约 4200 字（每章首尾各 300 字），输出约 500 字，耗时 2–5 秒。

### 4.5 步骤 3：讲纲

**输入**：书名、部分标题、briefs、预算参数（每讲页数上限 30、目标 ρ=3.3、章数区间 [2,6]）、用户偏好（期望讲数、指定切点）。

**输出 schema**（强约束，解析失败回灌重试一次）：

```jsonc
{
  "throughline": "一句话主线（≤40 字）",
  "lectures": [
    { "n": 1, "chapters": [4,5,6,7], "title": "函数：从映射到运算",
      "goal": "能判断一个对应是不是函数", "in": "读者已知集合与映射",
      "out": "会用定义域、值域、复合描述函数" }
  ],
  "seams": [
    { "from": 1, "to": 2, "concept": "极限",
      "sentence": "上一讲把函数当机器；这一讲只问：输入靠近某点时，输出会去哪？" }
  ],
  "terms": [ { "name": "定义域", "forbid": ["定义区间"] } ],
  "cut_notes": "第 4 章开头是转折，不宜在 3/4 之间切开"
}
```

**校验规则**（程序侧，不信任模型输出）：

1. 讲次连续、章覆盖等于部分章集合、无重叠（I1）；
2. 每讲章数 ∈ [1,6]，字数 ≤ 硬上限（I3/I4）；
3. seam 数 = N−1，字段齐全，`sentence` ≤ 60 字且含指代（弱检查）；
4. `terms[].name` 至少在一个 brief 或所在章标题中出现（防止术语凭空发明）；
5. 切点落在“同一主题相邻两章”之间时标记 `cut_warn`（允许但提示）。

**失败降级**：讲纲两次失败后退回规则切分（贪心装满 `LECTURE_MAX_CHARS`，不拆主题弧），系列置 `unstitched`，播放器仍可连播。不得因讲纲失败使整个系列不可用。

### 4.6 步骤 4：讲数与页预算

```
N       = max(1, ceil(totalChars / LECTURE_MAX_CHARS))   // LECTURE_MAX_CHARS = 60000
pages_i = clamp(round(chars_i / 2000), 6, 30)              // chars_i：该讲对应原文净字数；每讲 6–30 页
```

- 按 N 做贪心装章（每讲 ≤6 章、≤6 万字），再依据 `cut_notes` 与 `turning` 调整切点，且**只在章末移动，绝不在章内移动**。
- 单章超过 6 万字时章内拆分（§4.7），每段仍 ≤6 万字。
- 页预算按字数比例分配，不做平均：4.8 万字给 24 页，3.6 万字给 18 页。系列总页数可超过 30，因上限为每讲。
- 章不连续不影响装章与页预算：按章逐章求和，页区间取各章页区间的并集，包络中的空隙不计入。
- 体检项：`Σpages_i`、每讲 ρ 预估、每讲页数区间；不合格则要求重规划或调整页数。

### 4.7 步骤 5：开讲

沿用现有 `planBatches` 与 `generateBatch`，新增三处注入：

1. **契约切片**：本讲 `goal/in/out`、主线、相邻讲标题、已覆盖概念清单（前序讲的 `out` 与 terms），并声明“以下概念已讲过，用一句话唤起即可，不再重新定义”。
2. **批缝**：第 2 批起强制以一句承接开头（上一批末段要点，由上一批生成时回写）；原文 carry 由 300 字升级为“300 字原文 + 上一批标题与要点”。
3. **章内切分升级**（P9）：切点优先级为 `节标题 → 页边界 → 段落累计`。节标题为新增识别（`第X节`、`1.2`、`一、`、`【…】`），识别不到时退回现有 [splitLongText](dsh-book-slides/slides.js#L149)。

> 现状提示：章级正则将 `第X节` 也视为章头（[text.js:21](dsh-book-slides/text.js#L21)），但系统中不存在“节”这一层实体。节级切分需独立实现，不能复用章级正则。

### 4.8 步骤 6：预缝

注入点仅两处，且要求逐字：

| 位置 | 内容 | 约束 |
|---|---|---|
| 讲 i+1 第 1 页（cover）`audio_script` | `seam[i].sentence` 开头 + 本讲导览 | 总长 ≤220；导览 60–100 字 |
| 讲 i 末页 `audio_script` | 本讲小结 + `seam[i].sentence` 结尾 | 总长 ≤220；小结 60–100 字 |

不另设“视觉回顾页”的原因：30 页预算紧张，而 cover 本就必须有 `audio_script`（[validateSlides](dsh-book-slides/slides.js#L471) 对 cover 不豁免），可得 220 字承载。若确需视觉回顾页，应将 28 页正文 + 1 回顾 + 1 预告纳入预算，不得超页。

**断言**（生成后立即执行，零模型成本）：

```
cover.audio_script.trim().startsWith(seam.sentence)   // I6 前半
last.audio_script.trim().endsWith(seam.sentence)      // I6 后半
```

不通过时只重试该页（需新增页级修复能力；否则退化为批级修复）。

**约束与反模式**：

- 不得将上一讲全文注入提示词：成本高、干扰大，且易引发抄袭；
- 不得由相邻两讲各自生成回顾或预告：两次生成必然漂移，接缝句只能一次生成、两处复用；
- 不得在章内移动切点：切点仅在章末或节边界调整。

### 4.9 步骤 7：后验缝

**指标**（先机检，满足即不调模型）：

| 指标 | 算法 | 阈值 | 不通过处理 |
|---|---|---|---|
| 接缝句一致 | I6 字符串断言 | 100% | 页级重试 |
| 页序与章序 | I2 | 100% | 报告并禁止导出（或提示） |
| 重复率 | 讲 i+1 的 cover 导览与第 2 页要点，对比讲 i 末两页要点，逐条比对（归一化后相同或编辑距离 ≤2 视为同一条），重复条数 ÷ 本页要点数 | > 0.5 | 仅重生成衔接页 |
| 术语一致 | 全文扫描 `terms[].forbid` | 必须为 0 | 定点修改该讲或标警告 |
| 密度 ρ | 逐页核算：本页对应原文净字数（`source_pages` / `source_anchor`）÷ 本页讲义字数 | 2.5–8 | 标 `density_warn` |
| 覆盖 | 每讲 `source_pages` 落在所分配章的页区间内（章不连续时逐章判断） | 100% | 走锚点修复流程 |

**修复粒度矩阵**：

| 问题 | 最小修复单元 | 成本 |
|---|---|---|
| 接缝句不一致 | 1 页 | 1 次页级重试 |
| 重复或术语漂移 | 1 页或 1 讲 | 1 次小调用，或整讲重跑 |
| 切点错误（弧被切断） | 相邻 2 讲 | `replanFrom(k)` |
| 讲纲整体错误（主线错） | 整个系列 | 全量重规划，需用户确认 |

### 4.10 局部重规划

```
replanFrom(k):
  保留 lectures[1..k-1]（讲不变）
  重算 chapters[k..N] 的装章与页预算
  重建 seam[k-1] 与 k..N 的 seams
  仅使 lecture[k..N] 的缓存失效
```

影响面限定在 `k−1 .. N`。缺少该能力时，用户每改一次切点都需整系列重跑，手动切点等同于不可用。

### 4.11 状态机与幂等

- 系列状态：`planned → drafting → stitching → ready | partial | failed | cancelled`；每讲状态沿用同一套阶段名。
- 断点：从 `series.json` 读取已完成讲并跳过；讲内断点沿用 `batches/` 检查点。
- 缓存键分两级：
  - `seriesKey = sha256(series.chapters（Part 快照） | briefs 摘要 | 讲纲版本 | 模型 | prompt 版本)`
  - `lectureKey = sha256(seriesKey | lecture.chapters | plan 切片 | 页预算)`
  - 讲纲变更 → `seriesKey` 变化 → 全系列失效（需确认）；局部变更仅 `lectureKey` 变化。
- **不兼容（P11）**：2.0 只读 `book-slides-2/`，不解析 1.x 数据；无独立单讲，N=1 也生成系列。

### 4.12 失败与降级链

| 失败点 | 降级 | 用户可见结果 |
|---|---|---|
| briefs 失败 | 使用标题与首尾段 | 无感 |
| 讲纲两次失败 | 规则切分，无 seam | 标注“本系列未做衔接” |
| 某讲生成失败 | 系列 `partial` | 其余讲可听，失败讲可重试 |
| 预缝断言失败 | 页级重试 → 批级修复 → 标 `unstitched` | 不影响播放 |
| 后验缝不通过 | 记录指标，停留 `stitched` 不升 `verified` | 导出时提示 |

**总原则：接缝是最软的一层，任何接缝失败都不应导致“无法收听”。**

### 4.13 示例：某教材“函数”部分

7 章共 8.4 万字（用户勾选第 4–10 章构成一个 Part），讲纲输出 2 讲（5 章 + 2 章），页预算 30 + 12 = 42 页，一条接缝句：

> 上一讲把函数当机器；这一讲只问一件事：输入靠近某点时，输出会去哪？

该句同时作为第 1 讲末页朗读稿结尾与第 2 讲 cover 朗读稿开头。连续播放时，听感为“接着讲”而非“另起一讲”。

### 4.14 成本与耗时

以 7 章、8.4 万字、按每批约 1.2 万字估算（单章超过 1.2 万字即被切成两批，故约 14 批）：

| 项 | 次数 | 说明 |
|---|---|---|
| briefs | 1 | 2–5 秒 |
| 讲纲 | 1 | 10–20 秒（输出约 800 字） |
| 开讲 | 约 14 批 | 每批 30–90 秒，合计 7–21 分钟 |
| 预缝 | 0 | 复用开讲 |
| 后验缝 | 0–1 | 机检通常足够 |
| **合计** | **约 16 次调用** | 现状手拼两个模块约 14 次，增量为 briefs 与讲纲 |

时延主要来自开讲与 TTS，不在规划阶段。

### 4.15 可测性

以下函数不依赖文件系统与 HTTP，与 `slides.js` 现有定位一致，可直接以 `node test/xxx.mjs` 运行：

| 函数 | 职责 | 关键用例 |
|---|---|---|
| `validatePart(chapters, existingParts)` | Part 集合校验与不相交检查 | 空集、重复章、含 `front` 章、与已有 Part 相交 |
| `partTitleOf(chapters)` | 默认标题（连续 `–`、不连续 `、`） | 单章、连续 3 章、1/3/5 三章 |
| `planLectures(part, briefs, opts)` | 装章、定讲数、定切点 | 弧不拆、单章超长、章数不足 3、N=1 |
| `allocatePages(lectures)` | 页预算与 ρ 预估 | 总页数超过 30、单讲不足 6 页 |
| `parsePlan` | 讲纲契约解析与校验 | 坏 JSON、seam 数不符、术语凭空发明 |
| `assertSeams(lectures, plan)` | I6 断言 | 逐字首尾、标点差异 |
| `gradeDensity(lecture)` | ρ 分级 | 四档边界（§2.3） |
| `pickRepairTargets(metrics)` | 修复粒度决策 | 一页、一讲、相邻两讲 |
| `replanFrom(plan, k)` | 局部重规划 | 保留前 k−1、seam 重建 |

## 5 与 1.x 的差异（不兼容）

| 维度 | 1.x 现状 | 2.0 设计 |
|---|---|---|
| 选择单元 | 用户勾选即一个模块，1–5 章 | Part = 人工勾选的章集合，可任意章数，自动拆为 N 讲 |
| Part 实体 | 无，选择随用随弃 | `parts.json`，章归属唯一，Part 之间不相交 |
| 容量上限 | 5 章 / 6 万字，超出报错 | 单讲 6 万字（工程上限 8 万），超出自动拆讲 |
| 跨讲一致性 | 无 | 讲纲 + 接缝句 + 术语表 |
| 页数约束 | 模块 6–30 页 | 每讲 6–30 页，系列可超过 30 |
| 章内切分 | 段落累计 8000 字 | 节标题 → 页边界 → 段落累计 |
| 修复粒度 | 批、整套 | 增加页级 |
| 播放 | 播完即停 | 系列连播与系列进度 |
| 缓存键 | 章集合 | `seriesKey` + `lectureKey` |
| 旧数据 | 可读 | **不兼容**：新数据根，需重新导入 |
| 发布 | 独立包 | 同包名 2.0.0 覆盖安装，不与 1.x 并存 |

## 6 决策记录

| 编号 | 决策 | 理由 | 影响 |
|---|---|---|---|
| D1 | 交付单元为“讲”，每讲 ≤6 万字（工程 8 万）、6–30 页 | 由 ρ=3.3 与页数上限推导 | 取代 5 章 / 6 万字的硬拒绝 |
| D2 | 接缝句一次生成、两处逐字复用 | 两次独立生成必然漂移 | 需要页级修复能力 |
| D3 | 讲纲为系列单一事实源 | 保证主线、术语、切点一致 | 增加 1 次调用 |
| D4 | 切点优先弧边界，章内优先节边界 | 切在语义停顿处，缝的需求最小 | 需新增节级识别 |
| D5 | 章介绍由 brief 提供，原文首尾段兜底 | 兼顾结构信息与事实准确性 | 增加 1 次调用 |
| D6 | 接缝三态，失败不阻塞播放 | 播放可用性优先 | 界面需展示 `unstitched` |
| D7 | N=1 也生成系列（单讲），无独立模块路径 | 单一数据模型，少一条分支 | 系列目录在 N=1 时隐藏 |
| D8 | 支持 `replanFrom(k)` 局部重规划 | 级联成本不可接受 | 缓存键需分两级 |
| D9 | 后验缝先机检，模型仅在不过时介入 | 成本与确定性 | 需定义可机检指标 |
| D10 | **不做 1.x 兼容**：新数据根 `book-slides-2/`、不迁移、不读旧模块 | 双模型/双路径成本高于一次重导 | 老用户需重新导入 PDF |
| D11 | Part 由用户声明，插件不解释语义 | 语义推断不可靠，且错误会经讲纲放大 | 需 Part 归属与冲突检查 |
| D12 | Part 之间章集合两两不交；单讲亦登记为 Part | 同章落入两个系列会造成练习、进度与导出的归属歧义 | 冲突时须交互选择（P13） |
| D13 | 系列保存创建时的 Part 章快照 | Part 后续变更不得静默改动已生成内容 | 变更后提示“基于旧快照” |
| D14 | **不与 1.x 并存**：同包名 `dsh-book-slides`、版本 2.0.0、同插件 id，覆盖安装 | 并存要维护两套路由、两块面板、两份数据根 | 插件列表只有一个「精讲」；回滚需重装 1.x |
