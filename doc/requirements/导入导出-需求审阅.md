## 0. 一页结论

- ✅ **三句话正好是三层状态**：书 →（章节 + 原文）→ 模块 → 音频。每一层都有明确落盘文件，没有一层需要新造数据。这是这个需求能被低成本实现的根本原因。
- ⚠ **它现在还不能验收**：没说「在」的最低标准。补一张 MUST / SHOULD / MUST NOT 表（§2.2），每条挂一个 AC，需求才算闭合。
- ⚠ **三个「在但不对」的坑**：`pages.json` 若用本机 pdf.js 重抽 → 锚点全部错位；只带 `slides.json` 不带 `module.json` → 模块在面板里根本不显示；缺音频时把 `audio_provider` 清空 → 浏览器用另一个声音顶上，违反 D21。
- ⚠ **「重新导入」隐含一条硬约束**：导入过程**不得调用 LLM 与 TTS**。否则「还能听」= 再花一次钱、结果还不确定，且目标机可能没网没 Key。
- ✅ **容器**：撤掉「一本书一个 ZIP」的预设后，这个问题不再需要争论——只剩统一容器一个合理答案（D23），单本导出就是「容器里只有一本」。
- 仍需你拍板：音频默认、冲突默认、缺 PDF、批量上限（§12，都有默认值，回「按默认」即可）。

## 1. 需求重述与这一版的变化

### 1.1 规范化后的需求

**FR-9.0（新增，不改 FR-1～FR-8）**

1. **导出**：把一本书的全部「可再生状态」写成一个**自包含**包——包内不含本机独有的东西（配置、缓存、播放位置），也不依赖目标机已有任何数据。
2. **导入**：在**另一个数据根**还原到「能打开、能勾章、能进播放器、有音频就出声」。
3. **批量**：N 本一次导出、一次导入，且单本失败不拖垮整批。
4. **不变**：既有导入 PDF、书架、解析、生成、播放、设置的行为与数据格式不变。

### 1.2 与 v0.1 的差异

| 项 | v0.1 | 本稿 | 影响 |
|---|---|---|---|
| 打包单位 | 你指定「一本书一个 ZIP」 | 你只给目标 | 容器从「说服」变成「推导」；结论仍是统一容器，但理由换成「只有一条代码路径」 |
| 验收 | 由我代拟 AC | 你给了三句人话 | **必须先定义「在」**，否则 AC 写不出来（§2） |
| 音频 | 我建议「默认包含」 | 「点开还能听」把它变成**验收项** | 默认值从「讨论」变成「必须包含」，除非同时提供「仅补配音」 |
| 「导出」的歧义 | 未提 | 「重新导入后」四个字排除了成品导出 | SRS 的 Q4（HTML/PPT 成品）仍是非目标，本稿明确写死 |

> 顺带说：这一版把「一本书一个 ZIP」拿掉是对的。它原本是个**实现细节**，写进需求会逼着后面所有批量逻辑围着它转。目标留下来，实现细节交给我推导，这是需求文档该有的分工。

## 2. 把「书还在、模块还在、点开还能听」变成可测

### 2.1 三层不变量

| 层 | 断言 | 依赖落盘 | 不成立时的表现 |
|---|---|---|---|
| **L1 书在** | 书架出现 1 本，书名/作者/页数/章数一致；能进详情；章节可勾选；左窗格能渲染原文 | `book.json` + `chapters.json` + `pages.json` + `source.pdf` | 书不见了，或书在但章节是空的/错的 |
| **L2 模块在** | 模块列表出现 N 个，标题/章号/页数/状态可读；能进播放器 | `module.json` + `slides.json` | 模块目录躺在磁盘上，但面板里一个都没有 |
| **L3 点开还能听** | 每页有 `audio_file` 的 `/audio` 返回 200 且字节一致；无音频页显示「本页无配音」且**不换声** | `audio/NNN.wav` + `slides.audio_file/audio_provider/audio_ms` | 能出声，但不是原来那个声音；或每页都 404 |

### 2.2 保真清单（这是本稿的核心）

**MUST：缺任意一项，导入即失败（整本拒绝）**

| 项 | 判据 |
|---|---|
| `book.json` | 字段齐全（`title/author/pages/chars/chapterCount/sha256/schemaVersion`），`sha256` 与 PDF 实际哈希一致 |
| `source.pdf` | 字节一致；大小与 manifest 一致 |
| `pages.json` | **字节一致**。它是 `source_anchor.para_index` 的坐标基准，重抽必漂 |
| `chapters.json` | 全字段保留：`n/title/from/to/chars/manual/hidden/front/verified/source`。`manual:true` 是用户的手工成果，丢了等于白改 |
| `modules/<id>/module.json` | `id/bookId/chapters/chapterTitles/status/model/promptVersion/voice/createdAt`。**没它模块在面板里不存在**（§2.3-②） |
| `modules/<id>/slides.json` | **字节一致**。含 `source_anchor`、`audio_ms`、`audio_file`，任一处重算都会让播放器行为变化 |
| `audio/<seq>.wav` | 与 `slides.audio_file` **一一对应、文件名不改、序号不重排**；字节一致 |
| `manifest.json` | `formatVersion`、每文件 `sha256`、每模块 `contentKey` |

**SHOULD：缺了要降级并提示，不算失败**

| 项 | 缺了会怎样 |
|---|---|
| `toc.json` | 阅读与播放不受影响；「重新解析目录」要重花一次 token，用户填的范围也丢 |
| `README.txt` | 只是给人看的说明 |
| `book.lastOpenedAt` | 由导入时间重算（D32），原值记在 manifest |
| `module.anchorHitRate / code / error` | 只影响诊断与提示，不影响播放 |

**MUST NOT：出现即拒绝整包**

| 项 | 理由 |
|---|---|
| `voice.json` / 任何 `apiKey` 字段 | 明文 Qwen Key 不能进一个会被复制、上传、发同事的文件 |
| `audio-cache/` | 去重缓存，体积可能超过书本身；导入后由本机重新积累 |
| `trash/` | 回收站不是书 |
| `modules/*/batches/*.json` | 生成检查点，中间态；重试时才有意义（丢了只是重试要重花模型调用） |
| `preference.json` / `progress.json` | 本机偏好与播放位置，不随书走 |
| 绝对路径 / `..` / 符号链接 / 盘符 / UNC | 安全边界，见 D29 |

> 封面是**算出来的**（`cover.js:coverSvg`，按书名哈希取色），摘要也是勾选时算的——这两样**不进包**。能把「不必带的东西」列清楚，包才小得下来。

### 2.3 三个「看起来在、其实不在」的反例

这四条不是假想，是对着现有代码点出来的。每一条都要变成一条 AC。

**① 书在，但锚点全错**
导入时若「顺手」用本机 pdf.js 重抽 `pages.json`：pdf.js 版本不同 → 分页/分段碎片不同 → `para_index` 指向错段 → 播放器高亮到别处，甚至整页无高亮。原文还在，锚定没了。
→ 规则：`pages.json` 只搬运，不重算（D24）。

**② 文件在，但模块不在**
`listModules()`（`generate.js:219`）扫 `modules/` 下的目录，逐个读 `module.json`，读不到就跳过。所以包里若为了「轻一点」只带 `slides.json`，导入后模块列表是空的——文件明明在，面板里就是没有。
→ 规则：`module.json` 与 `slides.json` 必须成对出现（D24）。

**③ 能出声，但不是原来的声音**
`client.js:1676` 的判定是：`(audio_provider === 'browser' || !audio_provider) && audio_script && 浏览器支持朗读` 才走浏览器合成。所以只要缺音频时把 `audio_provider` 清成空（或删字段），播放器就会用系统语音顶上——用户听到的不是 Qwen 那个音色，而且他不知道为什么。
→ 规则：缺音频时归一为 `audio_file = null` + `audio_provider = 'none'`，**恰恰不能清空**（D30）。

**④ 能听，但要再花一次钱**
若导入时「顺便把没音频的页补配音」：成本不可控、结果不确定（模型/音色可能已变）、目标机可能没 Key 没网，而且违背「导入是还原，不是再生成」。
→ 规则：导入全程零模型、零 TTS 调用（§2.4）。

### 2.4 导入的「零生成」约束

| 约束 | 判据 |
|---|---|
| 不调用 `ctx.llm` | mock 计数 = 0 |
| 不请求千问 | mock/日志计数 = 0 |
| 不重新解析 PDF | 不读 `source.pdf` 正文（只算哈希） |
| 不「顺手补配音/补目录」 | 缺什么就降级什么，交给用户显式点「重试 / 仅补配音 / 重新解析」 |

理由：确定性（同样的包导入两次结果一样）、成本、离线可用。这条约束也让批量导入的耗时只与磁盘有关，不会因为某本书目录缺失而卡住 90 秒。

## 4. 决策（接 D22）

### D23 容器：统一容器，单本 = 容器里只有一本

撤掉「一本书一个 ZIP」的预设后，这个决定只剩一个答案：

- **一个包** = `manifest.json` + `books/<bookId>/…`；`books[]` 长度 1..N。
- 单本导出：`books[]` 长度 1。多本导出：同一个包，`books[]` 长度 N。
- 读写**只有一条代码路径**；批量导入天然原子（要么整包校验完，要么整包不动）。

作废的备选：严格「一本一包」——批量导出只能连点 N 次下载（浏览器会拦多文件下载）或用 `showDirectoryPicker` 写目录，两者都比一个包更难做、更难测。整库快照——会带出 Key、缓存、回收站，见 §2.2 MUST NOT。

### D24 内容边界：白名单，不是黑名单

按 §2.2 的 MUST / SHOULD / MUST NOT 三张表实现。导出前**显式断言包内不含 `voice.json`**；导入时遇到白名单外的条目一律忽略并计入 `skippedFiles`（不报错，方便未来加字段）。

**音频默认包含**，理由有三，缺一不可：
1. 「点开还能听」是验收项，不是加分项。
2. 播放 WAV **不需要 Key、不需要网络**（`/audio` 只读文件），所以带音频的包在目标机一定能听。
3. 现有实现里没有便宜的补音频路径：`/generate` 命中 `moduleCacheKey` 直接返回旧模块、不重跑 `voicing`；`force` 会把 LLM 一起重跑。所以「不带音频」必须配一个「仅补配音」按钮（FR-9.7），否则等于把模块做成静音。

### D25 身份：`sha256` 是书的身份，`contentKey` 是模块的身份

| 对象 | 跨机稳定身份 | 本地别名 |
|---|---|---|
| 书 | `book.json.sha256` | `bookId` |
| 模块 | `contentKey = sha256(canonicalJson({chapters, promptVersion, slides 去标识字段}))` | `moduleId` |

- 去重、合并、判「已存在」**一律用稳定身份**，不用 `bookId/moduleId`。
- `contentKey` 去掉的字段：`module_id / book_id / generated_at / audio_file / audio_ms / audio_provider / voice.*`——同一套幻灯片换个音色、换台机器，仍是同一个模块。
- 与既有 `moduleCacheKey`（`generate.js:118`，含 `bookId`）分工：`cacheKey` 管**本机生成幂等**，导入时按目标 `bookId` 重算；`contentKey` 管**跨机内容身份**。两者不混用。
- `bookId` 处理：**目标机空闲则沿用**（模块内引用零改写）；**被另一本不同 sha256 的书占用则整本拒绝**（`E_PKG_ID_CONFLICT`）。不做「重铸 ID + 全量改写引用」——v1 不值得为 10⁻¹² 量级的碰撞引入改写风险。

### D26 冲突策略：默认「合并补模块」，不做覆盖

| 目标机状态 | 包内情况 | 默认动作 | 结果 |
|---|---|---|---|
| 无同 sha256 | 任意 | 新书入库 | `imported` |
| 有同 sha256，0 模块 | 有模块 | 只补模块 | `merged` |
| 有同 sha256，已有同 `contentKey` | 同内容模块 | 跳过该模块 | `merged`，`moduleExists++` |
| 有同 sha256，章节被手改/重切 | 模块的 `chapterTitles` 与本地 `chapters[n]` 对不上 | **该模块不导入**（`orphan`），书不报错 | `merged`，列出无法对应的模块 |
| `bookId` 被另一本书占用 | — | 整本拒绝 | `failed: E_PKG_ID_CONFLICT` |
| 同批两个包含同一 sha256 | — | 前者入库，后者按「已有同 sha256」处理 | `merged` |

**合并只补模块，绝不改** `book.json`（书名/手改）、`chapters.json`、`toc.json`、`pages.json`、`source.pdf`。理由：本地章节是本地模块锚点与章节号的基准，覆盖会让本地已有模块整体错位。要「完整还原包里那套章节」就选 `copy`（另存副本，两套并存）——这是 `copy` 唯一的存在理由。

策略：`merge`（默认）/ `skip` / `copy`。**不提供 `replace`**。

### D27 批量：失败隔离，结果逐项可见

- **导出**：勾 N 本 → 一个包；任一本不存在或正在生成 → 整包拒绝并指出是哪本（导出是纯读，失败就该整包不产，避免「半个库」）。
- **导入**：包内 N 本**逐本判定**；一本失败不影响同包其它本，也不影响同批其它包。
- **响应**：HTTP 200 + `{ok, items[], summary}`；`ok = failed === 0`。前端按 `items` 展示，不靠单个错误码猜。
- **上限**：单批 ≤ 10 本、单包 ≤ 4 GiB。超限在开始传输前拦。

### D28 传输：流式，不落临时 ZIP，不整包进内存

| 项 | 决策 | 理由 |
|---|---|---|
| 导出 | `GET /export` 直接流式写响应，**不生成临时 ZIP** | 4 GB 包落盘再读一遍 = 双倍磁盘 + 双倍时间 |
| 导入 | `POST /import/package`，沿用现有约定（**裸二进制 + `x-file-name`**），流式落 `.import/<id>/pkg.zip` 再解压 | 复用现有 200 MB 上传约定，不引入 multipart；`readBody()` 不复用 |
| 压缩 | `.pdf` / `.wav` 用 store；`.json` / `.txt` 用 deflate | 前者已压缩，deflate 只烧 CPU |
| 体积 | 单包 ≤ 4 GiB；单本 ≥ 1 GiB 给黄条 | 见 §8：全量最坏 4.7 GB |
| 预估 | `GET /export/size` 只 `stat` 求和，不读内容 | 点之前就要看到「约 1.2 GB」 |
| 进度/取消 | 导出用浏览器原生下载；导入用 XHR `upload.onprogress` + 「正在校验第 k 本」；取消即清 `.import/` | v1 不引入作业状态机 |

> 实现期确认项：若 DSH `webServer` 对单请求有硬超时，则把「解压 + 校验」改为作业轮询（复用 `generate.js` 的 job 形态），上传段不变。

### D29 原子性、校验与安全

导入顺序（逐本 fail-fast）：容器 → 路径 → manifest → 每本 JSON → PDF 哈希 → JSON 哈希 → 冲突 → 落盘。

- **路径**：只接受 `/` 分隔相对路径；无 `..`、无盘符、无 UNC、无符号链接；`resolve` 后必须以 staging 为前缀。
- **条目**：≤ 10 000 条、单条名 ≤ 200 字节、声明解压总量 ≤ 8 GiB、压缩比 > 100 拒绝（炸弹）。
- **校验**：`source.pdf` 的 sha256 必须等于 `book.json.sha256`（这是去重与信任的根）；JSON 逐个比对 manifest 哈希；音频只靠 ZIP CRC32（不为 GB 级数据再算一遍）。
- **落盘**：解压到 `.import/<id>/books/<bookId>/`，全部通过后 `rename` 到 `books/<bookId>`（同卷原子）；`book.json` 在其内最后写，维持 §5.1「存在即完成」。
- **清理**：失败即删 `.import/<id>/`；插件 `apply()` 启动时清理超过 24 h 的残留。
- **导出侧**：包内路径只用 ASCII 的 `bookId` / `moduleId`，**绝不把书名放进路径**（中文在 ZIP 里依赖 UTF-8 标志，Windows 仍可能按 GBK 解出乱码）；书名只出现在 `manifest.json` 与下载文件名（`filename*=UTF-8''…`）。

### D30 状态归一与降级

包是**快照**，不是事务。导入时归一，保证「导入成功 = 面板没有第二个真相」：

| 包内状态 | 归一为 | 用户可见 |
|---|---|---|
| `queued/structuring/validate/anchor/voicing` | `interrupted` + `E_INTERRUPTED` | 「已中断，可重试」（与 §5.4 一致） |
| `ready` / `ready_degraded` | 原样 | — |
| `failed` / `cancelled` | 原样（保留错误码） | 可重试/删除 |
| 有 `slides.json` 但 wav 缺失 | `ready_degraded`；该页 `audio_file=null`、`audio_provider='none'` | 「本页无配音」，**不换声**（§2.3-③） |
| 无 `source.pdf` | **整本拒绝** `E_PKG_NO_PDF` | 「包里没有原文 PDF」 |

**导出时**：书有活动作业则拒绝（`E_EXPORT_BUSY`）。否则会打出「18 页只有 12 页音频」的包，而用户看不出为什么。

### D31 版本：容器版本与数据版本解耦

| 字段 | 位置 | 规则 |
|---|---|---|
| `formatVersion` | `manifest.json` | 包结构变化时 +1；读到 > 1 **一律拒绝**，不做「尽力解析」 |
| `schemaVersion` | `book.json` / `slides.json` | 沿用既有值；> 1 拒绝，缺失按 1 |
| `generator.version` | `manifest.json` | **仅记录，不参与校验**（不让版本号把老包卡死） |

### D32 排序与可见性：导入的书要能被看见

| 项 | 决策 | 理由 |
|---|---|---|
| `lastOpenedAt` | 导入时置为**导入时间**（新导入的排前面），原值记入 `manifest.books[].lastOpenedAt` | 若沿用旧值，导入的 10 本会散落在 200 本中间甚至末尾，用户找不到 |
| 书架 200 本上限 | 导入后总数 > 200 时在结果里提示「已有 N 本，书架只显示最近 200 本」 | §FR-1 的既有规则，不改 |
| 结果面板 | 每本一行，带「打开这本书」 | 批量导入后必须能一键到达 |

### 5.2 每个文件都在为「那三句话」服务

| 文件 | 支撑 | 去掉后的具体后果 |
|---|---|---|
| `book.json` | 书在 | 书架扫不到（`book.json` 存在即完成，§5.1） |
| `source.pdf` | 书在 + 点开能看 | 左窗格永久空白；也无法校验身份 |

| `chapters.json` | 书在（可勾选） | 详情页没有章节；`manual` 手改丢失 |
| `toc.json` | 书在（目录成果） | 仅「重新解析」要多花一次 token |
| `module.json` | 模块在 | 模块在面板里不显示（§2.3-②） |
| `slides.json` | 模块在 + 能播 | 播放器无内容；锚点与 `audio_file` 全丢 |
| `audio/*.wav` | 点开还能听 | 每页「无配音」，且没有便宜办法补 |

## 6. 批量语义

**「批量」有三种理解，只做第一种**：① 勾选多本一次出入（做）；② 按条件（全部/某作者/未听过）批量（不做）；③ 定时自动备份（非目标）。

**导入的两个来源，一套处理**：多个包文件（前端多选、逐个 POST）/ 一个含 N 本的包（上一次批量导出的产物）。服务端只有一个处理函数，循环 `manifest.books[]`。

**冲突矩阵**见 D26。**结果结构**：

```json
{
  "ok": true,
  "summary": { "imported": 1, "merged": 1, "skipped": 0, "failed": 1, "modulesAdded": 3, "modulesExisting": 2 },
  "items": [
    { "file": "A.zip", "bookId": "k3m9…", "title": "…", "status": "imported", "modulesAdded": 2 },
    { "file": "B.zip", "bookId": "", "status": "failed", "code": "E_PKG_CORRUPT", "message": "包已损坏" }
  ]
}
```

## 7. 接口与错误码

全部挂在 `/dsh-book-slides/`，`kind: 'exact'`，不遮蔽现有路由。

| 方法 | 路径 | 请求 | 响应 |
|---|---|---|---|
| GET | `/export` | `books=id1,id2`、`source=1\|0`、`audio=1\|0` | `application/zip` 流；错误在写流之前返回 JSON |
| GET | `/export/size` | 同上 | `{ok, books, modules, files, bytes, warnings[]}` |
| POST | `/import/package` | 裸 ZIP + `x-file-name`（URL 编码），可选 `?policy=merge\|skip\|copy` | 见 §6 结构 |
| POST | `/module/voice` | `{moduleId}` | **仅补配音**（FR-9.7，也是「不含音频」的前置） |

> `/import`（PDF）保持原样。**不要**合并成「智能识别文件类型」的单一入口：那会让 `E_PDF_*` 与 `E_PKG_*` 两套语义缠在一起。

| 码 | 触发 | 粒度 |
|---|---|---|
| `E_EXPORT_EMPTY` / `E_EXPORT_BUSY` / `E_EXPORT_TOO_LARGE` / `E_EXPORT_FAILED` | 未选书 / 正在生成 / >4 GiB / 读盘失败 | 整包 |
| `E_PKG_NOT_ZIP` / `E_PKG_CORRUPT` / `E_PKG_UNSAFE` / `E_PKG_TOO_LARGE` | 非 ZIP / CRC 或截断 / 路径穿越 / 超限 | 单包 |
| `E_PKG_MANIFEST` / `E_PKG_VERSION` / `E_PKG_CHECKSUM` | 缺清单 / 版本过高 / 哈希不符 | 单包或单本 |
| `E_PKG_NO_PDF` / `E_PKG_ID_CONFLICT` | 缺原文 / 书号被占 | 单本 |
| `E_PKG_BOOK_EXISTS` | `skip` 命中（`status=skipped`，非失败） | 单本 |

## 8. 体积预算

| 组成 | 典型（542 页 / 2 模块 / 18 页） | 单本上限（50 模块 × 30 页） |
|---|---|---|
| `source.pdf` | 20–80 MB | 200 MB（既有硬上限） |
| `pages.json` | ~1 MB（30 万字） | ~3 MB |
| `chapters/toc/book` | < 100 KB | < 200 KB |
| `slides.json` ×N | ~30 KB / 模块 | 1.5 MB |
| `audio/*.wav` ×N | ~50 MB | **~4.5 GB** |

依据：Qwen3-TTS 返回 WAV（J.2），24 kHz / 16 bit / 单声道 ≈ 48 KB/s；220 字 ≈ 60 s ≈ **3 MB/页**。
结论：全量最坏 4.7 GB > 4 GiB 上限 → 「不含音频」必须提供；而它又要求「仅补配音」存在（D24 末段）。

## 9. 验收（AC-32 ~ AC-50）

| AC | 判据 |
|---|---|
| AC-32 | **三层往返**：单本（2 模块、含音频）导出→导入空数据根→书架 1 本、页数/章数/sha256 一致、模块 2 个且状态一致、每页 `/audio` 返回 200 且字节与源文件相同 |
| AC-33 | **只读性**：导出前后 `books/` 递归 `size+mtime` 完全一致；导出不产生临时 ZIP |
| AC-34 | **幂等**：同包连导两次，书架仍 1 本、模块数不增 |
| AC-35 | **合并**：目标机已用 PDF 导入同一本书（不同 `bookId`、0 模块）→ 导入后 `bookId` 不变、只补 2 个模块 |
| AC-36 | **手改保留**：`manual:true` 的章节标题与页区间在导入后不变；`merge` 不覆盖 `chapters.json` |
| AC-37 | **锚点不漂**：导入后任取 3 页，`source_anchor` 与高亮矩形与源机一致（同窗格宽度，误差 ≤ 1%） |
| AC-38 | **零生成**：导入全过程 `ctx.llm` 调用 0 次、千问请求 0 次（mock 计数） |
| AC-39 | **无 Key 可播**：把 `voice.json` 设为 `provider:off`（或删除）后导入并播放，音频正常——播放不依赖 Key |
| AC-40 | **缺音频不换声**：删掉一个 wav 后导入 → 该页 `audio_provider='none'`、显示「本页无配音」、`speechSynthesis.speak` 调用次数为 0 |
| AC-41 | **批量部分失败**：3 个包 1 个截断 → 成功 2、失败 1、`E_PKG_CORRUPT`；`books/` 与 `.import/` 无残留 |
| AC-42 | **缺 PDF**：删包内 `source.pdf` → `E_PKG_NO_PDF`，书架不新增；同批其它照常 |
| AC-43 | **篡改**：改 `pages.json` 一个字节 → `E_PKG_CHECKSUM`，整本拒绝，不写半本 |
| AC-44 | **路径穿越**：含 `../../evil.txt` 的包 → `E_PKG_UNSAFE`，`$DSH_HOME` 外无新文件 |
| AC-45 | **体积/内存**：声明解压 10 GiB 的包被拦；GB 级导出导入全程内存峰值 < 512 MB |
| AC-46 | **版本**：`formatVersion=99` → `E_PKG_VERSION`；旧数据（无 `toc.json`、`book.json` 无新字段）正常 |
| AC-47 | **不含音频**：导出→导入后模块 `ready_degraded`、全页无配音；点「仅补配音」后落 wav 并恢复 `ready` |
| AC-48 | **生成中导出**：`E_EXPORT_BUSY`，不产半截 ZIP |
| AC-49 | **批量规模**：勾 10 本导出 1 个包；`/export/size` 与实际大小偏差 ≤ 10% |
| AC-50 | **回归**：`npm test` 全绿，既有 162 项通过数不下降 |
