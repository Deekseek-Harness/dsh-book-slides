## 0. 一页结论

**一句话**：这是一个**以精讲为范围、以原文为判据、以题库为资产、以复习为闭环的练习子系统**——不是「AI 出题按钮」，也不是「播放器里加个测验 tab」。

- ✅ **它是「写少读多」的功能**：一次生成（贵、慢、异步），多次练习（判题 0 成本、毫秒级、可离线；自动讲解只为答错的题付一次）。所有设计都由这条经济学推出来：题库必须落盘、跨场复用、可去重、可随书档走。
- ✅ **它是纯加法**：所有**已经生成过的**精讲模块都能直接练，不需要重跑 LLM、不需要重新导入 PDF。这是需求最划算的地方。
- ⚠ **「实时判题」决定了题型只能是客观题**。简答题必须调模型评分，判题的延迟、离线、可复现、成本四项同时失守。
- ⚠ **讲解不预生成**：判题即时；讲解在**首次答错时**调一次模型生成（「半实时」，≤8s），生成完写回题库，同题再错秒出。预生成要为每道题付一次讲解费，而多数题不会错；按需生成只为错题付费，还能把每个错误选项都讲清楚。
- ⚠ **③ 与 ④ 不是矛盾，是两层**：去重发生在**题库**（写路径），复用发生在**组卷**（读路径）。
- ⚠ **练习数据属于书，不属于模块**：模块可删、可重生成，题库与掌握度要活下来，否则「旧题」与「复习」一起断。
- 7 个参数已按默认冻结，并入 SRS Q7–Q13（§10 保留为评审记录）。

## 1. 你写的是什么需求

### 1.1 需求定性

| 视角 | 它是什么 | 不是什么 |
|---|---|---|
| 产品 | 精讲的**第四个能力**：听 → 练 → 记 → 复习 | 一个独立的刷题 App |
| 功能 | 题库 + 组卷 + 判题 + 讲解 + 掌握度调度 | 一个「生成 10 道题」的按钮 |
| 技术 | 1 个异步生成作业 + 3 个确定性状态（组卷 / 判题 / 调度）+ 1 个按需讲解调用 | 一个每次都要调模型的问答链 |
| 数据 | 书级资产（可复用、可导出） | 模块的附属临时文件 |

一句话说清它为什么不是「出题器」：出题器只解决「有题做」；这个需求真正要解决的是**「听完之后怎么确认自己记住了，以及忘了的怎么找回来」**。后者需要题库、记录和调度，出题只是入口。

### 1.2 它不是出题器，是学习闭环

| 环节 | 现状 | 练习补上的 | 缺了会怎样 |
|---|---|---|---|
| 输入 | 精讲：幻灯片 + 配音 + 原文对照 | 把「讲过的重点」变成可考的范围 | 考到没讲的内容，读者不服 |
| 检索 | 无 | 逐题作答，强制回忆 | 只是又读了一遍，没有提取 |
| 反馈 | 无 | 对错 + 为什么 + 原文哪一页 | 错了不知道为什么错，下次还错 |
| 调度 | 无 | 错题本 + 到期复习 | 练完就忘，记录变成死数据 |

后三个环节在学习科学里叫**检索练习 + 即时反馈 + 间隔重复**；缺一个，都会退化成「刷题」。

### 1.3 它长在既有能力的接缝上

| 既有能力 | 练习复用什么 | 为什么这是差异点 |
|---|---|---|
| 模块 = 勾选的 1–5 章（FR-4） | 练习范围默认 = 该模块的章 | 不新增「选章」交互，直接接住读者刚听完的那一段 |
| `slides[].title` / `bullet_points` | 出题的**考点白名单** | 讲过的才考，「没讲过怎么考」不成立 |
| `source_quote` + 锚点回填（D10） | 每题带 `source_quote` → `{page, para_index}` | 答错点「看原文」直接跳到那页那一段；通用题库 App 做不到 |
| 书档（FR-9 / 附录 M） | 题库与练习记录随书走 | 换机后旧题还在，「不重复」不断档 |
| 异步作业 + 进度条（FR-5） | 题库生成复用同一形态 | 不用重造轮子 |

**结论**：这是个加法功能。不改既有数据结构、不改生成状态机、不引入新服务；老模块零迁移即可开练。

### 1.4 五条原文翻译成可判定的表述

| # | 原文 | 翻译成能验收的话 | 原文缺的 |
|---|---|---|---|
| ① | 主要生成对应的练习题 | 从**考点白名单**生成 N 题，题型/难度/覆盖有配额，每题带答案与原文出处（讲解不预生成） | 题从哪来、什么题型、多少题、何时生成 |
| ② | 读者答题，实时判题，错误给出讲解 | 提交后 ≤100ms **本地**判定；错误时先给正确答案与原文出处，再给按需生成的讲解（≤8s） | 判题在哪端、答案是否下发、讲解何时生成 |
| ③ | 每次练习可能有旧题目 | 组卷按配额从本书题库复用旧题（到期题、错题、巩固题） | 旧题怎么选、比例多少、会不会总是同一批 |
| ④ | 新题目不与旧题目重复 | 生成层三重去重：题干精确、题干近似、考点上限 | 去重范围、阈值、重了怎么办 |
| ⑤ | 每次练习有记录，可用于复习 | 场次流水 + 每题掌握状态；错题本 + 到期复习队列 | 复习算法、记录粒度、是否随书档走 |

> ④ 的原文写作「新题目捕鱼就题目重复」，按「新题目**不与**旧题目重复」理解（看着像拼音输入笔误）。若原意不是这个，§2.3 整节要重写。

## 2. 审阅：五个必须现在定的问题

### 2.1 题从哪来：精讲，还是原文？

「基于精讲 + 其对应章节」把两个不同的东西放在了一起，必须先拆开：

| 输入 | 能给什么 | 单独用会怎样 |
|---|---|---|
| 精讲 `slides`（标题、要点、讲稿） | **考什么**：读者刚听过的重点、讲者强调的论断 | 只能考到 6–30 个压缩过的点，题目偏浅，还可能把讲稿的口语当成事实 |
| 章节原文 `pages.json` | **依据什么**：可引用的原句、正确的因果、干扰项素材 | 会考到精讲没讲的内容，读者的第一反应是「这没讲过」 |

**决策：双输入，各管一段。**

- **范围**：由覆盖该章的 slide 的 `title` / `bullet_points` 决定，形成「考点白名单」；白名单外的知识点不出题。
- **依据**：答案与讲解必须能在该章原文里找到 `source_quote`；找不到就不许出。
- **映射**：slide → 章，用 `source_pages` 与章区间求交。没有 slide 覆盖的章，不允许**生成新题**（复习旧题不受此限）。

这样「基于精讲」不是一句口号，而是一条可校验的约束：**考点来自 slides，出处来自原文**。

> 顺带一个边界：没有精讲模块的章，练习入口置灰并提示「先听一遍再练」。这不是刁难，是产品定位——没有「讲过的重点」，出题就只能考全书，退化成通用题库。

### 2.2 什么题能「实时判」：题型决定架构

| 题型 | 判题方式 | 实时 | 离线 | 额外成本 | v1 |
|---|---|---|---|---|---|
| 单选 | 选项 key 相等 | ✅ <10ms | ✅ | 0 | 做 |
| 多选 | 集合相等（全对才算） | ✅ | ✅ | 0 | 做 |
| 判断 | 二选一 | ✅ | ✅ | 0 | 做 |
| 填空 | 归一化匹配，同义/单位/语序歧义多 | ⚠️ 要人工兜底 | ✅ | 0 | 不做 |
| 简答 | LLM 按 rubric 评分 | ❌ 2–8s | ❌ | 每题一次调用 | 不做 |

「实时」不是形容词，是**架构约束**。一旦有简答题，判题就必须调模型，于是：① 延迟不可控；② 断网不可用；③ 同答案两次评分可能不同；④ 每场都花钱。四条里破一条，这个功能就不再是「练习」，而是「AI 批作业」。

**决策**：v1 只做三种客观题；多选**全对才算对**，不给部分分——半分会把「掌握」变成不可判定的连续量，复习调度也随之失去依据。

判题与讲解因此拆成两段：判题必须即时、确定、离线可用；讲解可以慢一步、可以联网，但**必须留痕**——生成一次就写回题库，第二次错同一题不再付钱。这就是「半实时」的边界。

### 2.3 「旧题」与「不重复」：是两层，不是一条

原文 ③ 说每场可能有旧题，④ 说新题不与旧题重复。字面上打架，实际是两条不同层面的规则：

```
写路径（生成）                          读路径（组卷）
新题 ──▶ 三重去重 ──▶ 题库 ──▶ 到期题 / 错题 / 新题 ──▶ 本场 8 题
          │                              │
          └─ 永不与库内重复               └─ 允许、且必须复用旧题
```

- **去重是题库的属性**：同一道题不重复入库。作用域 = 同一本书同一章（精确）+ 同一本书（近似）。
- **复用是组卷的策略**：每场按配额从库里取，旧题是正常来源，不是例外。

反过来做（把「不重复」实现在组卷层，每场只出新题）会得到三个坏结果：旧题永远不出现 → ③ 落空；错题永不重练 → 复习没有载体；题库越攒越大但只用一次 → 生成成本白花。

**决策**：两条规则分开写、分开验收（AC-75/76/77 对 AC-78/79/80）。

### 2.4 「复习」有四种理解，v1 只做前三种

| 理解 | 是什么 | 成本 | v1 |
|---|---|---|---|
| A 错题重做 | 把答错的题再练一遍 | 低 | ✅ |
| B 间隔重复 | 按遗忘节奏安排「这题什么时候再出现」 | 中（要维护每题状态） | ✅ 简化版：Leitner 5 盒 |
| C 回顾讲解 | 不做题，重看错题讲解与原文 | 低 | ✅ 作为结果页的一部分 |
| D 学习分析 | 正确率曲线、掌握度雷达、章节强弱 | 高 | ❌ |

没有 B，「记录」就只是日志；有了 B，记录才是**调度输入**。所以「记录」的最小字段不是「对/错」，而是「**这题下次什么时候该出现**」。

### 2.5 题目错了谁负责

LLM 出题有四类错，性质不同，兜底手段也不同：

| 错法 | 例子 | 规则能抓吗 | 兜底 |
|---|---|---|---|
| 结构错 | 答案不在选项里、多选只给 1 个 | ✅ | 结构校验，整题丢弃并补生成 |
| 出处假 | `source_quote` 不是原文连续子串 | ✅ | 复用精讲的锚点回填；未命中修复一次，仍不中则丢弃 |
| 重复 | 与旧题同义改写 | ✅ 近似 | 三重去重 |
| 答案有争议 | 两个选项都说得通 / 答案本身错 | ❌ | 只能靠人：每题一个「这题有问题」，标记后不再出现 |

所以质量兜底是**三道闸**：结构校验（自动）→ 锚点回填（自动）→ 用户标记（人工）。**不做**逐题「答案复核」调用（那是判对错，不是讲解）——生成成本翻倍，而复核本身也会错。要更严可以给一个可选的「严格模式」，默认关。

## 3. 决策（D51–D61）

> 每条按「原文怎么说 → 模糊在哪 → 怎么定 → 为什么」写。决策即规范，§4 的条目全部引用这里。

| 编号 | 原文/问题 | 模糊在哪 | 决策 | 理由 |
|---|---|---|---|---|
| **D51** | 「基于精讲 + 其对应章节」 | 考精讲的内容，还是考原文的内容？ | **双输入**：`slides` 的标题/要点定考点白名单（考什么），章原文定 `source_quote` 与正确性（依据什么） | 只用 slides 太浅且易把口语当事实；只用原文会超纲。两者分工，各管一段 |
| **D52** | 「实时判题」 | 哪些题型能实时？ | 只做**单选 / 多选 / 判断**；多选全对才算对；填空、简答不做 | 客观题判题是确定性代码，才能做到实时、离线、可复现、零成本 |
| **D53** | 「读者答题」 | 判题放前端还是宿主？ | **宿主判题**；下发题目时剥离 `answer` / `explanation`，提交后由宿主返回结果并落记录 | 答案不下发，判题逻辑只写一遍；记录与掌握度不会因前端丢写而不一致 |
| **D54** | 「错误给出讲解」 | 讲解是预生成，还是答错时再生成？ | **不预生成**。答错时按需调一次模型生成（「半实时」，≤8s），并把结果写回题库（`explanation` + `explanation_status=ready`）；讲解按题存、不按选项存，因此同题再错直接复用 | 预生成要为每道题付一次讲解费，而多数题不会错；按需只为错题付费，且逐项讲解天然覆盖读者的选择。代价是首次答错要等几秒、离线时无讲解，可接受 |
| **D55** | 「每次练习可能有旧题目」 | 旧题存在哪、属于谁？ | 题库按**书**存、按**章**索引；`module_id` 只作来源标记。模块删除/重生成不影响题库 | 模块是播放单元，会删会重做；题库是资产，必须跨模块、跨场次活着，去重与复习才有依据 |
| **D56** | 「主要生成练习题」 | 什么时候生成？跟着精讲一起，还是练习时？ | **首次练习时按需、异步、按章缓存、幂等**；不并入精讲生成流水线 | 加进生成流水线 = 每个模块多 20–40s 与一次调用，而多数人只听不练；老模块还无法回溯。按需生成让成本只落在真正练习的人身上 |
| **D57** | 「新题目不与旧题目重复」 | 什么算重复？在哪个环节查？ | **题库层**三重去重：题干归一化哈希、题干 bigram Jaccard ≥ 0.80、同考点 ≤ 2 题；**组卷层不去重** | 去重是写入约束，复用是读取策略；混在一起会做出「每场全出新题」 |
| **D58** | 「每次练习可能有旧题目」 | 旧题占多少、怎么挑？ | 默认 **8 题**；`mixed` 模式下到期题 ≤ 40%（8 题时最多 3 题，向下取整），其余优先未答过的新题，不足再用未掌握旧题补，最后才用已掌握旧题；同考点 ≤ 2、章数 ≤ 题数时每章至少 1 | 保证「以新为主 + 错题必复现」，同时不会因为题库小而开不出场次 |
| **D59** | 「可以用于复习」 | 复习是错题本，还是间隔重复？ | **Leitner 5 盒**（间隔 1/3/7/21/60 天）+ 错题本；答对进盒、答错回盒 0；不做 SM-2、不做跨书复习 | 5 盒的调度效果接近 SM-2，状态只有两个整数，实现与调试成本低一个量级 |
| **D60** | 「每次练习有记录」 | 记录跟书走还是跟机器走？入不入书档？ | 题库 **MUST**（有则必还原）、掌握度与场次 **SHOULD**（缺了只丢复习进度）；`voice.json` 等仍不入包 | 题库重生成要花钱且会让「不重复」断档；记录体积小、价值高，但不该让缺记录的书档导入失败 |
| **D61** | （未提）题目质量 | 模型出错题谁兜底？ | 三道闸：结构校验 → 锚点回填 → 用户标记；可选「严格模式」逐题复核，默认关 | 全量复核成本翻倍且复核也会错；人工标记是最便宜的真值来源 |

## 4. 优化后的需求（FR-11 草案）

### 描述

在已就绪的精讲模块（或其中的章）上提供「练习」：从该章的精讲考点生成题库，按「新题 + 到期题」组一场 5–20 题的练习；读者逐题作答，宿主即时判题；答错后再按需生成讲解，并给出原文出处；每场记录落盘，答错的题进入错题本并按遗忘节奏回到后续场次。

### 目标判据

1. **能出题**：一个 3 章模块首次练习，2 分钟内得到 12–18 道题，每题有考点、答案与原文出处（讲解不预生成）。
2. **能判**：提交后 ≤100ms 出结果；答案在提交前不下发；断网时判题、正确答案与原文照样可用（未生成的讲解降级为「暂不可用」）。
3. **能复用**：同一本书连续练 5 场，**题库生成**不重复调用模型（讲解按错题另计）；新题不与库内旧题重复；旧题按配额正常出现。
4. **能复习**：答错的题进错题本；到期题在入口有计数；关掉面板再打开能接着答。

### 规则

- **范围**：练习范围 = 一个模块的章，或模块覆盖的若干章。生成新题要求该章至少有一个 `ready` / `ready_degraded` 模块覆盖；题库已有题的章可直接复习，不受此限。
- **题库规模**：每章 4–6 题（3 章模块 12–18 题，按章累加）；单书上限 300 题。题型配比 单选 60% / 多选 20% / 判断 20%；难度 易 30% / 中 50% / 难 20%。
- **题目字段**：题干 ≤120 字；单选 4 个选项、判断 2 个、多选 2–4 个正确项；选项 ≤60 字；`point`（考点）≤16 字；`source_quote` 10–200 字，必须是该章原文连续子串；`explanation` 生成时为 `null`，由答错后按需填充。
- **生成**：异步作业 `queued → drafting → checking → anchoring → ready | failed | cancelled`；按章缓存，键 = `sha256(bookId | 章号 | 章标题 | 章字数 | promptVersion | blueprintVersion)`；命中直接返回，不重跑模型；单章失败不影响其它章；整章失败可重试。
- **去重**：见 §5.5。重复题直接丢弃并补生成，最多两轮；仍不足则接受并记 warning（不阻断）。
- **组卷**：见 §5.4。场次生成时**冻结题目清单**（`plan`），中途不换题；同一场次内 qid 唯一。
- **作答**：逐题提交，提交即定结果，不可改选、不可回退；可「不会，看答案」（记错，`picked: []`）；可中途「结束本场」，正确率分母 = 已答数；同一 qid 重复提交按幂等处理，只记首次。
- **判题**：宿主本地判定，单选/判断比 key，多选比集合且全对才算对；判题不调模型，返回 `{correct, answer, source_quote, source_anchor, explanation}`（`explanation` 已沉淀则带上，否则 `null`）。
- **讲解**：答错后自动请求一次生成（置 `pending`，「正在讲解…」≤8s），内容须覆盖「正确项为什么对 / 每个错误选项为什么错 / 原文依据」150–300 字；成功写回题库并置 `ready`，失败置 `failed`，同题再错直接秒出；失败或离线显示「讲解暂不可用」+ 正确答案与原文，不阻断下一题。答对时默认不出讲解，点「看讲解」才生成（同样沉淀）。可选「再讲讲」：换个说法或带一个例子再生成一版，按 `qid + 选择` 单独缓存，点了才花钱。
- **记录**：每答一题立即 append 到 `sessions/<sessionId>.json` 并更新 `mastery.json`；断点续练从第一道未答题继续；`summary` 在结束本场时写入。
- **复习**：错题本 = `last = wrong` 或 `box = 0` 的题，按最近答错时间排序；「到期」= `due_at ≤ now`；入口显示「待复习 N」；「练错题」直接开一场 `review`。
- **质量**：题目可被标记「这题有问题」→ `flagged: true`，不再进入任何组卷，但仍保留在场次记录里可回看；不提供手工编辑题干与答案。
- **书档**：`practice/` 有则随包走（题库 MUST、掌握度与场次 SHOULD），合并时按 `qid` / `session_id` 取并集，不覆盖本地。
- **隔离**：不写 `slides.json` / `module.json`，不改模块状态机；题库作业与精讲生成作业互不阻塞。

## 5. 数据契约

### 5.1 磁盘布局（只增不改）

```
books/<bookId>/
├── book.json / source.pdf / pages.json / chapters.json / toc.json   ← 不变
├── modules/<moduleId>/…                                             ← 不变
└── practice/                                                        ← 新增
    ├── questions.json        # 题库（全书，按章索引；explanation 懒填充）
    ├── mastery.json          # 每题掌握状态（box / due_at / attempts）
    ├── explain-cache/<hash>.json   # 「再讲讲」的按需讲解缓存（不入书档）
    └── sessions/<sessionId>.json   # 每场练习：计划 + 作答流水 + 汇总
```

> 分离的理由：题库可重建、可合并；掌握度是用户数据，重建题库不能把它冲掉；场次是 append-only 的历史；`explain-cache/` 只是避免重复付费的缓存，丢了最多重生成一次「再讲讲」。


- `qid = "q" + sha256(bookId | chapter | dedupe_key)` 前 12 位。**由内容派生**，所以重新生成同一道题会命中同一个 `qid`，掌握度不丢。

- 「再讲讲」的结果单独放 `explain-cache/<sha256(qid | 选择 | promptVersion)>.json`，不进题库、不入书档。
- `flagged` 的题留在库里（场次记录要能回看），只是不参与组卷。

### 5.4 组卷算法

```
compose(book, chapters, mode, N, now):
  pool   = questions.where(chapter ∈ chapters, flagged = false)
  due    = pool.where(due_at ≤ now).sort(due_at)
  unseen = pool.where(attempts = 0).sort(difficulty ↑, qid)
  weak   = pool.where(attempts > 0, box ≤ 1, ∉ due)
  solid  = pool − due − unseen − weak

  if mode = "review": picked = due ++ weak
  elif mode = "new":  picked = unseen
  else:                                  # mixed（默认）
    picked  = due[0 : min(len(due), floor(0.4N))]
    picked += unseen[0 : N − len(picked)]
    picked += weak[0 : N − len(picked)]
    picked += solid.sort(box).take(N − len(picked))

  picked = capByPoint(picked, 2)         # 同考点 ≤ 2，超出换弱题
  picked = coverChapters(picked, chapters)  # 章数 ≤ N 时每章至少 1
  picked = orderBy(picked, difficulty ↑, 相邻不同考点)
  return picked[0 : N]                   # 允许 < N；0 题才报 E_QZ_NOT_ENOUGH
```

场次不足 N 时不报错：准备页明说「本次只有 5 题（题库不足）」，比拦下来更有用。

### 5.5 去重算法

```
normalize(s) = NFKC → 全半角归一 → 去空白/标点/题号 → 英文小写
key(s)       = sha256(normalize(s))
bigrams(s)   = normalize(s) 的相邻二字集合

重复(a, b) =
     key(a.stem) = key(b.stem)
  或  jaccard(bigrams(a.stem), bigrams(b.stem)) ≥ 0.80
  或  同 chapter 且同 point 的题已有 2 道
```

只对**同书同章**做精确去重、**同书**做近似去重；跨书不去重（两本书都讲「什么是导数」是合理的）。

### 5.6 复习调度（Leitner 5 盒）

| 盒 | 含义 | 答对后 | 答错后 |
|---|---|---|---|
| 0 | 新题 / 刚答错 | → 1，1 天后 | 留 0，**立即到期** |
| 1 | 初记 | → 2，3 天后 | → 0，立即到期 |
| 2 | 熟悉 | → 3，7 天后 | → 0，立即到期 |
| 3 | 掌握 | → 4，21 天后 | → 0，立即到期 |
| 4 | 稳固 | 留 4，60 天后 | → 0，立即到期 |

- 「立即到期」只影响**下一场**，不在当前场次里重出（否则本场正确率会被自己刷高）。
- 错题本不按盒算，直接是 `last = wrong`，这样「我错过的题」永远找得到，不会被后续答对冲掉。

## 6. 界面

### 6.1 入口（只加不改）

| 位置 | 入口 | 行为 |
|---|---|---|
| 模块行 | 「练习」+ 角标 `可练 14 · 待复习 3` | 进准备页，范围 = 该模块的章 |
| 播放器底栏 | 「练一练」 | 同上；返回时回到原页 |
| 书籍详情 | 「复习」chip（到期 N） | 进准备页，范围 = 全书，模式默认 `review` |
| 结果页 | 「再练本场错题」 | 直接开一场 `review` |

### 6.2 练习视图三态

| 态 | 内容 |
|---|---|
| **准备** | 范围 chip（模块名 / 第 1–3 章）· 题库状态（可练 18 · 未答 12 · 到期 4 · 错题 2）· 模式（混合 / 只练新题 / 只复习）· 题量（5 / 8 / 10 / 15）· 主按钮「开始练习」；题库不足时按钮变「先生成 N 题」并走作业进度 |
| **作答** | 顶部 `3/8` + 细进度条 + 「结束本场」；题干与考点 chip；选项；「提交」（Enter）；提交后出反馈卡；「下一题」 |
| **结果** | 正确率、用时、答对/答错数；错题列表（点开看讲解与原文）；「再练本场错题」「返回」 |

### 6.3 反馈卡

- **判定条**：✓ 正确 / ✗ 错误（「你选了 A，正确答案 B」），提交后即时出现。
- **讲解**：答错后自动生成，先显示骨架与「正在讲解…」（≤8s）；成功后就地展开——每个错误选项为什么错、正确项为什么对、原文依据；已沉淀的题秒出。
- **原文**：引文块 + `第 12 页 · 看原文` → 跳到播放器该页并高亮该段（无锚点时只跳页并提示）。
- **底部**：`下一题`（Enter）· `再讲讲`（换角度/带例子，按需付费）· `这题有问题`（就地标记，不打断流程）。
- **失败/离线**：讲解区显示「讲解暂不可用，可稍后重试」，正确答案与原文照常显示，不阻断下一题。
- **答对时**：不自动生成讲解，只留一个 `看讲解`（点了才生成并沉淀）。

### 6.4 键盘

`1–4` 选项、`Enter` 提交/下一题、`Esc` 退出（作答中二次确认，避免误丢进度）。

## 7. 非功能需求

| 类别 | 指标 |
|---|---|
| 判题延迟 | P95 ≤ 100ms（本机 HTTP 往返，含写盘前的内存判定） |
| 生成耗时 | 单章 4–6 题 P50 ≤ 40s、P90 ≤ 90s；3 章模块 ≤ 3 分钟 |
| 生成成本 | 每章 1 次 LLM 调用；同一章重复练习 0 次调用 |
| 判题成本 | 0（本地确定性代码，无模型、无网络） |
| 讲解成本 | 每题**首次答错** 1 次调用（答对时点「看讲解」同样 1 次）；已沉淀 0 次；「再讲讲」每次 1 次（按 `qid + 选择` 缓存） |
| 讲解延迟 | 单题 P50 ≤ 4s、P90 ≤ 8s；超时或失败不影响判题与下一题 |
| 容量 | 单书 ≤ 300 题；单场 ≤ 20 题；单书场次 ≤ 1000 |
| 存储 | 题库 ~1KB/题（含讲解 ~1.5KB）、场次 ~1KB/场、再讲讲缓存 ~1KB/条；单书 < 8MB |
| 隐私 | 生成复用既有 LLM 通道（章文本 + slides 要点）；**新增一类外发**：答错（或点「看讲解」）时把该题题干、你的选择、正确项与原文片段发给模型生成讲解；判题、组卷、记录、复习全本地；不上传整场作答记录 |
| 离线 | 题库与**已沉淀**的讲解可用；未生成的讲解显示「暂不可用」，「再讲讲」禁用 |
| 可靠性 | 题库 / 掌握度 / 场次均原子写；作业中断可重跑；标记不丢 |

## 8. 验收（AC-71 ~ AC-89）

| AC | 判据 |
|---|---|
| AC-71 | **首次生成**：3 章模块首次点练习 → 作业走 `drafting → checking → anchoring` → 落盘 12–18 题；再次点练习命中缓存，LLM 调用计数为 0 |
| AC-72 | **判题实时**：提交单选，P95 ≤ 100ms；返回体含 `correct/answer/source_quote`（`explanation` 可为 `null`）；判题过程模型调用 0 次 |
| AC-73 | **答案不下发**：`POST /practice/session` 与 `GET /practice/session` 返回的题目对象均不含 `answer` / `explanation`；讲解只由 `POST /practice/explain` 生成，`answer` 只回已沉淀的 |
| AC-74 | **错题讲解**：答错后立即显示正确答案与原文页码；≤8s 生成讲解并就地展开（每个错误选项为什么错 / 正确项为什么对 / 原文依据）；同题再错秒出；点「看原文」跳到该页并高亮该段，`unanchored` 题只跳页并提示 |
| AC-75 | **精确去重**：同章生成两次（或并发两次），题库内 `dedupe_key` 无重复，`qid` 唯一 |
| AC-76 | **近似去重**：构造两条 Jaccard ≥ 0.80 的题干，第二条被丢弃并补生成；最终题库无近似重复 |
| AC-77 | **考点上限**：任一 `chapter + point` 组合的题 ≤ 2 |
| AC-78 | **组卷（混合）**：题库 20 题、5 题到期、8 题未答 → 8 题场次中到期题 ≤ 3、新题 ≥ 5、同考点 ≤ 2、每章 ≥ 1 |
| AC-79 | **组卷（不足）**：库内 12 题、未答仅 3 题、N=8 → 补足 8 题（其中 5 道为旧题），准备页提示「本次含 5 道旧题」；题库总共 0 题时才报 `E_QZ_NOT_ENOUGH` |
| AC-80 | **旧题复用**：连续两场，第二场至少 1 题来自库内旧题，且第二场的**题库生成**调用为 0（讲解调用另计） |
| AC-81 | **断点续练**：答 3 题后关面板 → 重开进入同一 `sessionId`，停在第 4 题，前 3 题记录与掌握度都在 |
| AC-82 | **错题本**：答错 2 题 → 错题本 2 条；「练错题」开出的场次必含这 2 题 |
| AC-83 | **复习调度**：答错 → 回盒 0 并立即到期，下一场被优先选中；答对 → 进盒 1，1 天后到期并出现在入口「待复习 N」；连续答对 5 次后间隔依次为 1/3/7/21/60 天 |
| AC-84 | **标记坏题**：标记后该题不再进入组卷，但历史场次仍能回看；题库总数不减 |
| AC-85 | **失败可恢复**：模拟模型超时 → 该章 `E_QZ_TIMEOUT`，其它章不受影响，可重试；不留下半截题库 |
| AC-86 | **离线降级**：断开网络，打开已有题库的练习 → 判题、正确答案、原文、已沉淀的讲解可用；未生成的讲解显示「暂不可用」，「再讲讲」禁用；全场无非预期外发 |
| AC-87 | **书档往返**：导出含 `practice/` 的书档 → 空数据根导入 → 题库 `qid` 集合、已生成的 `explanation` 与 `mastery.box/due_at` 一致；再练不出近似重复题 |
| AC-88 | **讲解按需与沉淀**：生成题库阶段讲解调用 0 次；首次答错 1 题 → 1 次调用、≤8s 出文并写回 `questions.json`；同题再错 0 次调用且秒出；「再讲讲」只多 1 次并按 `qid + 选择` 命中缓存 |
| AC-89 | **回归**：`slides.json` / `module.json` 零改动；`npm test` 既有 228 项通过数不下降 |

## 9. 非目标

| 不做 | 理由 |
|---|---|
| 简答 / 论述 / 作文的 AI 评分 | 与「实时、离线、可复现」直接冲突；v1 之外的另一个产品 |
| 填空题 | 同义、语序、单位、单复数都会产生误判，需要人工兜底 |
| 整卷交卷后统一判分（考试模式） | 与「实时判题」互斥 |
| 跨书复习 / 全局错题本 | v1 按书；跨书要处理不同书的考点口径，收益小于复杂度 |
| 自适应难度（IRT / BKT） | 需要足够作答量才收敛，单机单用户几乎跑不起来 |
| 排行榜 / 打卡 / 证书 / 分享 | 本地单机，无社交面 |
| 导出错题 PDF / Anki / Quizlet | 书档已经解决迁移；导出是另一条产品线 |
| 语音读题、口述答题、拍照搜题 | 与阅读场景无关，且都要新能力 |
| 题库手工编辑（改题干/改答案） | 只提供「标记」，避免把题库变成需要版本管理的编辑器 |
| 公式 / 代码题自动判等 | 判等器是另一个工程 |
| 跨章综合题 | v1 按章出题，去重与复用才简单；跨章题要另立身份与去重口径 |
| 全量预生成讲解 | 要为每道题付一次讲解费，而多数题不会错（D54） |
| 多轮对话式讲题 | 追问只做一次「再讲讲」，不做自由对话；否则变成聊天窗口，成本与范围都失控 |

## 13. v0.1 → v0.2 变更记录

> 触发：2026-11-04 评审意见——「同一道题答错时再调用 AI 模型讲解并记录，保留『半实时』即可，还能节约 AI 成本」。

| 改动 | 原因 |
|---|---|
| 讲解从「生成题目时预生成、随题存储」改为「首次答错时按需生成，并写回题库沉淀」 | 预生成要为每道题付一次讲解费，而多数题不会错；按需只为错题付费，还能把每个错误选项都讲清楚。首次答错等 ≤8s（半实时），之后秒出 |
| 新增 `POST /practice/explain`、`explanation_status / explanation_at / explanation_model`、`explain-cache/`、「再讲讲」 | 承接按需生成、失败重试与用户主动追问 |
| AC-88 改为「讲解按需与沉淀」，原回归顺延为 AC-89；AC-72/73/74/80/86/87 随之改写 | 验收要能证明「只有错题付费」「重复不付费」「离线降级」 |
| 隐私从「不新增外发」改为「新增一类外发：答错时题干、选择、正确项与原文片段 → 模型」 | 按需生成必然外发；不写清楚等于偷偷发 |
| 非目标新增「全量预生成讲解」「多轮对话式讲题」；待确认新增 Q7 | 把成本边界与追问边界写死 |
| 估算从 3 人日调整为 3.5 人日（P2 +0.5d） | 新增按需讲解与「再讲讲」的接口、缓存与反馈态 |
