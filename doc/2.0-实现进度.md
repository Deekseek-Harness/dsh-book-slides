### 3.3 FR-14 复验手册：AC-99 / AC-100

口径以 **SRS v1.13 · FR-14 ~ FR-20**（AC-99 ~ AC-121、AC-113 的“构造 → 断言 → 判定 → 机检入口 → 人工边界”）为准，§3.3 ~ §3.9 是可执行步骤。这些 AC 是**可机检的不变量**，不需要人眼比对原文。每条都给出“命令 → 预期 → 失败判定”；人工只负责跑命令、看退出码/警告，以及最后抽查语义质量。

**前置**：数据根 `~/.dsh/book-slides/`（或 `DSH_BOOK_SLIDES_ROOT`）；`<bookId>` 换成书架里的书；命令都在 `dsh-book-slides/` 下执行。数据文件改动即时生效；改动 `v2/` 代码后需重载插件再走 UI 路径。

#### AC-99：`sections` 必须逐字取自该章原文

**不变量**：每条 `brief.sections[i]` 都是该章正文（`chapters.json` 的 `from..to` 页文本按 `\n` 拼接）的子串；不满足则该章整条 brief 回退“标题 + 首尾段”。模型回复与落盘 `briefs.json` 走同一处校验（读取侧不信任缓存）。

**验法 A（机检，推荐）**

```powershell
npm run verify:briefs -- --book <bookId>
```

- 预期：每条打印 `ok 第 n 章 @<字符偏移> "<section>"`，末行 `结论：PASS（k/k 可检索）`，退出码 `0`。
- 失败：任一行 `MISS`、`结论：FAIL`、退出码 `1`；脚本会区分“原文中没有”与“仅空白差异”。
- 另会提示 `briefs.json` 的 hash 是否与当前 Part 章纲一致（过期时讲纲会重新生成 briefs）。

**验法 B（篡改回退，产品内观察）**

1. 编辑 `~/.dsh/book-slides/books/<bookId>/briefs.json`，把某条 section 改成原文没有的字符串（保持合法 JSON，**不要动 `hash`**）。
2. 选该 Part →「预览讲纲」（数据文件每次请求重读，无需重载；只有改过 `v2/` 代码才需重载插件）。
3. 预期：预览页警告条出现 `第 n 章 brief 的 sections 未逐字出现在原文，已回退标题 + 首尾段。`；`/plan/preview` 响应 `briefsSource: "mixed"`；该章 brief 使用“标题 + 首尾段”，其余章不受影响。
4. 判定：警告未出现、或篡改值仍进入讲纲 → 不通过。UI 的预览/保存计划不传 `force`，不会覆盖人工修改；只有章纲变化（hash 不符）或显式 `POST /series/plan {force:true}` 才会让模型重建 briefs——这是“可复用”语义，不是回退。
5. 调试：`GET /dsh-book-slides/briefs?bookId=<bookId>` 返回 `warnings` 与 `rejected`（回退的章号）。

**验法 C（模型返回坏 section，自动化）**：`test/v2-briefs.test.mjs` 用脚本化假模型注入“含一条原文没有的 section”，断言只回退该章、好章保留——不依赖真模型偶发出错。同一文件还有一条 route 级用例：`POST /plan/preview` 对改坏的 `briefs.json` 返回 `briefsSource: "mixed"` 与含章号的 warning，保证“UI 能看到回退”不是靠人工口头保证。

**仍需人工**：`gist` / `role` 的语义质量（是否说清本章讲什么、与前后章什么关系）。机器只保证“不编造原文没有的 section”。

#### AC-100：坏 JSON → 重试 1 次；仍失败整份回退，系列仍可规划

**不变量**：解析/校验失败重试 1 次（共 2 次调用）；仍失败则整份 briefs 回退“标题 + 首尾段”，讲纲降级为规则 planning（`unstitched`），不阻断规划。

**验法（自动化，故障注入）**

```powershell
node test/v2-briefs.test.mjs
```

- 用例 1（两次坏 JSON）：假模型连续返回散文/截断 JSON → 断言模型调用 **4 次**（briefs 2 + 讲纲 2，各重试 1 次）、`briefs.fallback=true`、warning 含“解析失败”、规则讲纲覆盖 Part 全部章、`plan.source="rule"`、`stitched=false`。
- 用例 2（坏一次、好一次）：断言只重试 1 次（共 2 次调用）即恢复，`fallback=false`、不降级。
- 判定：调用次数不符、`fallback` 非 `true`、讲纲未覆盖全部章、测试红 → 不通过。

**为什么不用真模型复现**：偶发的是“触发”，不是“行为”。坏 JSON 后的降级是确定性的，用故障注入固定；“真模型坏 JSON 的发生率”属于运行时观测（可在 `errors.js` 的最近错误环上加计数），不作为验收用例。

#### 断言强度自检（防止“恒真断言”回归）

历史坑：旧测试用 `sections: []`，`validateBrief` 对空数组恒真，删掉校验也不会红。现在要求：

- `test/v2-briefs.test.mjs` 必须使用**非空** sections；
- 改完 briefs 逻辑后重做变异自检：删掉 `checkBriefs` 里的 `validateBrief` 调用 → 应红 2 条；把重试上限 `2` 改成 `1` → 应红 2 条；跑完还原。

### 3.4 FR-15 复验手册：AC-101 / AC-102

口径与 AC-99/100 相同：失败分支用脚本化假模型注入，人只看调用次数、`source`/`stitched`、覆盖率与退出码。

#### AC-101：`seams` 数 ≠ N−1 → 重试 1 次；两次失败降级规则 plan

- **不变量**：讲纲校验失败（`seams.length !== N−1`、讲次不连续、章覆盖不符、每讲超 8 万等）只重试 1 次（讲纲 2 次调用，加 briefs 共 3 次）；仍失败 → 规则 plan（`source='rule'`、`stitched=false`），覆盖 Part 全部章，且满足生成门（`plan_version≥1`、`lectures` 非空）。
- **验法（自动化，故障注入）**：`node test/v2-plan-ac.test.mjs`
  - 用例 1（0 条 seam，第二次合法）：调用 3 次、`source='model'`、`seams.length=1`、`stitched=true`；
  - 用例 2（两次分别为 2 条 / 0 条）：调用 3 次、规则 plan、`stitched=false`、覆盖 `[1,2]`，`createSeries` 到 `planned` 且 `plan_version=1`。
- **判定**：调用次数 ≠ 3、重试后仍采用坏讲纲、降级 plan 少章或过不了生成门 → 不通过。
- **人工边界**：主线与每讲 `goal`/`in`/`out` 是否切题。

#### AC-102：术语凭空发明 → 重试 1 次；合法术语不得误杀

- **不变量**：`terms[].name` 必须在原文或 briefs 中出现；否则重试 1 次；仍失败整份降级规则 plan，warning 含“术语”。
- **验法（自动化，故障注入）**：`node test/v2-plan-ac.test.mjs`
  - 用例 3（第一次“不存在的术语”、第二次 `接口对比`，只出现在 `brief.gist`）：调用 3 次、`source='model'`，术语被保留 → 证明 briefs 词放行；
  - 用例 4（两次都是假词）：规则 plan，warning 含“术语”，覆盖全部章。
- **判定**：坏词被采用、合法词被拒、或未降级 → 不通过。
- **人工边界**：术语该不该收、`forbid` 是否合理。

#### 断言强度自检

- 禁用 `validateModelPlan` 的 seams 数校验 → AC-101 两条应红；
- 禁用术语校验 → AC-102 两条应红；
- 讲纲重试上限 `2 → 1` → 四条应红。

## 4. 已知缺口与边界

- **`POST /series/replan` 未实现**：`replanFrom(k)` 在附录 B 标注“规范已定，本期未实现”，手动改切点仍会走重建系列。
- **FR-13 的两条规范意图未实现**：`cut_warn`（不拆同主题相邻章）、`cut_line`（无节标题时退到行/字切）与 `density_warn` 在 `rulePlan` 中都不产生；v1.5 起 AC-96 ~ AC-98 不再假装覆盖它们，M6 真书走查时单列。
- **`rulePlan` 硬上限已修（v1.5）**：原贪心在“当前讲 <4.2 万字”时会继续装章，`41999 + 59999` 可拼出 10.2 万字一讲，违反 I4；现改为“再加一章超 8 万必须换讲”，FR-13.1 的 F6/F7 为回归夹具。
- **单章拆分阈值回到 6 万（v1.5）**：原实现按 8 万才拆，6–8 万单章会被压成 1 讲 30 页（页预算被 `clamp` 吃掉）；现 >6 万即拆上/下、每段 ≤6 万。`sliceChapter` 同时修掉“极长章只递归前半段、后半段被丢”的缺陷（F12）。
- **真书验收未做**：三模式真 PDF、文科 + 技术两本真书的“Part → 讲纲 → 生成 → 接缝”端到端在 M6。
- **ComfyUI TTS 真机部分验证**：设置页音色表/工作流导入、连接与试听、`Uncle Fu`/`Ono Anna` 切换已手工验证；完整逐页配音、缓存/串行队列真机表现、flac 输出与 PPT 不嵌 flac 的 warning 仍待 M6 复核。
- **AC-136 全量走查未做**：M5 只覆盖练习/配图/导出/书档的入口与静态反馈；C1–C14 逐项证据在 M6。
- **1.x 套件冻结**：`npm test` 是 1.4.0 的测试；2.0 替换同名路由与数据模型后不再作为门禁，2.0 以 `npm run test:v2` 为准。
