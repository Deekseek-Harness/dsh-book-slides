### 3.3 FR-14 复验手册：AC-99 / AC-100

口径以 **SRS v1.15 · FR-14 ~ FR-20**（AC-99 ~ AC-121、AC-113 的“构造 → 断言 → 判定 → 机检入口 → 人工边界”）为准，§3.3 ~ §3.9 是可执行步骤。这些 AC 是**可机检的不变量**，不需要人眼比对原文。每条都给出“命令 → 预期 → 失败判定”；人工只负责跑命令、看退出码/警告，以及最后抽查语义质量。

**前置**：数据根 `~/.dsh/book-slides/`（或 `DSH_BOOK_SLIDES_ROOT`）；`<bookId>` 换成书架里的书；命令都在 `dsh-book-slides/` 下执行。数据文件改动即时生效；改动 `host/` 代码后需重载插件再走 UI 路径。

#### AC-99：`sections` 必须逐字取自该章原文

**不变量**：每条 `brief.sections[i]` 都是该章正文（`chapters.json` 的 `from..to` 页文本按 `\n` 拼接）的子串；不满足则该章整条 brief 回退“标题 + 首尾段”。模型回复与落盘 `briefs.json` 走同一处校验（读取侧不信任缓存）。

**验法 A（机检，推荐）**

```powershell
npm run verify:briefs -- --book <bookId>
```

- 预期：每条打印 `ok 第 n 章 @<字符偏移> "<section>"`，末行 `结论：PASS（k/k 可检索）`，退出码 `0`。
- 失败：任一行 `MISS`、`结论：FAIL`、退出码 `1`；脚本会区分“原文中没有”与“仅空白差异”。
- 另会提示 `briefs.json` 的 hash 是否与当前 Part 章纲一致（过期时讲纲会重新生成 briefs）。

**验法 B（篡改回退，产品内观察）**

1. 编辑 `~/.dsh/book-slides/books/<bookId>/briefs.json`，把某条 section 改成原文没有的字符串（保持合法 JSON，**不要动 `hash`**）。
2. 选该 Part →「预览讲纲」（数据文件每次请求重读，无需重载；只有改过 `host/` 代码才需重载插件）。
3. 预期：预览页警告条出现 `第 n 章 brief 的 sections 未逐字出现在原文，已回退标题 + 首尾段。`；`/plan/preview` 响应 `briefsSource: "mixed"`；该章 brief 使用“标题 + 首尾段”，其余章不受影响。
4. 判定：警告未出现、或篡改值仍进入讲纲 → 不通过。UI 的预览/保存计划不传 `force`，不会覆盖人工修改；只有章纲变化（hash 不符）或显式 `POST /series/plan {force:true}` 才会让模型重建 briefs——这是“可复用”语义，不是回退。
5. 调试：`GET /dsh-book-slides/briefs?bookId=<bookId>` 返回 `warnings` 与 `rejected`（回退的章号）。

**验法 C（模型返回坏 section，自动化）**：`test/v2-briefs.test.mjs` 用脚本化假模型注入“含一条原文没有的 section”，断言只回退该章、好章保留——不依赖真模型偶发出错。同一文件还有一条 route 级用例：`POST /plan/preview` 对改坏的 `briefs.json` 返回 `briefsSource: "mixed"` 与含章号的 warning，保证“UI 能看到回退”不是靠人工口头保证。

**仍需人工**：`gist` / `role` 的语义质量（是否说清本章讲什么、与前后章什么关系）。机器只保证“不编造原文没有的 section”。

#### AC-100：坏 JSON → 重试 1 次；仍失败整份回退，系列仍可规划

**不变量**：解析/校验失败重试 1 次（共 2 次调用）；仍失败则整份 briefs 回退“标题 + 首尾段”，讲纲降级为规则 planning（`unstitched`），不阻断规划。

**验法（自动化，故障注入）**

```powershell
node test/v2-briefs.test.mjs
```

- 用例 1（两次坏 JSON）：假模型连续返回散文/截断 JSON → 断言模型调用 **4 次**（briefs 2 + 讲纲 2，各重试 1 次）、`briefs.fallback=true`、warning 含“解析失败”、规则讲纲覆盖 Part 全部章、`plan.source="rule"`、`stitched=false`。
- 用例 2（坏一次、好一次）：断言只重试 1 次（共 2 次调用）即恢复，`fallback=false`、不降级。
- 判定：调用次数不符、`fallback` 非 `true`、讲纲未覆盖全部章、测试红 → 不通过。

**为什么不用真模型复现**：偶发的是“触发”，不是“行为”。坏 JSON 后的降级是确定性的，用故障注入固定；“真模型坏 JSON 的发生率”属于运行时观测（可在 `errors.js` 的最近错误环上加计数），不作为验收用例。

#### 断言强度自检（防止“恒真断言”回归）

历史坑：旧测试用 `sections: []`，`validateBrief` 对空数组恒真，删掉校验也不会红。现在要求：

- `test/v2-briefs.test.mjs` 必须使用**非空** sections；
- 改完 briefs 逻辑后重做变异自检：删掉 `checkBriefs` 里的 `validateBrief` 调用 → 应红 2 条；把重试上限 `2` 改成 `1` → 应红 2 条；跑完还原。
