# 真值 · 人工切章标注

这里放 5 本真书的人工切章真值，PDF 本身不进仓库（体积 + 版权）。核对脚本按 `books.json`
点名配对，PDF 目录可以放在任何地方。

## 文件怎么来的

| 文件 | 内容 | 来源 |
|---|---|---|
| `【书签】*.txt` | 每行「标题<TAB>物理页码」，缩进用前导 tab，不影响解析 | 从 PDF 阅读器的书签面板导出 |
| `【目录页码】*.txt` | 目录页范围，如 `16-22` | 人工翻到目录页记下 |

`check.js` 只把「章 / 前言 / 附录」算进对照：分卷（第一部、Part Ⅰ）、小节（1.3、3.1.1）、
封面目录索引之类一律跳过，见 `isChapterEntry`。

## books.json 是什么

| 字段 | 用途 |
|---|---|
| `pdf` | 数据目录里的 PDF 文件名，必须完全一致（含空格） |
| `bookmark` / `toc` | 真值文件名；`toc` 可以没有 |
| `pages` / `sha256` | 锁住「用的是哪一版 PDF」；换版先核对这两个 |
| `modes` | 这本书能用哪条路径：`toc`（目录驱动）、`mech`（纯页眉机械切分） |
| `expect` | 当前基线快照，`--baseline` 用它判回归 |
| `ignored` | 明确不参与对照的 PDF（扫描重本、没真值的书），避免前缀配对串台 |

## 怎么跑

```powershell
npm run test:truth        # 目录驱动，与基线比
npm run test:truth:mech   # 机械切分，与基线比
```

默认 PDF 目录是仓库旁边的 `../测试书籍/`。PDF 在别处时：

```powershell
$env:BOOK_SLIDES_PDF_DIR = 'D:\books'
node test/books.toc.e2e.mjs --truth test/truth --baseline
```

不加 `--baseline` 时，退出码按「严重 > 0」算（当前会红）；加了 `--baseline` 只看是否比基线差。

在 DSH 里跑同一套逻辑：

```
/chapter-check @D:\books mech
```

配 `BOOK_SLIDES_TRUTH_DIR=...\dsh-book-slides\test\truth` 后，命令会自动去这份清单里找真值。

## 加一本新书

1. 从 PDF 书签导出，存成 `【书签】<pdf 同名>.txt`；
2. 翻目录页，记下范围存成 `【目录页码】<pdf 同名>.txt`（目录没有页码就不存，`modes` 只写 `mech`）；
3. 在 `books.json` 的 `books` 里加一条，先不写 `expect`；
4. 跑 `node test/books.toc.e2e.mjs --truth test/truth`（机械路径同理），把实测的
   `truth / parsed / matched / serious / warn` 抄进 `expect`；
5. 再跑一次带 `--baseline`，确认退出码 0。

## 算法改好了想更新基线

跑一遍，确认每一本的数字都**变好或不变**，再改 `expect`，并在 `CHANGELOG.md` 记一笔。
如果某一本变差，别改基线——那是回归。
